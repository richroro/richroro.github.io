한 줄 정의 LLM과 차이 프리미티브 비용 계산기 끼우는 자리 한계 팩트·출처

01 · What

글을 쓰지 않는 모델

Jev는 TypeSafe AI가 2026년 9월 15일 얼리 액세스로 공개한 모델입니다. 트랜스포머 기반이지만 LLM이 아닙니다 — 문장을 만들지 않고, 미리 정해 둔 스키마에 맞는 결정 하나와 그 확률만 돌려줍니다. 토큰을 하나씩 뽑지 않고 한 번의 병렬 계산으로 끝내기 때문에 빠르고, 출력 형식이 구조적으로 어긋날 수 없습니다. 회사는 이런 모델을 System One(빠르게 판단하는 쪽)이라고 부르고, 글을 쓰는 LLM을 그 반대편에 둡니다.

02 · Difference

LLM과 무엇이 다른가

같은 "AI 모델"이라 부르지만 쓰는 자리가 다릅니다. Jev는 LLM을 대체하는 게 아니라, LLM에게 굳이 글로 물어볼 필요가 없던 일을 떼어 가는 쪽입니다.

항목일반 LLMJev (System One)
출력자유 문장. 원하는 형식은 프롬프트·스키마로 유도타입이 고정된 값 + 확률. 스키마 밖은 불가능
생성 방식토큰을 하나씩 순차 생성(자기회귀)한 번의 병렬 계산(비자기회귀)
지연출력 길이에 비례해 늘어남70~500ms, 출력 길이 개념이 없음
과금입력 + 출력 토큰입력 토큰만 ($0.042/100만), 출력 무료
실패 모드형식 깨짐, 없는 값 생성, 장황함형식은 안 깨짐. 대신 틀린 선택을 함
잘하는 일작성·설명·계획·대화·코드분류·라우팅·점수·게이트 판정
못 하는 일—글쓰기 전부. 이미지·음성·영상 입력도 미지원

03 · Primitives

물어볼 수 있는 세 가지 모양

프롬프트를 자유롭게 쓰는 대신, 질문을 세 가지 틀 중 하나로 만들어 보냅니다. 코드가 받을 답의 모양을 미리 고정해 두는 방식입니다.

Choice

여러 개 중 하나

분류·라우팅·게이트 판정. 스팸인가, 어느 팀으로 보낼까, 이 요청을 LLM에 넘길까 — 답이 목록 안에 있는 질문.

옵션 최대 255개
Score

등급 매기기

심각도·우선순위·품질 같은 단계 평가. 숫자를 계산하는 게 아니라 말로 정의한 단계 중 하나를 고르는 것입니다.

확인 필요

Score를 계산기로 쓰지 말 것. 회사가 직접 적어 둔 주의사항입니다. Score는 "얼마인지"를 재는 자가 아니라 단계 사이를 의미로 가르는 루브릭이라, 등급에서 정확한 금액이나 수치를 되돌릴 수 없습니다.

04 · Cost

내 호출량에서는 실제로 얼마나 싼가

"최대 200배 빠르고 400배 싸다"는 회사 발표입니다. 배수는 무엇과 비교하느냐에 따라 크게 달라지니, 본인 숫자를 넣어 보는 편이 빠릅니다. 분류 한 건의 입력 토큰과 월 호출 수, 비교할 모델만 고르면 됩니다.

05 · Where

파이프라인의 어디에 끼우나

Jev를 쓰는 방식은 대체가 아니라 앞단 게이트입니다. 들어온 것을 먼저 싸게 판정해서, 정말 글이 필요한 건만 LLM으로 넘깁니다. 절감의 실체는 단가가 아니라 LLM 호출 건수가 줄어드는 것입니다.

자주 나오는 자리

  • 01
    모델 라우팅 — 쉬운 질문은 값싼 모델, 어려운 질문만 큰 모델로. 라우터 자체를 LLM으로 돌리던 비용이 사라집니다.
  • 02
    가드레일 — 프롬프트 인젝션·금칙어·민감정보 판정. 판정이 길 필요가 없고 빨라야 하는 일.
  • 03
    티켓 트리아지 — 문의를 팀·심각도로 나눠 큐에 넣기. Choice + Score 조합.
  • 04
    전처리 필터 — 수집한 문서 중 요약할 값이 있는 것만 골라 LLM에 넘기기.
🔌

06 · Limits

쓸 자리와 안 쓸 자리

이 구분을 먼저 하지 않으면 "LLM보다 싼 모델"로 오해해서 엉뚱한 자리에 넣게 됩니다. Jev는 더 싼 LLM이 아니라, 결정만 하는 다른 종류의 부품입니다.

이럴 때 쓴다

  • ✓
    답이 미리 아는 목록 안에 있다 (분류·라우팅·게이트)
  • ✓
    사람이 읽지 않고 코드가 바로 받아서 분기한다
  • ✓
    같은 판정을 대량으로 반복한다
  • ✓
    응답이 수백 ms 안에 와야 한다
  • ✓
    확률값을 받아 애매한 건만 사람에게 넘기고 싶다

이럴 때는 안 된다

  • ✕
    답장·요약·설명·코드처럼 글이 결과물인 일 — 생성 자체를 못 합니다
  • ✕
    이유를 붙여 설명해야 하는 일 — 판정만 나오고 근거 문장은 없습니다
  • ✕
    정해진 선택지로 좁힐 수 없는 열린 계획·탐색
  • ✕
    이미지·음성·영상 입력 — 현재 텍스트만 읽습니다
  • ✕
    정확한 수치 산출 — Score는 루브릭이지 계산기가 아닙니다

이 페이지에 대해

"Jev가 뭐냐"는 질문 하나에서 시작한 정리 노트입니다. 새 모델 소개를 그대로 옮기는 대신, 내 호출량을 넣어 실제 배수를 보고 어디에 쓸 수 있고 어디엔 못 쓰는지까지 적었습니다. 외부 스크립트 없이 HTML 한 파일로 돌아갑니다.

이 페이지의 수치 대부분은 제조사 발표와 언론 보도를 옮긴 것이고, 독립적으로 재현한 값이 아닙니다. 계산기는 입력 단가와 토큰 수만으로 단순 곱셈을 하며, 캐싱·배치 할인·최소 과금·무료 한도는 반영하지 않습니다. 도입 판단 전에 공식 가격표와 약관을 직접 확인하세요.
