# 한 손 농구

공을 스와이프해서 던지고, 움직이는 골대에 넣는 45초 세로형 농구 게임.

- 배포: https://richroro.github.io/games/basketball/
- 소스: `index.html` 한 파일 (외부 스크립트·에셋·빌드 없음)

## 게임 규칙

화면을 누른 채 던질 방향으로 끌면 예상 궤적이 점으로 보이고, 손을 떼면 그대로 날아간다.
길게 끌수록 세게 나간다. 18단위보다 짧게 끌면 던지지 않는다(주머니 속 오터치 방지).

| 상황 | 점수 | 시간 |
| --- | --- | --- |
| 림이나 백보드를 맞고 들어감 | 2점 | +2초 |
| 아무것도 안 닿고 들어감(스윔) | 3점 | +3초 |
| 2~3연속 | +1점 | |
| 4~5연속 | +2점 | |
| 6연속 이상 | +3점 | |

시작 45초. 넣으면 시간이 늘지만 **45초를 넘지는 않는다.** 시간 보너스를 무제한으로 두면
잘 넣는 사람의 판이 끝나지 않아서, 상한을 두고 "잘 넣는 동안만 45초가 유지되는" 구조로 했다.
빗나가면 연속이 끊긴다.

## 난이도

넣은 골 수에 따라 골대가 움직인다. 처음 세 골까지 멈춰 있는 건 던지는 감을 먼저 잡게 하려는 것이다.

| 넣은 골 | 골대 |
| --- | --- |
| 0~2골 | 멈춰 있음 |
| 3골부터 | 좌우 이동 시작 (코트를 한 번 가로지르는 데 약 7초) |
| 8골부터 | 위아래 흔들림 추가 |
| 16골부터 | 좌우 최대 속도 (한 번 가로지르는 데 약 2.3초) |
| 19골부터 | 흔들림 최대 (위아래 ±26) |

조준 점선은 **14개까지만** 보여 준다. 궤적을 골대까지 전부 그려 주면 멈춰 있는 골대는
눈감고도 넣게 된다. 앞부분만 보여 주고 마지막 한 뼘은 눈으로 재게 남겼다.

## 측정

궤적을 직접 예측해서 조준하는 봇으로 화면 크기별 6판씩 돌렸다. 봇은 골대의 좌우 이동까지는
예측하지만 위아래 흔들림은 예측하지 않는다(사람도 그만큼은 감으로 친다).

| 화면 | 점수 중앙값 | 범위 | 성공률 | 판당 골 |
| --- | --- | --- | --- | --- |
| iPhone 14 (390×844) | 116 | 103~150 | 66% | 31 |
| Galaxy (412×915) | 98 | 76~132 | 62% | 28 |
| iPhone SE (375×667) | 98 | 43~110 | 60% | 25 |
| 작은 안드로이드 (360×640) | 93 | 74~114 | 58% | 26 |
| 데스크톱 창 (900×760) | 70 | 42~81 | 50% | 19 |

거의 완벽하게 조준하는 봇이 50~66%에서 멈추는 게 이 게임의 상한선이다. 남는 오차는
골대의 위아래 흔들림과, 던지는 자리가 매번 바뀌는 데서 온다.

화면이 짧을수록(코트 세로가 짧을수록) 점수가 낮은 건 골대까지 거리가 짧아 각도 여유가
줄기 때문이다. 어느 화면에서도 못 넣는 구간은 없다 — 아래 검증 참고.

## 구현 메모

물리는 고정 스텝(1/60초) 적분으로 직접 구현했다. 만들면서 실제로 걸렸던 것들:

| 증상 | 원인 | 대응 |
| --- | --- | --- |
| 남은 시간이 `45초`에서 한참 안 바뀜 | 1/60씩 빼다 보면 44가 `44.0000000001`로 남아 `Math.ceil`이 45를 돌려줌 | `Math.ceil(t - 1e-6)` |
| 득점 문구가 그물과 겹쳐 안 읽힘 | 문구를 림 바로 아래(+54)에 띄웠는데 거기가 그물 자리 | 그물 아래(+84)로 내리고 흰 테두리를 깔았다 |
| 코트 바닥 선이 골대를 따라 미끄러짐 | 장식용 호를 골대 x에 붙여서 그림 | 코트 가운데에 고정 |
| 백보드가 판이 아니라 흰 막대로 보임 | 흰 배경에 흰 판 + 얇은 회색 테두리 | 판에 색(`#EDF1F6`)을 주고 비율을 9×78로 줄였다 |

득점 판정은 공의 **직전 위치와 현재 위치**로 림 평면을 위에서 아래로 가로질렀는지 본다.
한 프레임에 최대 40단위까지 움직이므로 위치만 보면 빠른 공이 림을 지나쳐 버린다.

림 양 끝은 반지름 5짜리 원 두 개로, 백보드는 사각형으로 두고 가장 가까운 점을 찾아
밀어내는 방식으로 충돌을 푼다. 림 안쪽 틈(52)이 공 지름(34)보다 넓어서, 물리적으로
들어갈 수 있는 공만 득점 판정에 도달한다.

## 검증

브라우저(헤드리스 크로미움)에서 실제로 돌려서 확인했다.

**물리·규칙** — 무작위 400샷에서 코트 이탈 0, NaN 0. 림 한가운데 통과는 3점(스윔),
2연속이면 +1, 한 슛에 두 번 득점되지 않음, 림 끝에 맞으면 노골, 밑에서 위로 통과도 노골,
시간이 끝나면 결과 화면. 골대 위치 8곳 × 던지는 자리 3곳 = 24조합 전부 도달 가능하고,
가장 먼 조합도 필요한 힘이 21로 상한(26)에 여유가 있다.

**실제 조작** — 시작 버튼, 스와이프 슛, 살짝 터치는 슛으로 치지 않음, 종료 확인 모달,
소리 토글, 탭 전환 시 일시정지와 이어하기까지 실제 이벤트로 눌러서 확인했다.

여기서 한 번 막혔다. `--virtual-time-budget` 으로 돌리면 `requestAnimationFrame` 이
**1500ms 동안 한 프레임밖에 안 돈다.** 게임 루프가 통째로 안 도니 "시계가 줄어든다",
"공이 날아가 떨어진다" 같은 건 검증이 안 됐다. 그래서 이 부분은 CDP 로 진짜 브라우저를
붙여 실시간으로 확인했다(`node` 22의 내장 WebSocket 사용, 외부 패키지 없음).

**확인 안 된 것** — 실기기 터치, 실제 사람의 플레이 감각. 점수 균형은 봇 기준이라
사람이 하면 다를 수 있다.

## 앱인토스

이 게임에는 앱인토스 SDK 브릿지가 없다. 형제 게임(`games/tikkeul-moa/`)에는 붙어 있고,
필요해지면 같은 어댑터를 그대로 가져오면 된다(리더보드 점수 제출은 **문자열**, 종료는
`Screen.close()`, 식별키는 `User.getAnonymousKey()`).

다만 정적 웹에서 만족시킬 수 있는 가이드 항목은 그대로 지켰다. 외부 요청 0건, 사운드·햅틱
On/Off 유지, 백그라운드 전환 시 소리 즉시 종료(`AudioContext.suspend`)와 일시정지,
Safe Area 미침범, 모든 화면에서 종료 가능 + 종료 확인 모달, 세로 고정, 브라우저 히스토리
미조작, `eval`/외부 스크립트 없음, 기록은 재접속해도 유지.
