# 불티나 버거

밀려드는 주문을 보고 재료를 순서대로 탭해 버거를 쌓고, 윗빵을 덮어 내보내는
한 손 세로형 주문 처리 게임. 앱인토스(App in Toss) 미니앱 게임 출시 가이드에
맞춰 만든 정적 웹 게임이다.

- 배포: https://richroro.github.io/games/bulti-burger/
- 소스: `index.html` 한 파일 (외부 스크립트·에셋·빌드 없음)

## 게임 규칙

아래빵은 자동으로 깔린다. 주문 카드에 그려진 **아래에서 위 순서**대로 재료
버튼을 누르고, 맨 아래 윗빵 버튼으로 내보낸다. 스택과 똑같은 주문을 한 손님
중 **가장 급한 쪽에게 자동으로** 나가므로 손님을 미리 고를 필요가 없다.

- 파란 테두리는 "지금 쌓는 게 아직 맞다"는 확인이지 선택지가 아니다.
- 어느 주문의 접두사도 아닌 재료를 누르면 저절로 치워지고 0.4초 멈춘다.
  되돌리기가 없는 대신 **막다른 스택에 갇히는 상태가 존재하지 않는다.**
- 손님 인내심이 0이 되면 하트가 깨지고, 셋을 다 잃으면 끝난다.

재료 8종은 시간에 따라 풀린다 — 패티·치즈·양상추·토마토(0초) → 양파(40초)
→ 베이컨(80초) → 계란(120초) → 피클(160초).

### 급하게 내보내기

손님 인내심이 35% 밑으로 떨어지고 현재 스택이 그 주문의 **절반 이상**을
채웠으면 윗빵 버튼이 주황색으로 바뀐다. 덜 쌓았어도 내보내 하트를 지킬 수
있다. 대신 인내심·무실수 보너스와 콤보 배수가 전부 빠지고 0.35초 멈춘다.

## 점수

```
정상  = round((80×재료수 + 120×남은인내심비율 + 50×무실수) × 콤보배수) × VIP배수
급송  = 80 × 쌓은재료수 × VIP배수
콤보배수 = 1 + min(콤보,10) × 0.1     (최대 ×2.0)
```

손님 5명마다 오는 VIP(👑)는 재료가 한 장 더 붙고 점수가 2배다.
무실수로 인내심 60% 이상 남기고 서빙하면 **가장 급한 다른 손님의 인내심이
5% 회복된다** — 잘 만든 값이 그 자리에서 시간으로 환전된다.

가벼운 실수에 점수를 깎지 않는 건 의도적이다. 잘못 누른 진짜 비용은 0.4초와
콤보 배수이고, 그 0.4초 동안 모든 손님의 인내심이 계속 줄어든다.

## 난이도와 측정값

난이도는 전부 **경과 시간**에 연동한다. 서빙 수에 연동하면 잘하는 사람이
난이도를 더 빨리 끌어올려 초보보다 먼저 죽는 역전이 생긴다.

| 항목 | 값 |
| --- | --- |
| 손님 도착 간격 | `max(1.25, 4.2 − 0.030·t)` 초 |
| 인내심 | `max(2.8, (13 + 2.6×재료수) × max(0, 1 − 0.0045·t) × 지터)` 초 |
| 대기줄 | 최대 3명 |
| 레시피 길이 | 0~18초 2장 → 125초 이후 4~6장 |

브라우저에서 **실제 게임 코드를 봇으로 돌려** 측정했다(각 80판, 총 320판).
봇은 프레임을 직접 돌리며 "현재 스택을 받아 줄 손님 중 가장 급한 쪽"을
목표로 삼고, 설정한 간격마다 한 번씩 탭한다.

| 플레이어 | 판 길이 10%/중앙/90% | 2~4분 | 점수 중앙 | 서빙 |
| --- | --- | --- | --- | --- |
| 완벽봇 (0.30초/탭, 오타 0%) | 3:08 / **3:13** / 3:16 | 100% | 90,092 | 88 |
| 숙련 (0.38초/탭, 오타 4%) | 2:55 / **3:02** / 3:08 | 100% | 48,496 | 69 |
| 보통 (0.50초/탭, 오타 8%) | 2:37 / **2:48** / 2:55 | 100% | 28,861 | 53 |
| 초보 (0.65초/탭, 오타 14%) | 2:14 / **2:29** / 2:40 | 100% | 18,081 | 39 |

320판 전부 정상 종료했고(무한 판 0건), 초보 대비 완벽봇 점수는 5.0배다.
실력은 판 길이(41초 차)보다 점수에 드러난다.

## 밸런스: 실제로 터졌던 것 세 가지

설계 단계의 수치를 그대로 구현했더니 **완벽봇이 12분 가드에 걸릴 때까지 죽지
않았다.** 원인은 셋이었고, 셋 다 "압박이 실제로는 걸리지 않는" 같은 병이었다.

| 증상 | 원인 | 대응 |
| --- | --- | --- |
| 대기줄이 3명에 절대 도달하지 않음(평균 2.1) | 줄이 꽉 찼을 때 도착 타이머를 고스트 예고 시간(0.6초)으로 되감았다. 자리가 날 때마다 그만큼 공짜 시간이 생겼다 | 꽉 차도 타이머는 계속 돌리고 0에서 멈춰 대기. 자리가 나는 즉시 입장 |
| 그래도 안 참 | 타이머를 아예 얼렸더니 이번엔 간격(1.25초) 전체를 자리가 난 **뒤에** 치렀다 | 0에서 멈추는 '문 앞 대기' 상태로 분리 |
| 후반에 아무도 안 죽음 | **급하게 내보내기가 처리량 이득이었다.** 2탭짜리 반쪽 버거를 던지면 하트를 지키면서 제대로 만드는 것보다 30% 빨랐다. 후반엔 전부 급송하는 게 최적 | 주문의 절반 이상을 쌓아야 발동 + 급송 뒤 0.35초 잠금. 지름길에 시간 값을 매겼다 |

세 번째가 핵심이다. 급하게 내보내기는 후반에 "제일 급한 놈부터"라는 기계적
규칙만 남는 걸 막으려고 넣은 장치인데, 값을 안 매기니 그 자체가 지배 전략이
되어 같은 문제를 반대편에서 다시 만들었다.

인내심 하한도 4.0초에서 **2.8초로 내렸다.** 하한이 가장 빠른 플레이어의
처리 시간(3×1.25초)보다 높으면 평형이 생겨 판이 영원히 끝나지 않는다.
대기줄이 3명에서 막혀 도착이 멈추는 구조와 맞물리는 문제라, 하한을 다시
올리면 같은 증상이 재현된다.

## 구현 메모

물리가 없다. 티끌모아 태산과 겹치는 건 "한 손 세로 2~4분 토스 스타일" 셸뿐이고,
압박의 원천이 공간이 아니라 시간이며 입력이 드래그가 아니라 단일 탭이다.

- **타이머는 전부 `remain -= dt` 감산이다.** `performance.now()` 절대 시각
  deadline 을 쓰면 백그라운드 복귀 때 타이머가 이미 다 지나 있어서 손님 셋이
  동시에 나간다. 감산 방식은 `state === "playing"` 일 때만 dt 를 먹으므로
  일시정지 하나로 전부 자동으로 멈춘다. 복귀 직후 1초는 인내심을 세우지 않는다.
- **`ctx.roundRect` 를 쓰지 않는다.** Safari 16 미만 웹뷰에 없어서 흰 화면이
  된다. `arcTo` 로 만든 `rr2()` 를 쓰고, `ctx.ellipse` 에도 폴백을 뒀다.
- 재료는 `drawIngredient()` 하나가 **조립대 큰 그림 / 주문 카드 미니 스택 /
  버튼 아이콘** 세 곳을 전부 그린다. 생김새가 갈라질 수 없다.
- 식별은 4중이다 — 색, 두께(11~26px 로 8종 전부 다름), 실루엣, 그리고 레이어
  오른쪽 끝의 **패턴 마커**(점 1~4개 / 세로선 1~2개 / 가로선). 미니 스택
  8~16px 에서는 실루엣이 뭉개져 색+두께만 남는데 마커가 그 구멍을 메운다.
  저dpr 기기에서는 마커 알파를 0.42 → 0.55 로 올린다.
- 재료 올리는 소리는 **재료별이 아니라 층 높이별**로 펜타토닉 음정이 올라간다.
  5단을 쌓으면 상승 아르페지오가 연주된다.
- 조립대 카운터는 흔한 4단 버거가 한가운데 오도록 놓는다. 바닥에 붙이면
  세로로 긴 기기에서 위쪽 2/3 가 빈 채로 남는다.

### 검증

Playwright + Chromium 으로 실제 파일을 띄워 확인했다.

- 부팅 시 콘솔 에러 0건, **외부 요청 0건**, 가로 스크롤 없음
- 320판 봇 플레이 중 페이지 에러 0건, 무한 판 0건
- 320×568(SE1) / 360×800 / 390×844 세 해상도에서 **최악 스택(6단)** 이
  조립대 안에 들어가고 재료 버튼이 44px 최소 터치 타겟을 넘는 것 확인
- 결과 화면 버거에 윗빵이 안 그려지던 버그를 스크린샷으로 발견해 고침
  (`drawBurgerFit` 이 `cap` 인자를 `drawStack` 까지 넘기지 않았다)

`og.png` 는 손으로 그리지 않고 **게임의 그리기 코드를 그대로 뽑아** 1200×630
페이지에 붙인 뒤 스크린샷으로 만든다. 공유 썸네일과 실제 화면이 갈라지지 않는다.

## 앱인토스 출시 가이드 대응 현황

[게임 출시 가이드](https://developers-apps-in-toss.toss.im/checklist/app-game.html)
기준으로 정적 웹에서 만족시킬 수 있는 항목은 모두 반영했다.

**충족**

- 최초 화면 10초 이내 진입 — 단일 HTML, 외부 요청 0건
- 사운드/햅틱 적용, 사용자가 직접 On/Off (설정 유지)
- 백그라운드 전환 시 사운드 즉시 종료(`AudioContext.suspend`) + 일시정지
- Safe Area 미침범 (`env(safe-area-inset-*)`)
- 진입 직후 바텀시트 자동 노출 없음
- 모든 화면에서 종료 가능(헤더 ✕ 상시 노출) + **종료 시 확인 모달**
- 인게임 풀스크린, 세로 모드 고정
- 브라우저 히스토리 조작 없음, OS 뒤로가기 제스처 미사용
- `eval` / `new Function` / 외부 스크립트 로드 없음
- 플레이 기록(최고 점수·최다 서빙) 재접속 후에도 유지
- 인터랙션 지연 2초 미만, 광고·결제 미사용
- 소리를 꺼도 게임이 어려워지지 않는다 — 인내심은 바 길이·3단계 색·카드
  흔들림·표정으로 4중 표시되고, 손님 도착은 고스트 카드로 예고된다

**콘솔 등록 후에 연결해야 하는 것**

웹 단일 파일 버전은 브릿지가 없어 조용히 건너뛴다. 교체할 곳은 어댑터 네 군데다.

| 필요한 것 | SDK |
| --- | --- |
| 리더보드 점수 제출 | `Game.setLeaderboardScore({ score: String(n) })` — 점수는 **문자열** |
| 리더보드 열기 | `Game.openLeaderboard()` |
| 미니앱 종료 | `Screen.close()` |
| 사용자 식별키 | `User.getAnonymousKey()` → `{ type: 'HASH', hash }` |

저장 키는 `burger.` 접두사를 쓴다(`tikkeul.` 과 충돌 없음).

### 남은 것

실기기 테스트는 콘솔 등록 후에만 가능하다. 지금은 데스크톱 Chromium 에서
검증된 상태이고, **토스 앱 안에서의 동작은 검증되지 않았다.** 미니앱 이식은
티끌모아 태산의 `toss-miniapp/port.py` 와 같은 방식으로 하면 된다.
