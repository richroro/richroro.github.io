# 불티나 버거

밀려드는 주문을 보고 재료를 순서대로 탭해 버거를 쌓고, 윗빵을 덮어 내보내는
한 손 세로형 주문 처리 게임. 앱인토스(App in Toss) 미니앱 게임 출시 가이드에
맞춰 만든 정적 웹 게임이다.

- 배포: https://richroro.github.io/games/bulti-burger/
- 소스: `index.html` 한 파일 (외부 스크립트·에셋·폰트·빌드 없음, 소리도 전부 합성)

## 게임 규칙

아래빵은 자동으로 깔린다. 주문 카드에 그려진 **아래에서 위 순서**대로 재료
버튼을 누르고, 맨 아래 윗빵 버튼으로 내보낸다. 스택과 똑같은 주문을 한 손님
중 **가장 급한 쪽에게 자동으로** 나가므로 손님을 미리 고를 필요가 없다.

- 파란 테두리는 "지금 쌓는 게 아직 맞다"는 확인이지 선택지가 아니다. 가장 급한
  카드에는 **다음 ○○** 이 적히고, 미니 스택에서 쌓은 층은 흐려지고 다음 층에
  파란 테두리와 화살표가 붙는다.
- 어느 주문의 접두사도 아닌 재료를 누르면 빨갛게 튕겨 나가고 0.4초 멈춘다.
  되돌리기가 없는 대신 **막다른 스택에 갇히는 상태가 존재하지 않는다.**
- 덜 쌓았을 때 서빙 버튼은 연한 파랑으로 **"2장 더 쌓아야 해요"** 라고 적힌다.
  그래도 누르면 −150 과 0.8초 잠금이다.
- 손님 인내심이 0이 되면 하트가 깨지고, 셋을 다 잃으면 끝난다.

재료 8종은 시간에 따라 풀린다 — 패티·치즈·양상추·토마토(0초) → 양파(40초)
→ 베이컨(80초) → 계란(120초) → 피클(160초).

처음 시작하면 **튜토리얼**이 뜬다. 시계와 인내심이 멈춘 채 주문 세 개를 대본대로
낸다 — ① 손가락 링을 따라 한 개 ② 첫 재료가 같은 주문 두 개(파란 테두리와 자동
배달을 보여 준다) ③ 혼자서 한 개. 건너뛸 수 있고 게임 방법에서 다시 할 수 있다.

### 급하게 내보내기

손님 인내심이 35% 밑으로 떨어지고 현재 스택이 그 주문의 **절반 이상**을
채웠으면 윗빵 버튼이 주황색으로 바뀐다. 덜 쌓았어도 내보내 하트를 지킬 수
있다. 대신 인내심·무실수 보너스와 콤보 배수가 전부 빠지고 0.35초 멈춘다.

### 조작

| 동작 | 터치 | 키보드 |
| --- | --- | --- |
| 재료 | 버튼 탭 | `1`~`8` 또는 자판 왼쪽 `QWER` / `ASDF` (그리드 2×4 와 같은 모양) |
| 서빙 | 윗빵 버튼 | `Space` / `Enter` |
| 버리기 | 조립대 오른쪽 위 ✕ | `Backspace` / `X` |
| 일시정지 | 헤더 ⏸ | `P` / `Esc` |

키는 `e.key` 가 아니라 `e.code` 로 받아서 **한글 자판 상태에서도** 같은 자리의 키가
먹는다. 데스크톱에서는 폰 폭(460px) 프레임으로 가운데 모으고, 마우스가 있는
기기에서만 버튼에 단축키가 표시된다.

## 점수 · 피버 · 등급

```
정상  = round((80×재료수 + 120×남은인내심비율 + 50×무실수) × 콤보배수) × VIP배수 × 피버배수
급송  = 80 × 쌓은재료수 × VIP배수 × 피버배수
콤보배수 = 1 + min(콤보,10) × 0.1     (최대 ×2.0)
```

- **VIP(👑)** 는 손님 5명마다 온다. 재료 한 장 더, 점수 2배, 카드에 금테.
- 무실수로 인내심 60% 이상 남기고 서빙하면 **가장 급한 다른 손님의 인내심이
  5% 회복된다** — 잘 만든 값이 그 자리에서 시간으로 환전된다.
- **피버** — 콤보가 10의 배수에 닿으면 8초 동안 점수 ×1.5, 조립대가 금빛으로
  달아오르고 음악이 빨라진다. 콤보가 끊기면 즉시 꺼진다. 점수에만 붙고 인내심·
  도착에는 손대지 않으므로 판 길이는 그대로다(아래 측정 참고).
- **등급** — S 70,000 / A 45,000 / B 25,000 / C 14,000. 실력별 봇 점수 분포에
  맞춰 잡아서 초보 C, 보통 B, 숙련 A 가 되고, S 는 숙련 봇 상위 10%(6만)보다 위다.

## 도전 과제

12개, 재접속해도 남는다. 처음 만든 목록은 숙련 봇이 **첫 판에 11개**를 풀어서
목표 구실을 못 했다. 한 판에 몇 개가 풀리는지 실력별로 재 가며 경계를 다시 잡았다.

| 과제 | 조건 | 완벽 | 숙련 | 보통 | 초보 |
| --- | --- | --- | --- | --- | --- |
| 🍔 첫 손님 | 첫 버거 | 100 | 100 | 100 | 100 |
| 🏃 급할수록 침착 | 한 판에 급송 3번 | 100 | 100 | 100 | 100 |
| ⚡ 콤보 장인 | 10연속 콤보로 피버 | 100 | 100 | 80 | 20 |
| 🥒 풀 메뉴 | 피클까지 해금 (160초) | 100 | 100 | 90 | 20 |
| 👑 VIP 대접 | 한 판에 VIP 12명 | 100 | 100 | 5 | 0 |
| ⏱️ 3분 영업 | 3분 버티기 | 100 | 70 | 5 | 0 |
| 🅰️ A 등급 | 한 판 45,000점 | 100 | 90 | 0 | 0 |
| 🌶️ 뜨거운 주방 | 한 판에 피버 4번 | 100 | 35 | 0 | 0 |
| ✨ 무결점 | 실수 없이 20개 연속 | 100 | 40 | 0 | 0 |
| 🛡️ 흔들림 없이 | 하트 3개로 2분 45초 | 95 | 65 | 5 | 0 |
| 💎 전설의 셰프 | S 등급 | 100 | 0 | 0 | 0 |
| 🧾 단골 가게 | 누적 버거 300개 | 여러 판에 걸쳐 | | | |

(빈 저장소에서 한 판 했을 때 풀리는 비율 %, 각 20판. 첫 판 평균 개수는
완벽 10.9 / 숙련 8.0 / 보통 3.9 / 초보 2.4.) 봇은 사람보다 한결같아서 사람에게는
이보다 어렵다.

기록 화면(🏆)에는 최고 점수와 등급, 판 수·누적 버거·최고 콤보·최다 서빙,
최고 기록 5판, 도전 과제 격자가 나온다. 결과 화면의 **공유**는 1080×1350
결과 카드 이미지(등급·점수·가장 잘 만든 버거)를 만든다. 휴대폰에서는 공유 시트로
이미지 파일을 넘기고, 파일 공유가 안 되는 곳에서는 미리보기와 저장·링크 복사를
띄운다. 공유 시트는 사용자 입력 직후에만 열리므로 `toBlob` 대신 `toDataURL` 로
동기에 파일을 만든다(사파리가 비동기 뒤의 공유를 막는다).

## 난이도와 측정값

난이도는 전부 **경과 시간**에 연동한다. 서빙 수에 연동하면 잘하는 사람이
난이도를 더 빨리 끌어올려 초보보다 먼저 죽는 역전이 생긴다.

| 항목 | 값 |
| --- | --- |
| 손님 도착 간격 | `max(1.25, 4.2 − 0.030·t)` 초 |
| 인내심 | `max(2.8, (13 + 2.6×재료수) × max(0, 1 − 0.0045·t) × 지터)` 초 |
| 대기줄 | 최대 3명 |
| 레시피 길이 | 0~18초 2장 → 125초 이후 4~6장 |

브라우저에서 **실제 게임 코드를 봇으로 돌려** 측정했다(각 80판, 총 320판).
봇은 프레임을 직접 돌리며 "현재 스택을 받아 줄 손님 중 가장 급한 쪽"을
목표로 삼고, 설정한 간격마다 한 번씩 탭한다.

| 플레이어 | 판 길이 10%/중앙/90% | 2~4분 | 점수 중앙 | 등급 | 서빙 |
| --- | --- | --- | --- | --- | --- |
| 완벽봇 (0.30초/탭, 오타 0%) | 3:08 / **3:12** / 3:16 | 100% | 103,779 | S | 89 |
| 숙련 (0.38초/탭, 오타 4%) | 2:57 / **3:01** / 3:07 | 100% | 50,325 | A | 68 |
| 보통 (0.50초/탭, 오타 8%) | 2:37 / **2:46** / 2:52 | 100% | 27,893 | B | 51 |
| 초보 (0.65초/탭, 오타 14%) | 2:18 / **2:32** / 2:41 | 약 98%\* | 18,224 | C | 40 |

320판 전부 정상 종료했고(무한 판 0건), 초보 대비 완벽봇 점수는 5.7배다.
피버를 넣기 전 판 길이(3:13 / 3:02 / 2:48 / 2:29)와 차이가 없다 — 피버는 점수만
벌린다(5.0배 → 5.7배). 아래 '실행 점검' 수정 뒤 다시 잰 160판도 3:13 / 3:01 /
2:48 / 2:28 로 같다.

\* 80판 표본에서는 100% 였지만, 판 수를 늘려 꼬리를 재면 초보 봇은 1,200판 중
22판(약 1.8%)이 1:36~2:00 사이에 끝난다. 실수가 한꺼번에 몰린 판이다. 보통 봇
이상은 400판 중 한 판도 2분 전에 끝나지 않았다. 게임에 '최소 2분'을 보장하는
장치는 없고, 넣으려면 초반 감쇠를 늦춰야 하는데 그러면 모든 실력대의 판 길이와
등급 경계가 함께 움직인다.

## 밸런스: 실제로 터졌던 것 세 가지

설계 단계의 수치를 그대로 구현했더니 **완벽봇이 12분 가드에 걸릴 때까지 죽지
않았다.** 원인은 셋이었고, 셋 다 "압박이 실제로는 걸리지 않는" 같은 병이었다.

| 증상 | 원인 | 대응 |
| --- | --- | --- |
| 대기줄이 3명에 절대 도달하지 않음(평균 2.1) | 줄이 꽉 찼을 때 도착 타이머를 고스트 예고 시간(0.6초)으로 되감았다. 자리가 날 때마다 그만큼 공짜 시간이 생겼다 | 꽉 차도 타이머는 계속 돌리고 0에서 멈춰 대기. 자리가 나는 즉시 입장 |
| 그래도 안 참 | 타이머를 아예 얼렸더니 이번엔 간격(1.25초) 전체를 자리가 난 **뒤에** 치렀다 | 0에서 멈추는 '문 앞 대기' 상태로 분리 |
| 후반에 아무도 안 죽음 | **급하게 내보내기가 처리량 이득이었다.** 2탭짜리 반쪽 버거를 던지면 하트를 지키면서 제대로 만드는 것보다 30% 빨랐다. 후반엔 전부 급송하는 게 최적 | 주문의 절반 이상을 쌓아야 발동 + 급송 뒤 0.35초 잠금. 지름길에 시간 값을 매겼다 |

인내심 하한도 4.0초에서 **2.8초로 내렸다.** 하한이 가장 빠른 플레이어의
처리 시간(3×1.25초)보다 높으면 평형이 생겨 판이 영원히 끝나지 않는다.
대기줄이 3명에서 막혀 도착이 멈추는 구조와 맞물리는 문제라, 하한을 다시
올리면 같은 증상이 재현된다.

## 독립 감사에서 나온 것

첫 버전을 얼려 두고 에이전트 셋이 따로 뜯어봤다(버그 헌터 / 명세 대비 누락 /
UX·데스크톱·접근성). 버그 보고 14건은 각각 다른 에이전트가 보고자 스크립트를 보지
않고 브라우저에서 다시 재현했고, 13건이 재현됐다. 검증자들은 수정안도 직접 패치해
돌려 봤는데, 그중 몇은 **내가 이미 넣은 수정이 모자라다**는 걸 보여 줬다(아래 표의
주황 테두리·고스트 카드·"+5%" 줄). 실제로 고친 것 중 중요한 것:

| 문제 | 원인 | 대응 |
| --- | --- | --- |
| **앱을 백그라운드로 보낸 뒤에도 소리가 남** (출시 가이드 위반) | 서빙 아르페지오처럼 `setTimeout` 으로 수십 ms 뒤 울리게 예약된 소리가 `ensure()` 의 `resume()` 으로 멈춘 AudioContext 를 다시 켰다 | 멈춘 동안(`halted`)과 `document.hidden` 일 때는 `ensure()` 가 아무것도 켜지 않는다. 수정 전 스냅샷에서 `running` 으로 재현 → 수정 후 `suspended` 확인 |
| 덜 쌓은 서빙 버튼이 완성 상태와 똑같이 파랬다 (−150 함정) | 표시가 `under` 와 `normal` 을 구분하지 않았다 | 연한 파랑 + "N장 더 쌓아야 해요" |
| 카드가 주황(급송 가능)인데 누르면 −150 | 카드 판정에 '절반 이상 쌓음' 조건이 빠져 버튼 판정과 달랐다. 조건을 맞춘 뒤에도 스택이 다른 손님 주문과 정확히 같을 때(버튼은 그 손님에게 정상 서빙)와 급송 대상이 둘일 때(버튼은 더 급한 쪽만) 어긋났다 | 주황은 **지금 버튼이 급하게 보낼 손님 한 명**에게만. 급송 불가인 빨간불 카드는 빨강 + 흔들림 |
| 게임 오버 뒤 조립대가 영원히 흔들리고 붉은 채 남음 | 흔들림·비네트 감쇠가 `playing` 일 때만 도는 `tick()` 안에 있었다 | 연출 갱신(`updateFx`)으로 옮김 |
| 마지막 두 재료를 같은 프레임에 누르고(두 손가락, 버벅이는 기기) 그 틱이 마침 그 손님의 마지막 틱이면 −150 | 서빙 유예를 `tick()` 끝에서만 걸었다. 보통은 직전 틱에 급송 구간이라 유예가 이미 켜져 있어서, 검증자는 "보고된 그대로는 도달 불가, 좁은 변형만 가능"으로 판정했다 | 서빙 가능해지는 탭 시점에도 유예를 건다. 한 줄이고 부작용이 없는 것을 검증자가 확인 |
| 7장짜리 VIP 주문의 맨 위 재료가 작은 화면 카드 밖으로 나감 | 미니 스택 층 높이 하한 8px × 7 이 캔버스보다 컸다. 조립대 축소배율도 최악 스택을 6장(163px)으로 잡고 있었는데 VIP 7장은 178px 이다 | 예산을 넘으면 층을 줄이고, 저화면에서도 카드는 줄이지 않는다. 최악 스택 상수를 178 로 |
| 고스트 카드(도착 예고)에 방금 떠난 화난 손님이 비침 | 빈 칸이 된 카드 내용을 지우지 않았다. 지우고 보니 흰 반투명 카드가 배경과 1단계밖에 차이가 없어 **예고 자체가 안 보였다** | 내용을 숨기고 회색 점선 카드로 |
| 회복 "+5%" 가 엉뚱한 카드에 뜨고, 반쯤에서 잘림 | 표시가 카드 칸에 묶여 있었다. 초록 번쩍임(0.3초)이 끝날 때 0.6초 애니메이션 클래스를 떼서 중간에 끊겼다 | 회복된 손님에게 묶고, 칸을 옮기면 음수 delay 로 이어서 재생. 애니메이션은 끝까지 |
| 서빙 직후 날아오던 재료가 빈 빵에 내려앉음 | 스택을 비워도 비행 중인 재료가 남았다 | 스택을 비우는 네 곳에서 비행도 끊는다 |
| 가로로 돌린 휴대폰에서 서빙 버튼이 화면 밖 | 웹에는 세로 고정이 없다 | 방향으로 추측하지 않고 **서빙 버튼이 화면 안에 들어오는지 직접 잰다.** 잘리면 안내("세로로 돌려 주세요" / 낮은 데스크톱 창이면 "화면이 조금 낮아요")를 띄우고 판을 멈춘다 |
| 헤더 '최고'에 진행 중 점수가 떴지만 저장은 게임 오버 때 | 표시와 저장 시점이 달랐다 | 저장된 기록만 보이고, 넘어서면 "신기록 중!" |

그 밖에 결과 화면 버거가 모달 등장 애니메이션(scale .97) 중에 측정돼 흐리던 것,
회전 때 한 프레임 빈 조립대, 긴 버거 위 점수 팝업이 떠오르다 화면 밖으로 잘리던 것,
기존 최고와 같은 점수에 "최고 기록!" 이
뜨던 것, 서빙 0개 판에 만든 적 없는 버거가 '가장 잘 만든 버거'로 나오던 것,
판 중에 밀린 알림이 결과 화면을 덮던 것도 고쳤다.

## 실행 점검에서 나온 것

PR 브랜치와 최신 `main` 을 합친 스냅샷을 여덟 가지 방식으로 실제로 돌렸다 — 폰에서 실제
탭으로 한 판(3:04, 45,261점 A), 처음 방문자의 튜토리얼, 데스크톱 키보드만, 화면 7종과
움직임 줄이기, 기존 118개 확인, 봇 160판, 사이트 전체를 HTTP 로 띄워 카드 클릭부터,
그리고 시드 고정 무작위 입력 3분 × 10회. 여기서 나온 이상은 다른 에이전트가 보고자
스크립트를 쓰지 않고 새로 재현했고, 아래는 **게임 버그로 확인된 것**과 완결성 점검이
추가로 찾아낸 것이다.

| 문제 | 원인 | 대응 |
| --- | --- | --- |
| **이어하기 직후 바로 앱을 내리면 소리가 켜진 채 남음** (출시 가이드 항목) | `resume()` 은 비동기다. 끝나기 전(헤드리스에서 13~17ms) 숨김 이벤트가 오면 `stopAll()` 은 상태가 아직 `suspended` 라 `suspend()` 를 부르지 않았고, 뒤늦게 끝난 `resume()` 이 뒤로 간 앱에서 컨텍스트를 켰다. 19번 중 18번 재현 | `stopAll()` 은 `closed` 가 아니면 무조건 `suspend()` 를 뒤에 세우고, 컨텍스트가 켜지는 순간 멈춘 상태면 다시 끈다 |
| 게임 오버 순간 누른 Space·Enter 가 결과 화면을 건너뛰고 바로 새 판 | 결과 창이 뜨면 키보드 사용자에게 '다시하기'에 포커스를 주는데, 모달 쪽 키 처리에 반복 입력·오버 직후 보호가 없었다. 서빙하려고 Space 를 연타하던 손이 그대로 눌렀다 | 오버 뒤 0.7초 동안과 꾹 누른 자동 반복은 버린다. 터치도 같다 — 재료 윗줄과 결과 창 아랫줄(공유·기록·나가기)이 화면에서 겹쳐서, 캡처 단계에서 0.7초 동안 결과 창 클릭을 끊는다 |
| 튜토리얼 서빙 차례의 손가락 링이 버튼에 묻힘 | 링 테두리와 서빙 버튼이 같은 파랑이라 버튼 안쪽 부분이 사라지고 선이 글자를 가로질렀다 | 서빙 버튼일 때만 바깥을 6px 두르는 둥근 사각형으로, 크기 대신 밝기로 숨 쉰다 |
| 튜토리얼 중 ✕(버리기)가 코치 말풍선 뒤에 있어 눌리지 않음 | 말풍선(z-index 4)이 조립대 오른쪽 위를 덮는다 | 튜토리얼 중엔 숨긴다. 틀린 재료는 튕겨 나가서 비울 일이 없다 |
| 튜토리얼 3단계 카드 막대가 초록으로 굳고 설명 없는 "+5%" | 무실수 서빙 회복이 튜토리얼에도 걸리는데, 번쩍임을 줄이는 `tick()` 이 튜토리얼 동안 돌지 않는다 | 튜토리얼에선 회복하지 않는다(인내심이 멈춰 있어 회복할 것도 없다) |
| 완성된 7재료 VIP 카드의 윗빵 파란 테두리 윗변이 절반 두께 | 층이 예산을 꽉 채워 테두리 윗변이 y=0 에 걸려 1.5px 선의 절반이 캔버스 밖으로 나갔다. 빈 스택일 때 첫 층 '다음' 테두리의 아랫변도 같은 식으로 잘렸다 | 윗변은 1px 안쪽으로, 아랫변은 캔버스 안으로 당긴다(측정: 윗변 0.75px → 1.5px) |
| 저장된 `burger.stats` 모양이 틀리면 흰 화면 또는 결과 화면이 안 뜸 | `'5'` 같은 원시값에 `top` 을 달다 부팅이 죽었고, `top` 이 배열이 아니면 게임 오버 때 `push` 가 터졌다(하트 0 인데 결과 창 없음) | 읽을 때 모양을 맞춘다. 깨진 값 10가지로 부팅→게임 오버→결과·기록 화면 확인 |
| 앱인토스 SDK 함수가 그 자리에서 예외를 던지면 🏆 가 게임만 멈추고 아무 화면도 안 띄움 | 호출 실패를 '연결됨' 으로 돌려줬다 | 동기 예외면 연결 안 된 것으로 보고 웹 동작(로컬 기록)으로 |
| 시작·이어하기 첫 프레임에 게임 시계가 음수(최저 −0.03초) | 입력 핸들러에서 찍은 `lastT` 보다 다음 프레임 시각이 이를 수 있다 | `dt < 0` 이면 0 |

그 밖에: 데스크톱에서 하트를 잃을 때 붉은 비네트가 창 전체 기준이라 460px 프레임 밖
회색 여백에만 번지던 것(프레임 기준으로), 0점 판(시작하고 방치)이 '최고 5판'에 오르던 것,
튜토리얼에서 덜 쌓고 내보내면 설명 없이 −150 이 뜨던 것(코치가 이유를 말한다), 건너뛰기
버튼 누르는 자리가 56×31px 이던 것(44px), `sitemap.xml` 에 이 게임이 빠져 있던 것.

## 구현 메모

물리가 없다. 티끌모아 태산과 겹치는 건 "한 손 세로 2~4분 토스 스타일" 셸뿐이고,
압박의 원천이 공간이 아니라 시간이며 입력이 드래그가 아니라 단일 탭이다.

- **타이머는 전부 `remain -= dt` 감산이다.** `performance.now()` 절대 시각
  deadline 을 쓰면 백그라운드 복귀 때 타이머가 이미 다 지나 있어서 손님 셋이
  동시에 나간다. 감산 방식은 `state === "playing"` 일 때만 dt 를 먹으므로
  일시정지 하나로 전부 자동으로 멈춘다. 복귀 직후 1초는 인내심을 세우지 않는다.
- **`ctx.roundRect` 를 쓰지 않는다.** Safari 16 미만 웹뷰에 없어서 흰 화면이
  된다. `arcTo` 로 만든 `rr2()` 를 쓰고, `ctx.ellipse` 에도 폴백을 뒀다.
- 재료는 `drawIngredient()` 하나가 **조립대 / 주문 카드 미니 스택 / 버튼 아이콘 /
  결과 화면 / 공유 카드 / og.png** 를 전부 그린다. 생김새가 갈라질 수 없다.
- 식별은 4중이다 — 색, 두께(11~26px 로 8종 전부 다름), 실루엣, 레이어 오른쪽 끝의
  **패턴 마커**(점 1~4개 / 세로선 1~2개 / 가로선). 현재 팔레트의 최소 색차는
  ΔE 14.2(계란↔양파), 적록색맹(deuteranopia) 시뮬레이션에서 ΔE 10.6
  (토마토↔피클)이고, 이 두 쌍은 두께와 마커로도 갈린다. 크게 그리는 공유 카드에서는
  마커가 잡티로 보여서 뺀다.
- 손맛: 날아오는 재료가 버튼 아이콘 크기에서 커지며 오고, 맨 위 한 장만 0.7 →
  1.08 → 1.0 으로 눌렸다 튀며 부스러기가 튄다. 서빙은 윗빵이 떨어져 덮이며 참깨가
  톡 튀고, 손님 카드가 ✓ 로 튕기며 사라지고 뒤 카드가 미끄러져 온다. 떠나는 손님은
  카드가 기울며 떨어지고 하트가 💔 로 깨지며 화면 가장자리가 붉게 번진다. 점수는
  굴러 올라간다.
- 소리는 전부 WebAudio 합성이다. 재료 올리는 소리는 **층 높이별** 펜타토닉이라
  5단을 쌓으면 상승 아르페지오가 된다. 배경음악은 C–Am–F–G 네 마디를 8분음표로
  돌리는 가벼운 그루브인데, 0.15초 앞을 내다보며 AudioContext 시각에 예약해서
  타이머 지터가 박자에 섞이지 않는다. 템포는 경과 시간을 따라 96 → 130 BPM 까지
  오르고 피버 때 더 빨라진다. 소리 버튼은 🔊 전부 → 🔉 효과음만 → 🔇 끔.
- 움직임 줄이기 설정이면 화면 흔들림·카드 흔들림·착지 출렁임·카드 미끄러짐을 끈다.
  정보(빨간 테두리, 비네트, ✕)는 그대로 남는다.
- 모달은 `role="dialog"` + `aria-modal`, 떠 있는 동안 뒤쪽 게임 화면은 `inert`.
  잠긴 재료·꺼진 서빙 버튼은 실제로 `disabled`, 하트·주문 카드·조립대에는 읽기용
  라벨이 붙는다. 자동 포커스는 마지막 입력이 키보드였을 때만 준다(터치 사용자에게
  포커스 링이 뜨지 않게). 보조 회색 글자는 #6B7684(흰 배경 4.6:1), 주황 버튼
  글자는 흰색 대신 진한 색(9:1).

비용이 얻는 것보다 컸고, 압박의 축을 시간 하나로 모으는 편이 2~4분 세션에
맞았다.

## 앱인토스 출시 가이드 대응 현황

[게임 출시 가이드](https://developers-apps-in-toss.toss.im/checklist/app-game.html)
기준으로 정적 웹에서 만족시킬 수 있는 항목은 모두 반영했다.

**충족**

- 최초 화면 10초 이내 진입 — 단일 HTML, 외부 요청 0건
- 사운드/햅틱 적용, 사용자가 직접 On/Off (배경음악·효과음 따로, 설정 유지)
- 백그라운드 전환 시 사운드 즉시 종료 + 일시정지. **예약돼 있던 소리까지 막는다**
  (첫 버전은 서빙 직후 전환하면 소리가 다시 켜졌다 — 위 감사 표. 이어하기 직후
  전환하는 좁은 경쟁도 실행 점검에서 찾아 막았다)
- Safe Area 미침범 (`env(safe-area-inset-*)`)
- 진입 직후 바텀시트 자동 노출 없음
- 모든 화면에서 종료 가능(헤더 ✕ 상시 노출) + **종료 시 확인 모달**
- 인게임 풀스크린, 세로 모드 (웹에서는 조작 버튼이 화면 밖으로 나가면 안내 후 일시정지)
- 브라우저 히스토리 조작 없음, OS 뒤로가기 제스처 미사용
- `eval` / `new Function` / 외부 스크립트 로드 없음
- 플레이 기록(최고 점수·최다 서빙·누적 기록·도전 과제) 재접속 후에도 유지
- 인터랙션 지연 2초 미만, 광고·결제 미사용
- 소리를 꺼도 게임이 어려워지지 않는다 — 인내심은 바 길이·3단계 색·카드
  흔들림·표정으로 4중 표시되고, 손님 도착은 고스트 카드로 예고된다

**콘솔 등록 후에 연결해야 하는 것**

웹 단일 파일 버전은 브릿지가 없어 조용히 건너뛴다. 교체할 곳은 어댑터 네 군데다.

| 필요한 것 | SDK |
| --- | --- |
| 리더보드 점수 제출 | `Game.setLeaderboardScore({ score: String(n) })` — 점수는 **문자열** |
| 리더보드 열기 | `Game.openLeaderboard()` |
| 미니앱 종료 | `Screen.close()` |
| 사용자 식별키 | `User.getAnonymousKey()` → `{ type: 'HASH', hash }` |

저장 키는 `burger.` 접두사를 쓴다(`tikkeul.` 과 충돌 없음) — `best`, `bestServed`,
`stats`(판 수·누적 버거·최고 콤보·최고 5판), `ach`(도전 과제), `tut`(튜토리얼 완료),
`muted`, `music`, `uid`.

### 남은 것

실기기 테스트는 콘솔 등록 후에만 가능하다. 지금은 Chromium 에서만 검증된 상태이고,
**토스 앱 안에서의 동작과 iOS 사파리 웹뷰의 공유 시트·소리는 검증되지 않았다.**
미니앱 이식은 티끌모아 태산의 `toss-miniapp/port.py` 와 같은 방식으로 하면 된다.
