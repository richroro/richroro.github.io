# 차가 보는 것

자율주행 화면이 보여 주는 층들 — 차선 · 물체 · 주행 가능 영역 · 계획 경로 · 점유 격자 — 이
각각 무엇이고 어떻게 겹쳐 보이는지를 3D 로 다시 그린 페이지. 슬라이더를 밀면 실제 장면이 인식 화면으로 녹는다.

- 배포: https://richroro.github.io/fsd/
- 소스: `index.html`(화면·조작) + `assets/fsd.js`(장면)
- 공용: `/assets/scene-kit.js` + `/assets/three.min.js`

## 먼저, 이건 무엇이 아닌가

**실제 주행 소프트웨어의 출력이 아니다.** 실제 인식 결과를 받아 오지도, 재현하지도 않는다.
어떤 회사가 내부적으로 무엇을 어떻게 계산하는지에 대한 주장도 담지 않았다.
화면에 그 문장을 그대로 적어 뒀다. 여기서 보여 주는 건 **자율주행 시각화라는 형식**이
어떤 층으로 이뤄져 있고 그 층이 각각 무슨 뜻인지, 그것뿐이다.

## 차는 서 있고 세상이 흐른다

길은 +Z 로 뻗고 내 차는 원점에 있다. 대신 세상이 -Z 로 흘러간다. 좌표가 커지지 않으니
정밀도 문제가 없고, 카메라도 따라다닐 필요가 없다.

- 노면은 한 장짜리 캔버스 무늬를 세로로 반복시키고 `offset.y` 만 빼 준다 → 끝없는 도로
- 다른 차는 **상대 속도**로만 움직인다(`z += (내 속도 − 그 차 속도) × dt`). 뒤로 밀려나면 앞쪽으로 되돌려 다시 쓴다
- 가로등과 나무도 같은 방식으로 돌려쓴다

## 실제 ↔ 인식 크로스페이드

슬라이더 값 하나가 두 세계의 투명도를 반대로 민다. 길(무대)만은 양쪽에 다 남되 어두워진다.

```js
real.visible  = v < 0.99;              // 보이는 세상
seen.visible  = v > 0.01;              // 차가 보는 세상
for (const m of realMats)  m.opacity = 1 - v;
for (const m of stageMats) m.opacity = lerp(1, 0.28, v);
```

## 층마다 셰이더 하나

| 층 | 그리는 법 |
| --- | --- |
| 차선 | 리본 네 줄. 실선·점선을 셰이더의 `fract` 로 가르고 멀수록 흐려진다 |
| 물체 | `EdgesGeometry` 로 뽑은 상자 테두리 + 옅은 채움 + 이름표(캔버스). 이름표는 늘 카메라를 본다 |
| 주행 가능 영역 | 바닥 한 장. 흘러가는 가로줄과 가장자리 발광으로 '여기까지' 를 보여 준다 |
| 계획 경로 | **매 프레임 다시 뽑는 리본.** 차선을 바꾸면 이 리본이 먼저 휜다 |
| 점유 격자 | 13×30 칸 인스턴스. 칸마다 차와 겹치는지 보고 색을 넣는다(가산 합성이라 빈 칸은 검정 = 안 보임) |

계획 경로가 먼저 휘는 게 이 화면의 요점이다. 앞차가 느리면 판단이 먼저 바뀌고, 차체는 그 뒤를 따라간다.

```js
const x = lerp(egoX, targetX, smooth(0, 1, clamp(z / 28, 0, 1)));   // 앞쪽일수록 새 차선 쪽으로
```

## 차 한 대 만들기

옆모습 실루엣(보닛 → 앞유리 → 지붕 → 트렁크) 점 열 개를 `ExtrudeGeometry` 로 옆으로 밀어내면 차가 된다.
유리는 지붕 부분만 조금 좁게 한 번 더 밀어낸다. 바퀴는 원기둥 네 개.
트럭은 같은 형상을 1.35 배로 키워 쓴다.

## 조작

| 입력 | 동작 |
| --- | --- |
| 시야 슬라이더 · `V` | 실제 장면 ↔ 차가 보는 것 |
| 드래그 / 휠 | 자유 시점으로 전환해 돌려 보기 |
| `1` `2` `3` `4` | 추적 · 보닛 · 위 · 자유 |
| `←` `→` | 해설 앞뒤로 |

## 성능

- 삼각형 약 9 만, 드로우 콜 약 150. 인식 층은 셰이더 다섯 개가 전부다
- 점유 격자는 인식 화면이 꺼져 있으면 계산도 건너뛴다
- 탭이 가려지면 멈추고, `prefers-reduced-motion` 이면 절반 속도로 시작한다
