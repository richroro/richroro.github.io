# 숏폼 해부기 — 내 영상의 컷·소리·안전영역을 수치로

영상 파일을 넣으면 컷이 언제 끊기는지, 소리가 얼마나 큰지, 앱 UI 에 무엇이 가려지는지를
재서 보여 주는 정적 웹 앱. 파일을 서버로 올리지 않고 `objectURL` 로만 열어 브라우저 안에서 전부 처리한다.

- 배포: https://richroro.github.io/shorts-analyzer/
- 소스: `index.html` 한 파일 (외부 스크립트·빌드 없음, 구글 폰트만 링크)
- 짝이 되는 도구: [웹컷](../video-editor/) — 편집은 그쪽, 진단은 이쪽

## 왜 만들었나

남의 영상을 가져다 재편집하는 쪽은 저작권·플랫폼 정책 양쪽에서 막힌 길이다.
그래서 반대로, **내가 만든 영상이 실제로 어떤 수치인지** 재는 도구를 만들었다.
"왜 안 터지지"를 감으로 말하는 대신 컷 중앙값 1.2초, 도입부 변화량 101%, −15.8 LUFS 로 말하게 하는 게 목적이다.

## 되는 것

| 영역 | 내용 |
| --- | --- |
| 컷 | 컷 전환 시점, 하드컷/전환 구분, 샷 개수, 컷 길이 중앙값·분포, 분당 컷 수 |
| 화면 | 샷별 화면 변화량과 평균 밝기, 가장 오래 멈춰 있는 구간, 첫·마지막 프레임 유사도(루프) |
| 소리 | 통합 라우드니스(LUFS), 피크·클리핑, 무음 구간, 소리가 처음 나는 시각 |
| 도입 | 첫 컷 시각, 0~3초 변화량이 전체 평균의 몇 %인지 |
| 안전영역 | 틱톡·릴스·쇼츠 UI 가 덮는 영역을 실제 프레임 위에 겹쳐 보기 (시점 스크럽) |
| 비교 | 여러 영상의 수치를 &lsquo;참고 세트&rsquo;로 쌓아 두고, 그 분포(사분범위·중앙값) 위에 지금 영상이 어디 있는지 |
| 출력 | 진단 12항목, 샷별 표, 대표 프레임 스트립, CSV·JSON 내보내기 |

## 어떻게 재는가

### 컷 검출

초당 최대 15회로 표본을 뜨고 각 프레임을 48×85 로 줄인다. 픽셀을 밝기(Y)와 색차(Cb·Cr)로 바꾼 뒤
이웃한 두 표본 사이의

- **Y×Cb×Cr 결합 히스토그램 차이** (8×4×4 = 128칸) — 카메라가 움직여도 잘 안 흔들린다
- **격자 픽셀 차이** — 색 분포가 비슷한 컷을 잡는다

를 `0.65 : 0.35` 로 섞어 점수를 만든다. 임계값은 `중앙값 + 6 × 1.4826 × MAD`, 하한 0.085.
평균·표준편차를 쓰지 않는 이유는 컷 자체가 평균을 끌어올려 자기 기준을 망가뜨리기 때문이다.

### 라우드니스

ITU-R BS.1770-4 그대로다. 48kHz 로 리샘플 → K-가중 2단 biquad → 400ms 블록을 75% 겹쳐 측정 →
절대 게이트 −70 LUFS, 상대 게이트 −10 LU → 통합값.

### 참고 세트

한 영상의 절대값보다, **잘 도는 영상들이 어느 범위에 몰려 있고 내 것이 그 어디쯤인지**가 훨씬 쓸모 있다.
영상을 하나씩 넣어 참고 세트에 쌓으면 10개 지표를 불릿 차트로 나란히 놓는다 —
회색 띠가 사분범위, 세로 눈금이 중앙값, 파란 점이 지금 영상이다.

의도적으로 하지 않은 것이 하나 있다. **"조회수 높은 영상은 컷이 몇 초"라는 기본값을 넣어 두지 않았다.**
업계에 도는 통설은 있지만 측정된 데이터가 아니라서, 숫자를 지어내는 대신 직접 모으게 했다.
참고가 8개 미만이면 중앙값을 경향으로 읽지 말라는 경고가 뜬다.

저장되는 것은 **파일 이름과 지표 숫자뿐**이다(`localStorage`, 8개 기준 1.3KB). 영상도 프레임도 썸네일도 남기지 않는다.

## 구조

- 상태는 `A` 하나다. `{ meta, F(프레임 계열), C(컷·샷), AU(오디오), m(지표), checks, stats }`.
- 화면은 전부 `A` 에서 파생된다. 새 영상을 넣으면 `A` 를 갈아 끼우고 다시 그린다.
- `F.dPix` 는 검출기가 쓰는 **날것**, `F.motion` 은 그래프·통계가 쓰는 **컷을 걷어낸** 계열로 나눠 둔다.
- 캔버스는 세 개(시간축·분포·안전영역). 테마를 바꾸거나 창 크기가 변하면 `drawAll()` 로 통째로 다시 그린다.
- `window.__sa` 로 `run` / `result` / `detectCuts` / `integratedLUFS` 를 노출한다. 헤드리스 검증이 화면과 같은 코드를 탄다.

### 그래프 규칙

단위가 다른 세 지표를 한 축에 겹치지 않는다. 샷 배치·화면 변화량·소리 크기를 위아래로 나누고 가로축만 공유한다
(두 개의 세로축을 가진 그래프는 두 축의 정렬이 임의라서 없는 상관관계를 만들어 낸다).
계열 색 세 개는 라이트·다크 표면에 대해 검증기를 돌려 통과한 조합만 썼다 —
전 쌍 CVD ΔE 9.2(라이트) / 9.4(다크), 정상시야 ΔE 24.0 / 20.9. 라이트 모드의 청록만 대비 2.82:1 로 3:1 아래라,
같은 값을 표로도 제공하는 것으로 보완한다.

## 검증

헤드리스 크로미움(Playwright)에서 48개 단언을 돌렸다. 층위를 나눠 둔 이유는,
end-to-end 만으로는 어디가 틀렸는지 알 수 없기 때문이다.

**1. 검출기 단위** — 잡음 위에 스파이크를 심은 합성 계열을 `detectCuts` 에 직접 넣는다.
심어 둔 6개를 시각까지 정확히 복원하고, 30ms 뒤에 겹쳐 둔 것은 최소 샷 길이로 기각하며,
연속 4표본 구간은 `trans`, 단발은 `hard` 로 분류하는 것까지 확인한다.

**2. 라우드니스 수치** — 1kHz 사인의 K-가중 이득을 전달함수에서 직접 계산해 기대 LUFS 를 만들고,
구현값과 0.15dB 이내로 맞는지 본다(측정 −9.024 / 예측 −9.024). 같은 신호를 2채널에 넣으면 정확히 +3.010dB.
톤 3초 뒤에 무음 3초를 붙였을 때 통합값이 톤만 있을 때와 거의 같고, 게이트가 없을 경우의 값보다
2.5dB 이상 높은 것으로 게이팅이 실제로 동작함을 확인한다.

**3. end-to-end** — 페이지의 샘플 생성기가 컷 시점·무음 구간·정적 구간을 미리 정해 두고 실시간 녹화한다.
그 파일을 실제 UI 경로로 넣어 계획과 대조한다.

- 컷 8개를 계획 시각과 ±0.25초 이내로 전부 검출 (1.2 / 2.0 / 3.4 / 4.2 / 6.5 / 7.1 / 8.0 / 10.2)
- 도입 무음 0~0.6초, 의도한 4.5~6.0초 무음 구간, 8.0초부터의 정적 구간 검출
- 오디오 디코딩·LUFS·피크, 샷별 대표 프레임 9개, 표 9행, KPI 6개, 진단 12항목 렌더
- 호버 툴팁, 샷 선택 연동(스트립↔표), 플랫폼 탭, 테마 토글 후 재렌더
- 390px 폭에서 가로 넘침 0px, 페이지 자체 콘솔 오류 없음

**4. 참고 세트** — 값을 아는 참고 6개를 심어 두고 UI 경로로 검산한다.
`medShot` 을 0.8~1.8 로 균등하게 넣어 중앙값 1.30 / 사분범위 1.05~1.55 / 범위 0.80~1.80 이
화면에 그대로 나오는지 본다. 현재 영상을 세트에 넣어도 자기 자신은 분포에서 빠지는 것(n=6 유지),
새로고침 후에도 남는 것, 저장된 문자열에 `data:`·base64 가 없는 것(=영상이 안 들어간 것),
영상을 열지 않은 상태에서도 카드가 **실제로 보이는** 것까지 확인한다.

샘플 영상은 데모이자 회귀 테스트 기준이다. 검출기를 건드리면 이 8개 컷으로 먼저 확인한다.
특히 1.2초 컷은 **밝기가 같고 색만 다른** 경우라, 색차를 빼면 바로 실패한다.

## 한계

- 탐색 기반 샘플링이라 영상 길이에 비례해 시간이 걸린다. 15분 넘는 파일은 막아 뒀다.
- 초당 15표본이라 컷 시점 정밀도는 약 ±0.07초다. 3분이 넘어가면 표본 간격이 늘어 더 거칠어진다.
- 아주 느린 디졸브나 페이드는 임계값 아래로 깔려 안 잡힐 수 있다. 반대로 심하게 흔들리는 핸드헬드나
  빠른 팬은 컷으로 오인될 수 있다.
- 글자를 읽지 않는다(OCR 없음). 자막이 안전영역을 침범하는지는 겹쳐 놓은 화면을 눈으로 봐야 한다.
- 안전영역 좌표는 공개된 앱 화면을 재어 만든 근사치다. 기기·앱 버전·언어·캡션 길이에 따라 달라진다.
- 라우드니스는 통합값만 낸다. short-term/momentary, true peak(오버샘플링)는 넣지 않았다.
- `decodeAudioData` 가 못 푸는 컨테이너(일부 `.mov`)는 소리 항목을 건너뛴다. 영상 분석은 그대로 된다.
- 참고 세트는 이 브라우저에만 남는다. 기기 간 동기화도, 백업도 없다. 시크릿 창에서는 탭을 닫으면 사라진다.
- 참고가 적으면 중앙값·사분범위는 숫자일 뿐 경향이 아니다. 8개 미만이면 경고가 뜨지만 계산 자체는 막지 않는다.
- **진단 문구의 임계값은 업계 경험칙이지 검증된 기준이 아니다.** "컷 중앙값 2.5초", "도입 3초",
  "−14 LUFS" 는 참고선일 뿐이다. 이 도구가 보증하는 것은 측정값까지다.
