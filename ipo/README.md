# 공모주 캘린더

한국 공모주 청약 일정과 수요예측 결과, 상장 성적을 한 화면에서 보고, 청약 금액과 손익을 계산하는 페이지.

- 배포: https://richroro.github.io/ipo/
- 종목 바로 열기: `/ipo/#i=<id>` (상세 창의 **링크 복사**)

## 무엇을 할 수 있나

화면은 **홈 · 일정 · 분석 · 도구 · 내 청약 · 가이드** 여섯 개로 나뉜다(휴대폰은 아래 탭, PC 는 위 탭). 주소 끝으로 바로 열 수 있다: `#schedule` `#calendar` `#market` `#method` `#plan` `#calc` `#my` `#guide`.
홈에는 오늘의 주목 종목, 오늘·다음 영업일 일정, 요약 숫자, 옆으로 넘기는 '다가오는 청약'이 있다. 글꼴은 Pretendard.

| 기능 | 내용 |

| 블로거식 점수 | 기관경쟁률 · 의무보유확약 · 공모가 확정 위치 · 유통가능물량 · 공모 규모 · 구주매출 · 시장 온도 7개 기준을 100점으로 채점하고 **적극 참여 / 참여 / 균등만 / 관망** 판정. 모르는 값은 빼고 다시 맞추며, 종목 상세에서 직접 입력하면 바로 다시 채점. 위험 신호(기관경쟁률 100:1 미만, 밴드 하단 미만 확정, 유통물량 45% 초과 …)는 판정 상한을 건다. 규칙은 `score.js` 한 곳 |

| 이번 주 주목 | 청약 중·예정 종목 중 점수 1위를 점수 고리와 핵심 숫자로 |

| 판정별 성적 | 상장한 종목을 청약 당시 숫자로 다시 채점해 판정별 평균·중앙값 시초가, 공모가 아래·따블 비율. 시장 온도는 그 종목 청약일 이전 90일만 써서 미래 정보를 섞지 않는다 |
| 언제 팔았으면? | 지난 1년 상장주를 시초가·첫날 종가·지금 가격에 팔았을 때의 평균·중앙값, 종가가 시초가보다 높았던 비율 |

| 기대 수익 · 주관사 한 줄 | 판정이 난 청약 예정 종목엔 '균등 1주 기대 수익'(같은 판정 지난 종목의 시초가 중앙값 × 공모가 − 청약 수수료, 5곳 이상일 때), 수요예측 전 종목엔 대표 주관사의 1년 시초가 평균 |
| 만약에 판정표 | 수요예측 전 종목 상세에 기관경쟁률 5구간 × 확약 4구간 표. 칸마다 그렇게 나왔을 때의 판정과, 지난 1년 같은 구간 종목의 시초가 중앙값·표본 수 |
| 상장일 매도 코치 | 청약이 끝나고 상장 전후 사흘: 확약 구간이 같은 지난 종목의 시초가·첫날 종가 중앙값, 종가가 더 높았던 비율, 따따블 비율. 내 기록에 배정이 있으면 공모가 1.6~4배에 팔 때 금액. 스팩은 스팩끼리 |
| 비슷했던 종목 5곳 | 판정이 난 종목·상장 종목 상세에 기관경쟁률·확약·공모 규모·공모가 위치·가격이 가장 가까운 지난 종목 5곳(이 종목 청약 전 상장분만)과 시초가·종가·지금 |
| 달력 | 월 달력에 청약(평일만)·환불·상장. 날짜를 누르면 그날 일정. `.ics` 로 종목별·관심 종목 전체 내보내기 — **알림 포함**(청약 첫날 09:30, 마감일 13:00, 상장일 08:20) |
| 기업 분석 | 종목 상세에 한 줄 요약(매출·영업이익·흑자/적자·공모가 PER), 사업 설명, 대표·기업 구분·본점·홈페이지, 품목별 매출 비중, 연도별 매출·영업이익 막대, 몸값(시가총액·PER·PSR·PBR — 상장 후 주식 수를 모르면 EPS로 어림)과 지난 1년 공모주 PER 중앙값 비교, 부채·유동비율(업종 평균), 최대주주 지분, 밴드 상단 이상 가격을 낸 기관 비율, 확약 기간별 비율, 장외 호가, 좋은 점·걸리는 점, 회사가 고른 비교 기업. 나란히 비교에도 매출·영업이익률·PER. 38 상세 페이지(증권신고서 요약)에서 읽어 `data/corp.json` 에 따로 둠(일정은 가볍게 먼저 뜨고 기업 분석은 뒤에 붙음) |
| 비례 청약 계산 | 청약 전·중 종목 상세에 증거금(100만~3억 칩 또는 직접)·계좌 수를 넣으면 기대 배정(균등 + 비례), 기대 손익, 증거금 1억당 손익과 연환산, 비례 1주에 드는 증거금. 청약 전이면 통합 경쟁률은 기관경쟁률 같은 구간 지난 종목의 중앙값(순위상관 0.81)으로, 수익률은 같은 판정의 시초가 중앙값으로 추정하고 직접 바꿀 수 있음. 경쟁률 100:1 미만이면 경고 |
| 비례 성적표 | 분석 화면에 지난 1년 종목마다 1억씩 비례로 넣었다면: 1억당 중앙값·연환산, 전부 넣었을 때 합계, 적극·참여만 넣었을 때 합계, 판정별 표(횟수·중앙값·합계·이익 비율), 가장 많이 번·잃은 3곳 |
| 계좌 준비 | 가진 증권사를 누르면(이 기기에 저장, 처음엔 내 기록의 증권사로 채움) 다가오는 청약마다 주관사 계좌가 있는지, 없으면 어느 증권사를 언제부터·언제까지 만들면 되는지 순서를 짬. 20영업일 개설 제한을 지키며 판정이 좋고 급한 청약이 먼저 오도록 고름. 마지막 개설일, '만들었어요' 버튼, 계좌 때문에 놓치는 청약, 지난 1년 자주 주관한 증권사. 홈에 다음에 만들 계좌 한 줄, 상세의 증권사 고르기에 ✓ 계좌 있음·없음 |
| 자금 플래너 | 다가오는 청약마다 전략(균등 최소 / 균등+비례 금액 / 주수 지정 / 건너뛰기, 기본은 판정대로)을 고르면 청약일에 나가고 환불일·상장일에 돌아오는 돈을 날짜별 계단 그래프로. 한 번에 필요한 최대 자금, 가족 계좌 수, 첫날·마감일 청약 선택, 플랜 전체를 달력으로. 종목마다 기대 손익(비례는 추정 경쟁률로)과 합계 |
| 나란히 비교 | 카드의 ⇄ 로 3곳까지 담아 판정·7개 기준·공모가·일정·최소 증거금·주의 사항을 한 표로. 칸마다 더 좋은 쪽을 색칠 |
| 공유 카드 | 종목 점수를 1080×1350 이미지로 만들어 휴대폰 공유 시트(카톡 등)로 보내거나 저장 |
| 계산기 | 증거금, 균등 + 비례(청약 주수 ÷ (통합 경쟁률 × 2)) 예상 배정, 비례 1주에 드는 증거금, 환불 예상액, 상장일 가격(-40%~+300%)별 순손익 |
| 내 청약 기록 | 실현 손익, 올해 손익, 보유 평가 손익, **월별 손익 그래프, 증권사별 배정률·손익, 승률**. localStorage 에만 저장. CSV, JSON 백업·복원 |
| 공모주린이 | 첫 청약 6단계, 용어 사전 18개, 자주 묻는 것 |
| 그 밖 | 휴대폰 아래 탭(오늘·일정·달력·플래너·내 기록), 불러오는 동안 스켈레톤, 관심 종목(★), `/` 로 검색, 다크 모드, 앱 설치(PWA)·오프라인 열람 |

## 파일

`data/ipo.json` 일정 · `data/corp.json` 기업 분석 · `index.html` 화면 · `app.js` 일정·상세·달력·계산기·기록 · `score.js` 점수 규칙(순수 함수) · `acct.js` 계좌 준비(순서 짜기는 순수 함수, `tests/acct.test.js`) · `extra.js` 플래너·비교·공유 카드·기록 대시보드·아래 탭(`app.js` 가 보내는 `ipo:*` 이벤트로 그림) · `ipo.css` · `sw.js`

## 데이터

페이지는 `data/ipo.json` **한 파일**만 읽는다. `build.py` 가 만들고, GitHub Actions
(`.github/workflows/update-ipo.yml`)가 평일 07:10 · 12:10 · 17:10 KST 에 다시 만들어 커밋한다(갱신 시각만 바뀌면 커밋하지 않는다). 인증키는 필요 없다.

| 무엇 | 출처(38커뮤니케이션) | 막히면 |
| --- | --- | --- |
| 청약 일정 · 확정/희망 공모가 · 청약경쟁률 · 주간사 | `/html/fund/index.htm?o=k` | **실패로 끝나고 기존 파일 유지** |
| 수요예측일 · 공모 금액 · 기관경쟁률 · 의무보유확약 | `/html/fund/index.htm?o=r1` | 이전 값 유지 |
| 상장일 · 시초가 · 첫날 종가 · 현재가 | `/html/fund/index.htm?o=nw` | 이전 값 유지 |
| 시장 · 업종 · 종목코드 · 총공모주식수 · 상장 후 주식수 · 환불일 · 상장일 · 구주매출 · 유통가능물량 · 증권사별 인수 물량 | 종목 상세 `/html/fund/?o=v&no=…` — 앞으로 일정이 있거나 최근 2주인 종목을 먼저, 남는 자리(최대 40곳)로 반년 안 못 읽은 종목을 채운다. 글 전체에서 찾는 값(구주매출·유통가능·인수 물량)은 말이 안 되면 버린다 | 이전 값 유지 |

상세 페이지의 수요예측일·기관경쟁률·의무보유확약·확정공모가·공모금액·청약경쟁률은 목록 표에 값이 없을 때만 빈칸을 메운다.
수요예측이 끝났는데 결과가 없거나 청약 예정 종목의 수요예측일을 모르면 다음 실행에서 상세 페이지를 다시 읽는다.

표 열은 순서가 아니라 **머리글 글자**로 찾는다(`SCHEDULE_COLS` 등). 38 이 표 모양을 바꿔 청약 일정 표를
5종목 넘게 읽지 못하면 빌드가 실패하고 기존 파일을 지킨다 — 그럴 때는 머리글 이름표를 고치면 된다.
400일이 지난 종목은 파일에서 뺀다.

### `ipo.json` 필드

`id`(38 번호) `name` `market`(KOSPI/KOSDAQ/KONEX) `sector` `code` `uw`(주간사 목록) `uw_alloc`([[증권사, 인수 주식 수], …])
`band_lo` `band_hi` `price`(확정 공모가) `amount`(억원) `shares` `post_shares` `old_shares` `float_pct`
`fc_start` `fc_end` `inst_comp` `lockup`(%) `sub_start` `sub_end` `sub_comp` `refund`
`list_date` `open` `close1` `cur` `spac`. 날짜는 `YYYY-MM-DD`, 모르는 값은 키가 없다.

## 개발

```sh
python ipo/build.py                      # 네트워크에서 모아 data/ipo.json 저장
python ipo/build.py --html-dir /tmp/38   # 받아 둔 HTML(k.html, r1.html, nw.html, v-<no>.html)로
python ipo/validate.py                   # 파일 검사
python -m unittest discover -s ipo/tests # 파서 테스트(네트워크 없음)
node --test ipo/tests/score.test.js       # 점수 규칙 테스트
```

`.github/workflows/ipo-tests.yml` 이 `ipo/` 를 바꾸는 PR 마다 위 테스트와 JS 문법 검사를 돌린다.

점수 기준은 공모주 블로그·커뮤니티에서 흔히 쓰는 경험칙(기관경쟁률 1,000:1, 유통물량 30% 미만, 밴드 상단 초과 등)을 옮긴 것이고,
'판정별 성적' 표로 실제 데이터에 맞는지 계속 확인한다. 일정과 숫자는 늦거나 틀릴 수 있다. 청약 전에는 증권사 공지와 DART 투자설명서를 확인할 것. 투자 권유가 아니다.
