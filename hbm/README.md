# HBM 해부

GPU 옆에 붙는 쌓인 메모리(HBM)를 3D 로 뜯어 보는 페이지. 슬라이더를 끌면 층이 뜨고,
조각을 짚으면 그게 무엇을 하는지 나온다.

- 배포: https://richroro.github.io/hbm/
- 소스: `index.html`(화면·조작) + `assets/hbm.js`(장면)
- 공용: `/assets/scene-kit.js`(환경광·블룸·배경) + `/assets/three.min.js`

## 숫자에 대하여

여기 실린 규격값은 **JEDEC 표준 기준**이다. 인터페이스 폭·핀당 속도·스택당 대역폭·최대 적층·용량이
그에 해당한다. **제조사별 실제 출하 제품, 점유율, 가격, 수주처럼 움직이는 숫자는 싣지 않았다** —
확인할 수 없는 건 쓰지 않는다는 이 저장소의 원칙을 그대로 따랐다.
설명 문구도 구조와 원리에 한정했고, 아직 굳지 않은 것("하이브리드 본딩이 논의된다")은 그렇게 적었다.

## 무엇을 코드로 만드나

에셋이 없다. 상자와 원기둥과 구를 깎아 쌓고, 표면 무늬는 캔버스에 그려서 입힌다.

| 부품 | 만드는 법 |
| --- | --- |
| 패키지 기판 · BGA 볼 | 상자 + 구 인스턴스 266 개 |
| 실리콘 인터포저 · C4 범프 | 얇은 상자 + 구 인스턴스 432 개 |
| GPU 다이 | 상자. 윗면만 '배치도' 무늬를 캔버스로 그려 입힌다 |
| 베이스 다이 + DRAM 적층 | 상자 8~16 장. 세대를 바꾸면 장수가 바뀐다 |
| TSV | 원기둥 인스턴스. 층과 층 사이를 잇고, **분해하면 늘어난다** |
| 마이크로범프 | 구 인스턴스. 위쪽 다이 바닥에 붙어 같이 움직인다 |
| 인터포저 배선 | 리본 56~112 개를 한 덩이(지오메트리 1 개)로 묶고, 셰이더로 신호를 흘린다 |

상자는 면마다 재질을 따로 줄 수 있다(`+x, −x, +y, −y, +z, −z` 순서). 윗면에만 무늬를 입히고
옆면은 민 실리콘으로 둬야 다이처럼 보인다.

## 분해

슬라이더 값 `e` 하나로 전부 움직인다. 층마다 올라가는 양이 다르고, 위로 갈수록 더 벌어진다.

```js
interposer.y = 1.45 * e;
gpu.y = stack.y = 2.85 * e;
die[i].y = baseTop + gap + i * (h + gap) + e * (i + 1) * 0.55;   // 위층일수록 더 뜬다
```

TSV 는 층 사이를 잇는 기둥이라 **벌어진 만큼 길어져야 한다**. 원기둥을 밑면 기준으로 만들어 두고
(`translate(0, 0.5, 0)`) 아래층 윗면에 세운 뒤 `scale.y` 를 간격만큼 준다. 범프는 위쪽 다이 바닥에
붙여 둬서, 층이 뜨면 범프도 같이 매달려 올라간다.

## 배선에 신호 흘리기

리본마다 `aSeed` 를 주고, 셰이더에서 `fract(uv.x − time·speed + seed)` 로 덩어리 하나를 만들어 흘린다.
리본 수십 개가 한 지오메트리라 드로우 콜은 1 이다.

```glsl
float p = fract(vUv.x - uTime * uSpeed + vSeed);
float pulse = smoothstep(0.0, 0.05, p) * (1.0 - smoothstep(0.05, 0.3, p));
```

세대를 HBM4 로 바꾸면 리본이 두 배가 된다(1,024 → 2,048 비트). 폭으로 번다는 말을 글 대신 굵기로 보여 준다.

## 해설

다섯 걸음. 각 걸음이 카메라 각도·거리, 분해 정도, 강조할 부품, 신호 속도를 한꺼번에 정한다.

1. 왜 옆에 붙이나 — 거리
2. 1,024개의 길 — 폭으로 버는 대역폭
3. 왜 쌓나 — 넓히는 대신 올리기
4. 층을 잇는 기둥 — TSV
5. 남는 문제는 열

| 드래그 / 한 손가락 | 시점 회전 |

| `R` · `L` | 시점 되돌리기 · 이름표 접기 |
