# 동네 특파원 — 나가 있는 사람이 전하는 현장

놀이공간·맛집·카페처럼 **직접 가 봐야 아는 것**을, 지금 거기 있는 사람이 한 줄로 남기고
링크로 돌리는 게시판. 서버도 계정도 없다.

- 배포: https://richroro.github.io/correspondent/
- 소스: `index.html` 한 파일 (외부 스크립트·빌드 없음, 구글 폰트만 링크)

## 이 페이지가 잡으려는 것

네이버 지도에도 카카오맵에도 있는 정보는 여기 없다. 여기 있는 건 **지금 거기가 어떤지**다.
웨이팅 30분, 주차 만석, 그늘막 자리는 벌써 찼음 — 세 시간 뒤면 아무 쓸모가 없어지는 것들.

그래서 리포트 하나를 두 덩이로 갈라 놓았다.

| | 무엇 | 다루는 법 |
| --- | --- | --- |
| **속보** | 웨이팅 · 사람 · 주차 | 시간과 함께 흐려진다. 하루가 지나면 접는다 |
| **기록** | 별점 · 태그 · 메모 | 흐려지지 않는다. 두 달 뒤에도 그대로 |

같은 카드 안에서 한쪽만 늙는다. "대기 없음"이 회색으로 죽어 있고 그 위에 **4시간 전 상황**이라고
적혀 있으면, 그건 지금 이야기가 아니라는 뜻이다.

```
0~10분    지금            시간축의 점이 주황으로 찬다
10분~1시간 조금 전
1~3시간   N시간 전 상황    점이 청록
3~12시간  N시간 전 상황    흐려짐(48%) · 점이 빈 동그라미
12~24시간 N시간 전 상황    더 흐려짐
24시간~   접힘            "어제 현장 정보 — 펼치기"
```

별점·메모·태그는 이 표와 상관없이 늘 또렷하다.

속보에는 시간축이 하나 흐른다. 카드는 **지금 / 오늘 / 어제 / 그 전** 으로 묶이고
(오늘·어제는 달력 기준이라 "5시간 전"이 어제가 되기도 한다), 왼쪽 축의 점 색이 위 표를 따른다.
칩 줄 끝에는 **3시간 창이 얼마나 남았는지** 보여 주는 38px 짜리 게이지가 붙는다 —
92% 에서 시작해 0 을 향해 비어 가고, 15% 밑으로 내려가면 회색으로 죽는다.

## 리포트가 오가는 길

서버가 없으므로 **사람이 옮긴다.** 카톡을 이미 쓰고 있으니 그 위에 얹었다.

```
① 특파원이 현장에서 리포트를 쓴다
② 앱이 카톡에 붙여 넣을 글 한 덩이를 만들어 준다
③ 단톡방에 붙여 넣는다
④ 링크를 누른 사람의 보드에 그 리포트가 더해진다
```

②에서 만들어지는 글은 이렇게 생겼다. **링크를 누르지 않아도 읽힌다**는 게 중요하다 —
대부분은 링크를 안 누르고 글만 읽고 지나간다.

```
📡 [맛집] 만안 손칼국수 · 안양 안양동
대기 10분 · 붐빔 · 주차 보통  (9. 20. 오후 12:31 기준)
“12시 반인데 열 명쯤 서 있고 회전은 빠릅니다.”
★★★★★  #포장가능 #유아의자
— 준호 특파원
받기 → https://richroro.github.io/correspondent/#r=2S1XSy2ouLE…
```

리포트 내용 전체가 저 `#r=` 뒤에 실려 있다. 해시는 서버로 전송되지 않으므로 깃허브 페이지스도
이 내용을 보지 못한다.

### 싣는 방법

필드를 위치로 눌러 담고(키 이름을 빼고), 브라우저 내장 `CompressionStream("deflate-raw")` 로 압축한 뒤
base64url 로 적는다. 라이브러리를 쓰지 않는다.

```
["k3f9a1c2", 1758338400, "준호", "food", "만안 손칼국수", "안양 안양동", 10, 2, 1, 5, "12시 반인데…", "포장가능,유아의자"]
  ↓ JSON → deflate-raw → base64url
"2" + "S1XSy2ouLEnMS83RS87PLShKLS5OzUnNKxFSslLwyU9MUdDwLy0pKC1RCM5ILE…"
```

앞 한 글자가 형식이다 — `2` 는 압축, `1` 은 날것(압축을 못 쓰는 브라우저용). 한 건이면 **220자 안팎**,
30건 묶음이면 1,400자쯤 된다. 묶음은 1,600자를 넘지 않게 최근 것부터 담고 넘치면 오래된 것을 뺀다.
카톡이 긴 링크를 중간에 끊어 버리기 때문이다.

### 같은 걸 두 번 받으면

리포트마다 붙은 8자리 id 로 걸러낸다. 같은 링크를 세 번 눌러도, A 가 준 걸 B 가 다시 전달해도
한 건만 남는다. 화면에는 `0건을 받았습니다. 1건은 이미 갖고 있어서 건너뛰었습니다.` 라고 적힌다.

## 지금 갈 만한 곳

속보 탭 맨 위에 세 곳을 세워 둔다. **3시간 안쪽 리포트만** 본다 — 그 밖의 것으로 "지금"을 말할 수 없다.

```
점수 = 여유도 × 신선도
여유도 = 대기·사람·주차 가운데 아는 것만 평균 (없으면 0.5)
         바로입장·한산·주차넉넉 1.0 / 보통 0.55 / 붐빔·만석 0.2 / 터짐·주차불가 0
         주차는 0.8을 곱하고 0.2를 더해 덜 결정적으로 친다
신선도 = 0.5 ^ (지난 시간 / 3시간)
```

여유도가 0.5 미만이면 아예 올리지 않는다. 다 붐비면 **"지금은 다들 붐빈다고 합니다"** 라고 말하지,
그중 제일 덜 붐비는 곳을 추천하지 않는다. 3시간 안쪽 리포트가 하나도 없으면 아무 말도 하지 않는다.

## 특파원 순서

**많이 쓴 순이 아니라 최근에 보낸 순이다.** 리포트 수로 세우면 지난달에 많이 쓴 사람이 맨 위에
눌러앉는다. 지금 물어볼 수 있는 사람이 위에 있어야 쓸모가 있으므로, 3시간 안에 소식을 보낸 사람을
**지금 나가 있는 특파원**으로 따로 묶고 그 안에서 최근순으로 세운다. 줄마다 마지막으로 어디서
보냈는지, 주로 어느 동네·어느 분야를 다니는지가 붙는다.

장소 줄에는 다녀간 특파원의 얼굴을 겹쳐 놓는다. **한 사람이 한 번 본 곳과 세 사람이 각자 본 곳은
무게가 다르다.**

## 장소 묶기와 엇갈림

같은 곳에 대한 리포트를 모아 한 줄로 만든다. 묶음 열쇠는 **띄어쓰기를 무시한 장소 이름 + 동네의 마지막 토막**이다.

```
"별빛 키즈카페" + "안양 안양동"  ┐
"별빛키즈카페"  + "안양동"       ├─ 한 장소
"별빛 키즈카페" + (빈칸)         ┘   ← 동네를 안 적으면 그 이름에서 가장 많이 쓰인 동네에 붙는다

"스타벅스" + "안양 안양동"  ┐
"스타벅스" + "평촌 범계동"  ┘─ 다른 장소
```

**엇갈리면 숨기지 않고 보여 준다.** 최근 3시간 안에 서로 다른 특파원이 같은 항목을 다르게 봤으면
그대로 적는다 — `엇갈립니다 · 사람 — 한산(민지 · 20분 전) / 붐빔(준호 · 1시간 전)`.
둘 중 하나를 고르지 않는다. 같은 사람이 시간차를 두고 다르게 쓴 것은 엇갈림이 아니라 상황이 바뀐 것이므로 세지 않는다.

## 색

색이 뜻하는 것은 **하나뿐이다 — 지금 거기가 여유로운가.** 분야(놀이공간·맛집…)에는 색을 주지 않았다.
분야까지 색으로 나누면 "붐빔"의 주황과 "맛집"의 주황이 같은 화면에서 싸운다.

혼잡 4단계는 글자색이 아니라 **칠의 농도**로 단계를 만든다. 글자색으로 4단계를 만들려면
네 색이 모두 본문만큼 진해야 하는데, 그러면 서로 구별이 안 된다. 실제로 처음엔 그렇게 짰다가
검사에서 걸렸다 — `#B03A0B`(붐빔)와 `#B02525`(터짐)의 정상 시야 ΔE 가 **4.2** 로, 색각 이상이 아니어도
구별이 안 되는 값이었다.

| 단계 | 밝은 모드 칠 / 글자 | 지각 명도 | 글자 대비 |
| --- | --- | --- | --- |
| 여유 | `#DCEFE4` / `#185F3E` | — (별도 색상) | 6.38 |
| 보통 | `#FBEAD1` / `#7A4600` | 0.944 | 6.58 |
| 붐빔 | `#F3BE8A` / `#6B3300` | 0.837 | 5.98 |
| 터짐 | `#A83812` / `#FFFFFF` | 0.499 | 6.48 |

명도가 단조롭게 내려가므로 **흑백으로 찍어도 단계가 보인다.** 어두운 모드는 밝은 모드를 뒤집지 않고
같은 원리로 따로 잡았다(0.303 → 0.403 → 0.617 로 올라간다). 모든 칸이 WCAG 4.5:1 을 넘는다.

그리고 색만으로 읽게 두지 않는다 — 칩에는 늘 "붐빔", "주차 만석" 같은 글자가 같이 있다.

## 예시 데이터

처음 열면 **가상의 리포트 8건**이 떠 있다. 전부 지어낸 곳이고, 카드마다 `예시` 딱지가 붙고,
띠에도 예시라고 적힌다. 직접 한 건을 쓰거나 링크로 한 건을 받는 순간 사라지고 다시 오지 않는다.

예시는 **저장되지 않는다.** 화면에 그릴 때 그때그때 만들어지므로 공유 링크에도 백업 파일에도 섞이지 않는다.
시각은 "지금으로부터 14분 전" 식으로 잡아서, 언제 열어도 신선도 단계가 전부 보이게 해 두었다.

## 밖에서 들어오는 것

링크에 실린 내용은 **남이 쓴 것**이다. 화면에 들어가는 모든 값을 이스케이프하고,
읽어 들이는 길목 하나(`sane()`)를 정해 거기서 전부 깎는다.

| | |
| --- | --- |
| 시각 | 2020년 이전이거나 하루 넘게 미래면 버린다 |
| 장소 | 비었으면 리포트 자체를 버린다. 40자로 자른다 |
| 이름·동네·메모 | 20 / 30 / 200자로 자르고 제어문자와 줄바꿈을 턴다 |
| 분야 | 아는 다섯 가지가 아니면 `그 밖에` |
| 대기·사람·주차 | 정해진 값이 아니면 `모름` |
| 별점 | 0~5로 깎는다 |
| 태그 | 12자 × 6개로 자르고 중복을 없앤다 |
| id | 영숫자 24자가 아니면 새로 발급 |
| 한 번에 | 400건 · 푼 크기 500KB · 코드 4만 자까지 |

## 저장

`localStorage` 의 `tpw.v1` 한 칸에 전부 들어간다. 브라우저 기록을 지우면 같이 사라지므로
**주고받기 → 파일로 저장**을 둬서 JSON 으로 빼 둘 수 있게 했다. 다시 읽을 때도 같은 길목을 지난다.

저장이 실패하면(용량 초과) 조용히 넘어가지 않고 `저장 공간이 부족합니다` 라고 알린다.

## 검증

헤드리스 크로미움(Playwright)에서 85개 항목을 확인했다.

- 신선도 4단계가 실제 카드 클래스로 나타나는지(14분/95분/260분/2600분 전)
- 하루 지난 속보가 `<details>` 로 접히는지
- 쓰기 → 공유글 생성 → **다른 브라우저 프로필에서 링크로 받기** → 내용 일치
- 같은 링크를 두 번 받으면 중복으로 건너뛰는지, 잘린 링크·링크 없는 글에 뭐라고 답하는지
- 90건 묶음이 1,600자 제한에 맞게 50건으로 잘리고, 그 50건이 그대로 복원되는지
- 동네 표기가 달라도("안양 안양동" / "안양동" / 빈칸) 한 장소로 묶이는지, 동네가 다르면 갈라지는지
- 엇갈림 판정 — 다른 사람이면 잡고, 같은 사람이 시간차로 쓴 건 안 잡는지
- 스크립트를 넣은 메모가 이스케이프되는지, 망가진 데이터 5건 중 1건만 살아남고 나머지는 깎이는지
- 모바일 375px 가로 스크롤 0px, 시트 안 모든 조작 요소 30px 이상, 어두운 모드
- 시간대 묶음(지금 2건 / 오늘 4건 / 어제 1건 / 그 전 1건)과 게이지가 92→79→47→6→2% 로 비어 가는지
- `hidden` 속성이 실제로 감추는지 — `display:flex` 를 준 요소는 작성자 규칙이 브라우저 기본을 이겨서
  `hidden` 만으로는 안 사라진다(`[hidden]{display:none !important}` 로 막았다)

## 공용 보드 (선택)

여기까지가 서버 없이 도는 앱이다. 같은 동네 사람들이 **같은 속보를 보게** 하려면
`config.js` 에 Supabase 주소를 넣는다. 비워 두면 위에 적은 대로만 돈다 — 설정법은 [SETUP.md](SETUP.md).

켜면 달라지는 것은 딱 하나다. **새로 온 사람이 빈 화면을 보지 않는다.** 나머지는 그대로다.

| | 그대로인 것 | 더해지는 것 |
| --- | --- | --- |
| 저장 | 로컬이 먼저. 쓰면 바로 내 보드에 | 올리기는 그 다음. 못 올렸으면 다음 기회에 |
| 링크 공유 | 그대로 동작 | — |
| 읽기 | — | 로그인 없이 동네 속보 |
| 쓰기 | 로그인 없이도 내 보드에 | 로그인하면 동네에 올라감 |
| 신고 | 없음 | 세 사람이 신고하면 가려짐 |

규칙 하나가 이 설계를 지탱한다. **링크로 받은 리포트는 서버에 올리지 않는다.**
남이 쓴 글을 내 계정으로 올리면 작성자가 세탁된다. 내가 쓴 것(`mine`)만 올라가고,
그 표시는 서버가 알려 주는 값으로만 붙는다 — 브라우저를 비우거나 기기를 바꿔도 내 글은 내 글이다.

서버는 클라이언트를 믿지 않는다. `author` 와 `by_name` 을 토큰 주인으로 덮어쓰고,
시각이 미래면 당기고, 리포트 수정은 권한 자체를 주지 않는다. 열두 가지 공격을 실제
Postgres 16 에 돌려서 확인했다 — 표는 [SETUP.md](SETUP.md) 에 있다.

**위치(GPS)는 받지 않는다.** 동네는 사람이 고른다. 좌표를 받는 순간 위치기반서비스사업
신고 대상이 되는데, 그 줄은 필요해질 때 넘는 게 맞다.

## 한계

- **사실 확인을 하지 않는다.** 누가 뭘 썼는지 확인할 방법이 없다. 이름도 그냥 적는 칸이다.
- **모두가 같은 화면을 보지 않는다.** 링크를 받은 사람만 그 리포트를 갖는다. 늦게 들어온 사람은
  누군가 묶음 링크를 건네줘야 따라잡는다.
- 지우기는 **내 브라우저에서만** 일어난다. 이미 퍼진 링크는 회수되지 않는다.
- 위치·지도·사진이 없다. 장소는 사람이 적은 이름으로만 구분한다.
- 리포트를 고칠 수 없다. 틀렸으면 새로 쓰는 쪽이 맞다 — 그게 현장 기록이다.
