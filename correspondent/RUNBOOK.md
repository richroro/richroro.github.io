# 운영 매뉴얼

공용 보드를 켠 뒤 운영자가 하는 일. 운영 화면은 `https://richroro.github.io/correspondent/admin.html`
(운영자 넣는 법은 [SETUP.md](SETUP.md) 4단계). 조항 번호는 [이용약관의 운영정책](terms.html#policy)을 따른다.

> 법률 자문이 아니다. 아래 기한과 절차는 운영을 시작하기 전에 전문가와 한 번 맞춰 본다.

## 매일 — 5분

**운영 화면 → 대기열.** 올라오는 것은 네 가지다.

| 딱지 | 뜻 | 보통 하는 일 |
| --- | --- | --- |
| 신고로 가려짐 | 세 사람이 신고해서 저절로 가려졌다 | 글을 읽고 정한다 |
| 신고됨 · 아직 보임 | 신고가 한두 건 | 명백하면 먼저 처리, 아니면 두고 본다 |
| 처리 뒤 새 신고 | 되살렸거나 가린 뒤 다른 사람이 또 신고했다 | 새 신고 사유만 본다 |
| 임시조치 30일 끝남 | 권리침해 임시조치 기간이 끝났다 | 아래 "권리침해 신고" 5번 |

판단 기준은 운영정책 1조다. 헷갈리면 이렇게 읽는다.

| 글에 있는 것 | 처리 |
| --- | --- |
| 가게·장소에 대한 현장 정보(붐빈다, 불친절했다, 맛없다) | **문제없음** — 불리한 후기는 권리침해가 아니다 |
| 특정인의 실명·얼굴 묘사·연락처·차량번호 | **지우기** (사생활) |
| 전화번호·할인 문구·가게 쪽이 쓴 홍보 | **지우기** (광고), 반복이면 정지 |
| 욕설·혐오 표현 | **지우기**, 반복이면 정지 |
| 사실인지 알 수 없는 주장("직원이 험담한다") | **가린 채 두기**, 권리침해 신고가 오면 임시조치 |
| 같은 사람이 같은 글에 매번 신고 | 신고한 사람 칸을 본다. 떼 신고면 **문제없음** — 기각된 신고는 다시 못 한다 |

**문제없음**은 되살리면서 걸려 있던 신고를 기각한다. 기각된 신고는 수에 안 들지만 남아 있어서,
같은 사람이 같은 글을 다시 신고하지 못한다. **가린 채 두기**는 이후 신고가 더 와도 풀리지 않는다.

지우기와 정지는 **사유를 적어야 눌린다.** 이의 신청이 오면 그 사유로 답한다.

## 권리침해 신고 — 임시조치

명예훼손·사생활 침해를 주장하며 글을 내려 달라는 요청이다(정보통신망법 44조의2). 앱의 신고 단추가 아니라
**메일**로 온다(운영정책 3조에 받는 주소가 있다).

1. **받는다.** 요청하는 사람의 이름과 연락처, 어느 글인지(장소·대략의 시각), 무엇이 침해인지 확인한다.
   빠졌으면 되묻는다. 당사자나 대리인이 아니면 일반 신고로 다룬다.
2. **찾는다.** 운영 화면 → 찾기에서 장소 이름으로 찾는다. 시각은 카드의 `9/24 22:36` 을 대조한다.
3. **임시조치 30일.** 메모에 `누가 · 언제 받은 요청 · 무엇을 주장` 을 적는다(비우면 안 걸린다).
   글은 모두에게서 가려지고, 쓴 사람에게는 "신고로 가려짐" 딱지와 함께 보인다.
4. **알린다.** 요청한 사람에게 조치했다고 답한다. 쓴 사람에게는 앱이 딱지로 알린다 —
   재게시를 요청하려면 운영정책 5조의 메일로 하라고 운영정책에 적혀 있다.
5. **30일 뒤.** 대기열 맨 위에 "임시조치 30일 끝남" 으로 돌아온다.
   - 쓴 사람이 재게시를 요청했고 주장에 근거가 있으면 → **문제없음**(되살리기)
   - 요청이 없었거나 침해가 분명하면 → **지우기**(사유: `임시조치 기간 중 재게시 요청 없음` 등)
   - 법원·수사기관의 판단을 기다리는 중이면 → 다시 **임시조치** (메모에 사건 번호)

## 정지와 이의 신청

기준은 운영정책 4조(1회 가림·지우기 → 2회 7일 → 3회 30일 → 그 뒤 영구, 광고·도배는 한 단계 빨리).
**작성자 보기**에 그 사람의 가려진 글 수, 처리 기록, 기각된 신고 수가 있다.

- 정지되면 글쓰기와 신고가 막힌다. 앱은 쓴 사람에게 "글쓰기가 정지된 상태"라고 알리고, 쓴 글은 기기에 남는다.
  풀리면 그 글이 올라간다 — 정지 중에 쓴 것이 풀리는 순간 올라가는 게 싫으면 풀기 전에 이야기한다.
- **이의 신청**은 메일로 온다. 앱의 공용 보드 창에 계정 번호가 보이므로 그 번호를 달라고 한다.
  찾기에 계정 번호를 넣으면 글이 없는 사람도 나온다. 7일 안에 답한다(운영정책 5조).
- 운영자는 정지할 수 없다. 운영자를 빼려면 SQL 편집기에서 `delete from admins where id = '…';`

## 개인정보 요청 — 열람·정정·삭제·처리정지

앱이 스스로 할 수 있는 건 앱에서 하게 한다.

| 요청 | 어디서 |
| --- | --- |
| 내 글 지우기 | 카드의 ✕ (서버에서도 지워진다) |
| 이름 바꾸기 | 특파원 탭 |
| 전부 지우기(탈퇴) | 🏘 공용 보드 → 계정 삭제 |
| 내가 가진 것 보기·가져가기 | 주고받기 → 파일로 저장 |

앱으로 안 되는 요청(탈퇴를 못 하는 상황, 서버에 무엇이 있는지 알려 달라 등)은 **10일 안에** 답한다
(개인정보보호법 35~37조와 그 시행령). 서버에 그 사람에 대해 있는 것은 이게 전부다:

```sql
-- '<번호>' 는 계정 번호
select id, name, hood_code, banned_until, created_at from correspondents where id = '<번호>';
select id, t, place, area, note, hidden, flag_count from reports where author = '<번호>' order by t desc;
select report_id, reason, dismissed, created_at from flags where reporter = '<번호>';
select at, action, report_id, note from mod_log where target = '<번호>' order by at desc;   -- 처리 기록 (1년)
```

처리 기록(`mod_log`)은 탈퇴해도 1년 남는다 — 처리방침 4조에 적힌 대로다. 지워 달라는 요청이 오면
진행 중인 분쟁이 없는지 보고 정한다.

## 사고 — 유출이 의심될 때

로그인 계정, 이메일, 특파원 이름, 리포트가 있는 DB 다. 새어 나갔다고 의심되면:

1. **막는다.** Supabase → Settings → API 에서 키를 새로 만든다(`service_role` 이 샜다면 반드시).
   anon 키를 바꾸면 `config.js` 도 바꿔 배포한다. Authentication → Users 에서 모든 세션을 끊을 수 있다.
2. **본다.** Supabase 로그(API·Auth·Postgres)에서 언제부터 무엇이 나갔는지 확인한다.
3. **72시간 안에 알린다.** 유출을 안 때부터 72시간 안에 해당 이용자에게 알리고,
   1천 명 이상이거나 외부의 불법 접근이면 개인정보보호위원회(또는 한국인터넷진흥원)에 신고한다
   (개인정보보호법 34조). 알릴 내용: 무엇이, 언제, 어떻게 새었는지, 이용자가 할 일, 연락처.
4. **기록한다.** 무엇을 언제 했는지 남긴다.

## 매주 — 비용과 용량

Supabase → Reports/Usage.

- **보내는 양(egress)** — 앱은 열려 있는 동안 3분마다 새로 들어온 글만 받고, 최근 200건 전체 대조는
  앱을 열 때와 30분마다 한다. 한 시간 열어 둔 폰 하나가 100KB 안팎이다. 갑자기 늘면 어느 동네에서 도배가 있는지
  운영 화면 → 숫자에서 본다.
- **DB 크기** — 1년 지난 리포트와 처리 기록은 매일 지워진다(`retention.sql`, 13:10 KST).
  `select jobname, last_run_status from cron.job_run_details order by start_time desc limit 5;` 로 돌았는지 본다.
- **새 동네 열기** — 숫자 탭의 "동네 (최근 7일)" 에서 한 동네에 쓰는 사람이 스무 명쯤 모이면 옆 동네를 연다.
  사람이 적은 동네를 먼저 열면 들어온 사람이 빈 화면을 본다.

## 폰 알림이 안 온다

켠 사람만 받는다(지켜보는 곳 상자의 **폰 알림 켜짐**). 차례로 본다.

1. **그 사람이 받을 조건인가** — 같은 동네, 그 장소를 지켜보는 중, 자기가 쓴 글이 아님, 그 장소로 30분 안에 받은 적 없음,
   쓴 지 세 시간 안 된 글. 아이폰이면 홈 화면에 추가한 앱에서 켰는지.
2. **구독이 있나** — `select owner, hood_code, places, fails, created_at from push_subs where owner = '<계정 번호>';`
   없으면 앱에서 다시 켜게 한다. `fails` 가 쌓였으면 그 기기의 푸시 서비스가 거절하고 있다(다섯 번이면 지워진다).
3. **함수가 불렸나** — Edge Functions → notify → Logs. 아무것도 없으면 Database → Webhooks 의 설정(표 `reports`, Insert,
   머리 `x-tpw-secret`)을 본다. `403` 이면 머리 값과 `PUSH_WEBHOOK_SECRET` 이 다르다. `500 VAPID 설정이 비었습니다` 면 비밀을 안 넣었다.
4. **보냈는데 안 울린다** — 로그의 `{"sent":1}` 까지 됐으면 그 다음은 푸시 서비스와 기기 몫이다(방해 금지, 배터리 절약).

VAPID 비공개 키가 샜으면 `tools/vapid-keys.mjs` 로 새 쌍을 만들어 `config.js` 와 비밀을 바꾼다.
그러면 모든 구독이 쓸모없어진다 — `delete from push_subs;` 하고, 사람들이 앱에서 다시 켜야 한다.

## 장애

- 서버가 멈춰도 **앱은 돈다.** 리포트는 기기에 먼저 쌓이고, 링크 공유도 서버를 안 거친다. 못 올린 글은 연결되면 올라간다.
- Supabase 상태: https://status.supabase.com
- 오래 멈추면 알린다 — 앱 안에 공지 칸은 없으니, 쓰는 사람들이 모인 단톡방이 가장 빠르다.
