# 업무 자동화 셀프 브랜딩

목표는 하나다. **"반복 업무를 맡기면 알아서 돌아가게 만들어 주는 사람"으로 기억되기.**
그러려면 주장보다 증거가 먼저다. 이 저장소에는 사람이 손대지 않아도 매일 도는 자동화가 이미 있으니, 그걸 보여 준다.

## 1. 증거부터 모은다 (매번 새로)

글을 쓰기 전에 저장소에서 지금 사실인 것만 모은다. 숫자는 여기서 나온 것만 쓴다.

```bash
# 돌고 있는 자동화와 일정
grep -H -E "^name:|cron:" .github/workflows/update-*.yml
# 사람 손 없이 쌓인 자동 커밋 수, 최근 것
git log --oneline | grep -c "자동"   # 얕은 clone이면 적게 나온다: 먼저 git fetch --unshallow
git log --format='%ad %s' --date=format:'%Y-%m-%d %H:%M' | grep "자동" | head -5
# 각 프로젝트가 무엇인지
head -6 */README.md
# 서비스·가격·약속 (랜딩 페이지)
sed 's/<[^>]*>/ /g' index.html | tr -s ' \n' | grep -oE '[0-9]+만원~ / 건|착수금[^.]{0,30}|[0-9]~[0-9]주[^.]{0,20}'
```

`references/proof.md`에 사례별로 어떤 이야기로 쓸 수 있는지 정리해 두었다. 거기 적힌 일정·숫자가 위 명령 결과와 다르면 **명령 결과가 맞다.**

지키는 것:
- 고객이 있었던 것처럼 쓰지 않는다. 지금 사례는 **내가 내 일을 자동화한 것**이다. "직접 만들어 매일 돌리고 있다"가 가장 강한 문장이다.
- 절약 시간·효과는 계산 근거를 같이 적는다 (예: "손으로 하면 하루 30분 × 22일").
- 투자 관련 페이지(공모주·종목)는 **데이터 수집 자동화 사례**로만 쓴다. 종목 추천처럼 읽히는 문장은 넣지 않는다.
- `couple-cards`처럼 `noindex`인 페이지는 사례로 쓰지 않는다.

## 2. 포지셔닝 한 줄

모든 채널의 글이 같은 사람을 가리키게 한다. 기본값:

> **반복 업무를 코드와 AI에게 넘겨 드립니다.** 엑셀 복붙, 매일 사이트 확인, 정해진 시간 보고 — 한 번 만들면 매일 혼자 돕니다.

사용자가 이름·닉네임·말투를 정해 주면 그걸 쓴다. 정해 주지 않았으면 이름은 지어내지 않고 `Cadence`와 `https://richroro.github.io/`만 쓴다.

## 3. 원 소스 멀티 유즈

사례 하나로 한 주를 채운다. 사용자가 사례를 고르지 않으면 `references/proof.md`의 추천 순서대로 아직 안 쓴 것을 고른다.

| 채널 | 이 사례로 만드는 것 | 분량 |
|---|---|---|
| 네이버 블로그 | 사례 글 1편 (문제 → 만든 것 → 지금 어떻게 도는지 → 이런 분께 필요) | 1,500~2,500자 |
| 카페 | 정보 글 1편 또는 질문 답변 2~3개 (홍보 아닌 도움) | 500~1,200자 |
| 스레드 | 짧은 글 3~5개 (시리즈 "자동화 일지 #n") | 글당 500자 이하 |
| 채용·외주 사이트 | 프로필/포트폴리오 항목 1개 추가 또는 갱신 | 사이트 양식에 맞춤 |

채널별 형식·주의사항은 `references/channels.md`를 따른다. 반드시 읽고 쓴다.

`automation-leads` 스킬을 돌린 적이 있으면 그 결과에서 **자주 나온 고민 문장**을 글 주제로 쓴다. 사람들이 실제로 검색하는 말이라 블로그 제목·카페 답변에 그대로 먹힌다. (개인 글을 인용하거나 링크하지는 않는다.)

## 4. 결과물

스크래치패드(없으면 저장소 밖 작업 폴더)에 `branding-YYYY-MM-DD/` 폴더를 만들고:

```
00-plan.md        이번 주 발행 계획 (요일·채널·파일·올릴 시간)
blog.md           제목 후보 3개 + 본문 + 태그 10개 + 대표 이미지로 쓸 화면 제안
cafe.md           올릴 카페 성격 + 글 / 답변 초안 + 그 카페 규칙 확인할 점
threads.md        글 3~5개 (각각 글자 수 표기) + 첫 댓글에 둘 링크 문구
profile.md        크몽·숨고·위시켓·원티드·링크드인 중 요청받은 곳의 문구
```

발행 계획 기본값: 월 블로그 → 화·목·토 스레드 → 수 카페 → 금 프로필 갱신.
사용자가 공유용 페이지로 원하면 Artifact로 만들고, 아니면 파일로 둔다.

마지막 답변에는 파일 목록과 **이번 주 가장 먼저 올릴 글 하나**만 짧게 알려 준다.

## 5. 문장 원칙
- 1인칭, 존댓말, 짧은 문장. "혁신", "획기적", "AI가 다 해 드립니다" 같은 말은 쓰지 않는다.
- 첫 줄은 독자의 고통이다 ("매일 아침 같은 사이트 5개 여는 분"). 내 소개는 맨 뒤.
- 화면을 보여 준다: 실제 페이지 링크, 자동 커밋 기록, 몇 시에 도는지.
- 끝맺음은 하나만: "무료로 진단해 드려요" + 랜딩 링크. 가격은 블로그·프로필에만, 카페·스레드 본문에는 넣지 않는다.

## 6. 지켜야 할 것
- **대신 올리지 않는다.** 글·댓글·프로필은 초안만 만든다. 올리는 건 사용자가 직접 한다. 자동 게시를 원하면 공식 API가 있는 채널(예: Threads API)만, 사용자가 따로 요청할 때 별도 작업으로 설계한다.
- 같은 글을 여러 카페에 복사해 올리는 계획을 세우지 않는다 (도배로 강퇴·저품질 위험). 카페마다 다시 쓴다.
- 후기·추천 글을 다른 사람인 척 쓰지 않는다. 가짜 고객 사례, 가짜 수치 금지.
- 결과 폴더는 공개 저장소에 커밋하지 않는다.
