# 영상 내레이션 (대본 → 자연스러운 음성 → 장면에 맞춰 합성)

캡컷의 "텍스트 음성 변환"에 대본을 붙여 넣던 작업을 대신한다.
핵심 스크립트: `scripts/narrate.py` (이 파일 옆 폴더). 모든 경로는 저장소 루트 기준
`.claude/skills/video-narration/scripts/narrate.py`.

## 0. 준비 (세션마다 한 번)

```bash
pip install -q edge-tts sherpa-onnx imageio-ffmpeg   # 온라인 음성 + 오프라인 음성 + ffmpeg
[ -f /root/.ccr/ca-bundle.crt ] && export SSL_CERT_FILE=/root/.ccr/ca-bundle.crt   # 클라우드 세션 프록시 인증서
```

시스템 `ffmpeg` 가 있으면 그걸 쓰고, 없으면 `imageio-ffmpeg` 의 것을 쓴다.

### 음성 엔진

| 엔진 | 품질 | 필요한 것 |
| --- | --- | --- |
| `edge` (기본) | Microsoft 신경망 음성. 무료인데 꽤 자연스럽다 | `speech.platform.bing.com` 접속 (웹소켓) |
| `google` | Chirp3-HD 음성이 가장 사람 같다 | `GOOGLE_TTS_API_KEY`, `texttospeech.googleapis.com` |
| `elevenlabs` | 감정 표현이 가장 좋다 | `ELEVENLABS_API_KEY`, `api.elevenlabs.io`, `--voice <voice_id>` |
| `openai` | `--style` 로 말투를 문장으로 지시 | `OPENAI_API_KEY`, `api.openai.com` |
| `supertonic` | Supertone 의 오프라인 신경망 음성(Supertonic 3). 한국어 자연스러움 좋음, CPU 로 장면당 2~3초 | 처음 한 번 `github.com` 에서 모델 약 130MB (`~/.cache/video-narration`) |

`--engine auto`(기본)는 edge → google → elevenlabs → openai → supertonic 순서로, 키가 있고 접속되는
첫 엔진을 쓴다. 중간에 한 엔진이 막히면 다음 엔진으로 넘어간다. `--voice` 를 주면 그 음성의 엔진을
먼저 쓴다 (`--voice 6` → supertonic). 음성 목록: `narrate.py --list-voices`.

클라우드 세션은 네트워크 정책 때문에 edge·openai·elevenlabs 가 막혀 있는 경우가 많다. 그럴 땐
**supertonic 이 키 없이 바로 동작**하므로 처음부터 `--engine supertonic` 을 줘도 된다.
supertonic 음성: `3` 여성·또렷(기본) · `2` 여성·차분 · `6` 남성·낮고 묵직 · `8` 남성·중저음.
목소리를 고르지 않았으면 여성 `3` 과 남성 `6` 으로 첫 장면을 만들어 들려주고 고르게 한다.

### 사람처럼 들리게 하는 처리 (supertonic 기본 켜짐, `scripts/humanize.py`)

| 처리 | 왜 |
| --- | --- |
| 숫자·기호·약어를 읽는 말로 (`3가지`→`세 가지`, `20영업일`→`이십 영업일`, `3.5%`→`삼 점 오 퍼센트`, `10월`→`시월`, `IPO`→`아이피오`, 전화번호는 묶음마다 끊어 읽기) | Supertonic 은 숫자를 그대로 주면 자주 틀린다 (실측: `3가지`→"설까지", `20영업일`→"인심영업일"). **자막에는 원래 숫자 표기가 그대로** 나간다 |
| 문장마다 따로 만들고 쉼 길이를 사람처럼 불규칙하게 (쉼표 0.2초 안팎, 마침표 0.4~0.6초, 물음표는 조금 더) | 기계가 읽으면 쉼이 늘 같아서 티가 난다 |
| 문장마다 속도를 ±3% 안에서 조금씩 다르게 | 같은 속도로 끝까지 가면 단조롭다 |
| 긴 문장 앞 쉼 끝에 작은 들숨 소리 (말소리보다 17dB 작게) | 사람은 긴 말 앞에서 숨을 쉰다 |
| 쉼 자리에 아주 작은 방 소음 (-64dBFS) | 완전한 디지털 무음은 '끊긴' 느낌이 난다 |
| 마이크 음색: 저역 정리, 따뜻함(+1.5dB 180Hz), 또렷함(+2dB 3.2kHz), 쏘는 고음 줄임, 약한 압축 (방 울림은 발음을 흐려서 뺌) | 합성 음성 특유의 '너무 깨끗한' 소리를 녹음한 목소리처럼 |
| 빨리 읽기 한도 1.12배 (supertonic) | 실측: 1.2배로 빨리 읽으면 받아쓰기 오류가 2배 넘게 는다 → 넘치면 속도 대신 대본을 줄인다 |
| 품질 단계 `SUPERTONIC_STEPS` (기본 10) | 실측에서 8·16·32 단계 발음 차이가 없어서 빠른 쪽 |

끄려면 `NARRATION_HUMANIZE=0`. 대본에 숫자를 한글로 직접 써도 된다 (그게 가장 확실하다).

**모든 엔진이 막히면** 사용자에게 막힌 호스트 이름을 알려주고, 환경 설정의 네트워크 접근에서 그
호스트를 허용하거나 API 키를 환경변수로 넣어 달라고 안내한다. 그동안은 1~2단계까지 만든 대본
파일과 `--check` 결과를 캡컷용으로 넘긴다.

## 1. 대본 파일 만들기

앞서 만든 영상/대본이 대화에 있으면 그 장면 구성을 그대로 옮긴다. 영상을 직접 만들었다면
장면 길이를 알고 있으니 **시간을 반드시 적는다** (없으면 영상 길이를 글자 수 비율로 나눈다).

아래 형식을 섞어 써도 된다.

```text
[0:00-0:04] 공모주 청약, 처음이라면 딱 세 가지만 기억하세요.
[0:04-0:09]
화면: 증권사 앱 화면          ← 화면/자막/BGM/효과음: 줄은 읽지 않는다
내레이션: 첫째, 계좌는 한 달 전에 미리 만들어 두세요.
(캘린더 확대)                 ← 괄호만 있는 줄도 읽지 않는다
## 장면 3 (5초)
둘째, 청약 증거금은 절반만 있으면 됩니다.
[6초] 마지막으로, 상장 첫날 매도 계획을 미리 세워 두세요.
```

- `[시작-끝]` (`0:04`, `4`, `4초`, `00:00:04.5` 모두 가능) · `[N초]`(앞 장면에 이어서) · `장면 N (N초)` / `장면 N (0:10-0:15)`
- 한 장면 안에 `내레이션:` 줄이 있으면 그 줄만 읽는다.
- JSON 도 된다: `{"scenes":[{"start":0,"end":4,"text":"..."}, {"duration":5,"text":"..."}]}`
- 시간 표기가 전혀 없으면 빈 줄로 장면을 나눈다.

### 자연스럽게 들리는 대본 쓰는 법 (대본을 다듬을 때 적용)

- **입말로 쓴다**: "~함", "~임" 같은 메모체 대신 "~해요/~합니다". 한 문장은 40자 안쪽.
- 문장 끝마다 마침표·물음표를 찍는다 — 쉼과 억양이 여기서 나온다. 쉼표는 숨 쉴 자리에만.
- 괄호, 화살표, 슬래시, 이모지, 해시태그는 소리 내 읽을 수 없으니 말로 풀어 쓴다
  (스크립트가 `→`, `~`, `·`, 이모지, `[BGM]` 정도는 자동으로 정리한다).
- 영어 약어는 읽는 대로: "IPO" → "아이피오" 또는 "기업공개". 헷갈리는 숫자는 한글로("1억 원" 정도는 그대로 OK).
- **분량 기준: 보통 속도 한국어 ≈ 초당 6~7음절**. 4초 장면이면 25음절 안팎.

## 2. 길이 점검 (음성 생성 전, 빠름)

```bash
python3 .claude/skills/video-narration/scripts/narrate.py 대본.txt --video 영상.mp4 --check
```

장면마다 `여유 / 딱 맞음 / 조금 빠르게 ×1.1 / 넘침 → 약 N자 줄이세요` 가 나온다.
**넘침이 있으면 속도를 올리기보다 해당 장면 대본을 줄여서 다시 쓴다** — 빨리 읽는 음성은 부자연스럽다.
사용자가 대본을 그대로 원하면 넘치게 두어도 된다(다음 장면을 밀고, 마지막이면 영상 끝 프레임을 늘린다).

## 3. 내레이션 생성·합성

```bash
python3 .claude/skills/video-narration/scripts/narrate.py 대본.txt --video 영상.mp4 --out 결과폴더 \
  [--voice ko-KR-InJoonNeural] [--music bgm.mp3]
```

하는 일:
1. 장면마다 자연 속도로 음성을 만들고 앞뒤 무음을 잘라 실제 말 길이를 잰다.
2. 창(장면 길이 − 앞 0.2초 − 뒤 0.3초)보다 길면 엔진 자체 속도 옵션으로 다시 만든다 (최대 `--max-speed` 1.2).
   엔진이 못 하는 만큼만 ffmpeg `atempo` 로 보충한다. 짧은 장면을 억지로 늘리지는 않는다.
3. 각 장면 시작 0.2초 뒤에 배치. 앞 장면이 넘치면 최소 0.25초 간격을 두고 뒤로 민다.
4. 원본 영상 소리·배경음악은 말하는 동안 자동으로 줄이고(`--no-duck` 로 끔), 전체를 -14 LUFS 로 맞춘다.
5. 내레이션이 영상보다 길면 마지막 프레임을 늘린다 (`--no-extend` 면 영상 길이에서 자른다).
   그렇지 않으면 영상은 재인코딩 없이 그대로 복사한다.

자주 쓰는 옵션: `--rate 1.05`(전체 조금 빠르게) · `--orig-volume 0`(원본 소리 제거) ·
`--music-volume 0.12` · `--lead/--tail/--gap` · `--engine google --voice ko-KR-Chirp3-HD-Kore` ·
`--engine openai --style "밝고 친근한 유튜버 톤"`.

결과 폴더:

| 파일 | 용도 |
| --- | --- |
| `narrated.mp4` | 내레이션이 들어간 완성 영상 |
| `narration.wav` | 영상 전체 길이의 내레이션 트랙 — 캡컷에서 0초에 올리면 바로 맞는다 |
| `subtitles.srt` | 문장 단위 자막 (edge 는 실제 발화 시점, 다른 엔진은 글자 수 비율) |
| `clips/scene_NN.mp3` | 장면별 음성 (supertonic 은 `.wav`) |
| `report.json` | 장면별 시작 시각·말 길이·속도·넘침 |

## 4. 확인하고 전달

- 콘솔 표와 `report.json` 에서 `⚠ 넘침` · `밀림` 장면을 확인한다. 넘친 장면은 대본을 줄인 뒤
  전체를 다시 돌린다 (뒤 장면 배치가 함께 바뀌므로 부분 재생성은 하지 않는다. 몇 초면 끝난다).
- 음성 선택이 애매하면 첫 장면만 담은 짧은 대본으로 2~3개 음성을 만들어 들려주고 고르게 한다.
- 완성본 `narrated.mp4` (필요하면 `narration.wav`, `subtitles.srt` 도) 를 사용자에게 파일로 보낸다.
  결과물은 저장소에 커밋하지 않는다 (`narration_out/` 은 .gitignore 에 있음).
