# 내 전용 영상 편집기

사용자는 편집을 전혀 모른다고 생각하고, **묻지 말고 끝까지** 한다. 막히는 것은 연결·권한 문제뿐이고, 그때만 무엇을 해야 하는지 짧게 안내한다.

경로: 스크립트 `S=.claude/skills/video-edit/scripts`, 규칙 `.claude/skills/video-edit/rules/`
작업 폴더: 저장소 루트의 `edits/<YYYYMMDD>_<영상이름>/` (`.gitignore` 에 있음 — 영상은 커밋하지 않는다)

## 0. 준비 (세션마다 한 번, 1분)

```bash
bash .claude/skills/video-edit/scripts/setup.sh
[ -f /root/.ccr/ca-bundle.crt ] && export SSL_CERT_FILE=/root/.ccr/ca-bundle.crt
```
한국어 받아쓰기·VAD 모델(GitHub 릴리스), Pretendard 글꼴(npm), 글자 인식, ffmpeg(libass 포함)를 준비한다.

그리고 **편집 전에 `rules/rulebook.md` 를 처음부터 끝까지 읽는다.** 판단(무엇을 지우고·강조하고·자료화면을 넣을지)은 전부 거기 기준을 따른다.

## A. "드라이브에 영상 올렸어, 편집해줘" — 편집 순서 (반드시 이 순서)

### ① 가져오기
```bash
python3 $S/fetch_drive.py [드라이브 링크] --out edits/<폴더>/inbox
```
- 링크를 안 줬으면 규칙집에 저장한 영상함(`rules.json` → `drive.inbox`)에서 가장 최근 영상을 받는다.
- 폴더 안 `bgm`/`음악` 폴더의 음악은 배경음으로, `ref`/`레퍼런스` 폴더의 영상은 레퍼런스로 따로 받는다.
- 영상함도 없고 링크도 없거나 접근이 막히면 → 아래 **Google 드라이브 연결** 안내를 보여주고 멈춘다.
- 사용자가 영상 파일을 직접 올렸으면(로컬 경로) 그 경로를 그대로 넣는다.

### ② 받아쓰기
```bash
python3 $S/transcribe.py edits/<폴더>/inbox/원본.mp4 --out edits/<폴더>
```
`transcript.txt` 를 읽는다: `(번호)낱말`, `*` = 삭제 추천(군말·반복·말 끊김), `⏸1.8s` = 긴 멈춤.

### ③ 교정 대본 → 편집 계획 (`edits/<폴더>/plan.json`)
규칙집 1장대로 판단해서 쓴다. **지우기만 하고, 말의 내용과 말투는 바꾸지 않는다.** `*` 추천은 참고일 뿐 — 문맥상 뜻이 있는 말이면 남긴다.

```json
{
  "delete":   [6, "7-8", 13],
  "fix":      {"2": "공모주 청약"},
  "title":    "공모주 청약, 이것만 기억하세요",
  "emphasis": [{"words": [16, 17], "text": "20영업일 제한!"}],
  "broll":    [{"from": 27, "to": 34, "url": "https://...", "card": {"kind": "news", "source": "매체", "date": "2026.10.05", "title": "확인한 기사 제목 그대로"}, "credit": "출처: 매체 (2026.10.05)"}],
  "bgm":      "edits/<폴더>/inbox/bgm/음악.mp3"
}
```
- `delete`: 교정 대본에서 뺄 낱말 번호. 범위 `"a-b"` 가능.
- `fix`: 자막 표기만 고침 (받아쓰기 오타·숫자 표기). 소리와 다른 말로 바꾸지 않는다.
- `emphasis`: 규칙집 5장 기준. `words` 는 그 순간의 낱말 번호, `text` 는 큰 강조 자막(생략하면 색·줌·효과음만).
- `title`: 인트로 제목. `bgm`: 없으면 규칙집 설정(드라이브 음악 → 합성 배경음). 배경음을 빼려면 `false`.

### ④ 자료화면 찾기 (규칙집 8장)
말한 내용 중 확인 가능한 사실마다: WebSearch → 공식 사이트·주요 기사 → WebFetch 로 실제 문구 확인 → `broll` 항목.
`url` 을 주면 캡처를 시도하고, 막히면 같은 항목의 `card` 로 대신한다 (그래서 둘 다 넣어 둔다).
**확인 못 한 제목·수치는 절대 지어내지 않는다** — 그럴 땐 자료화면을 넣지 않는다.
WebFetch·캡처가 네트워크 정책에 막히면 WebSearch 결과에 나온 제목·주소·요약만 근거로 쓰고, 매체명이 불확실하면 도메인으로 출처를 단다.

### ⑤ 렌더링
```bash
python3 $S/edit.py --video edits/<폴더>/inbox/원본.mp4 --transcript edits/<폴더>/transcript.json \
  --plan edits/<폴더>/plan.json --out edits/<폴더>/완성.mp4
```
컷 편집(점프 컷·확대) → 흐림 → 자료화면 → 자막·강조 자막·출처 → 효과음·배경음(덕킹) → -14 LUFS → mp4.
같이 나오는 것: `완성.srt`, `완성_교정대본.txt`, `work_edit/edit_report.json`.
미리 확인만 할 땐 `--fast`.

### ⑥ 자체 검수 → 고치기 (끝날 때까지 반복)
```bash
python3 $S/review.py --work edits/<폴더>/work_edit --fix --plan edits/<폴더>/plan.json --transcript edits/<폴더>/transcript.json
```
- 자동: 자막↔소리 대조, 무음·말 중간 컷·클리핑, 화면 멈춤·검은 화면, 화면 속 전화번호·이메일·주민번호·카드·계좌번호 → **자동 흐림 후 다시 렌더링**.
- **직접 눈으로**: `review_sheet_*.png` 를 Read 로 전부 연다. 이름·주소·알림창·메신저·다른 사람 얼굴·번호판·송장이 보이면
  `python3 $S/review.py grab 완성.mp4 <초> frame.png` 로 격자 화면을 열어 좌표를 읽고, `plan.json` 의 `blur` 에
  `{"start": 초, "end": 초, "box": [x, y, w, h]}` (결과 영상 기준) 를 넣어 ⑤부터 다시.
- 자막 전체(`edit_report.json` 의 subtitles)를 한 번 읽고 오타는 `fix` 로 고친다. 대조에서 걸린 줄은 소리를 다시 확인한다.
- 소리 끊김·말 중간 컷이 나오면 그 근처 `delete` 를 다시 보고(지운 범위가 넘쳤는지) 고친다.

### ⑦ 보고
`완성.mp4` 를 SendUserFile 로 보낸다 (자막 파일 `완성.srt` 도). 짧게 보고:
- 길이 변화 (원본 → 완성, 몇 초 줄였는지), 지운 말 개수와 예시 몇 개
- 넣은 강조 자막·자료화면 목록과 **출처**
- 검수에서 찾아 고친 것 (예: "4초 알림창의 이름·전화번호 흐림"), 남은 주의점
- 마지막에 한 줄: "아쉬운 점을 말해 주시면 규칙집에 넣어 다음 편집부터 반영할게요."

## B. 피드백 → 규칙집 (다음 편집부터 자동 반영)

사용자가 결과를 보고 아쉬운 점을 말하면:
1. 수치로 되는 것은 `rules.json` 을 고친다 (예: "자막이 작아" → `subtitle.size` 0.064→0.072, "컷이 너무 빡빡해" → `cut.max_pause`·`pad_after` 늘림, "배경음 커" → `bgm.volume_db` 낮춤).
2. 판단 기준은 `rulebook.md` 해당 장에 문장으로 넣는다 (예: "'진짜'는 말버릇이라도 지우지 않는다").
3. `rulebook.md` 11장 표에 `날짜 | 피드백 | 바꾼 규칙` 한 줄.
4. 이번 영상에 바로 다시 적용해 보여주고(⑤⑥⑦), **규칙 파일을 커밋하고 푸시**한다 — 클라우드 세션은 끝나면 사라지므로 커밋해야 다음 편집에 남는다.

## C. 레퍼런스 분석 → 규칙집 만들기

레퍼런스 영상(유튜브 링크 3~4개)을 받으면:
1. 영상 받기: `pip install -q yt-dlp && yt-dlp -f "bv*[height<=1080]+ba/b" -o "edits/refs/%(id)s.%(ext)s" <링크>`.
   유튜브가 네트워크 정책에 막히면(이 클라우드 환경은 보통 막혀 있음) 사용자에게: 레퍼런스 영상을 드라이브 영상함의 `ref` 폴더에
   올려 달라고 하거나, 환경 설정 → 네트워크 접근에서 `www.youtube.com`, `*.googlevideo.com` 허용을 요청한다.
2. 분석: `python3 $S/analyze_ref.py edits/refs/*.mp4 --out edits/refs/analysis`
3. `summary.md` 의 숫자(분당 컷 수, 컷 길이, 말 속도, 쉼 길이, 배경음 크기, 효과음 빈도, 자막 높이·위치·색)와
   장면 모음(`sheet_*.png`, `cuts.png`, `intro.png`, `outro.png`, `sfx.png`)을 **전부 열어 보고** 장면 단위로 정리한다:
   컷 간격, 자막 글꼴·크기·색·위치, 강조 자막이 뜨는 순간, 효과음·배경음 타이밍, 자료화면 넣는 방식, 화면 확대, 인트로·아웃트로.
4. `rulebook.md` 0장(레퍼런스 표)과 각 장을, `rules.json` 수치를 그 결과로 고친다. 공통점이 있으면 그걸 기준으로,
   레퍼런스끼리 다르면 사용자 원본(토킹헤드/화면 녹화)에 가까운 쪽을 고른다. 커밋·푸시.

## Google 드라이브 연결 (처음 한 번)

이 클라우드 환경에서는 드라이브 웹 주소는 막혀 있고, **Google Drive API(`www.googleapis.com`)는 열려 있다.** 그래서 API 키로 받는다.
사용자에게 이렇게 안내한다 (키·비밀번호를 채팅에 붙여 넣으라고 하지 않는다):
1. 구글 드라이브에 영상함 폴더를 하나 만든다 (예: `편집할 영상`). 안에 `bgm`, `ref` 폴더를 만들어도 된다.
2. 폴더 공유 → 일반 액세스 → **링크가 있는 모든 사용자 · 뷰어** → 링크 복사.
3. Google Cloud 콘솔(console.cloud.google.com) → 프로젝트 만들기 → "Google Drive API" 사용 설정 →
   사용자 인증 정보 → API 키 만들기 (API 제한: Google Drive API).
4. 이 세션 제목 표시줄의 클라우드 환경 메뉴 → 편집 → 환경 변수에 `GOOGLE_API_KEY=<키>` 추가 → 새 세션 시작.
5. 폴더 링크를 알려주면 `rules.json` 의 `drive.inbox` 에 저장·커밋한다. 이후로는 "드라이브에 영상 올렸어, 편집해줘"만 하면 된다.

claude.ai 의 Google Drive 커넥터(claude.ai/customize/connectors)를 연결해 두면 파일 찾기에는 쓸 수 있지만,
큰 영상 파일 내려받기는 위 API 키 방식이 확실하다.
다른 방법: 영상 파일을 이 대화에 직접 첨부하거나, 공유 링크만 주고 네트워크 설정에서 `drive.usercontent.google.com` 을 허용.

## 알아둘 한계

- 받아쓰기는 오프라인 한국어 모델(KsponSpeech)이라 고유명사·영어가 틀릴 수 있다 → ③에서 `fix` 로 자막만 고친다.
- 화면 글자 인식은 숫자·영문 위주다. 한글 이름 등은 ⑥에서 눈으로 찾는다.
- 효과음·기본 배경음은 코드로 합성한 것이다. 원하는 음악이 있으면 드라이브 `bgm` 폴더에.
- 렌더링은 CPU 로 하므로 10분 영상에 몇 분 걸린다. 먼저 `--fast` 로 확인해도 된다.
