# 웹컷 — 설치 없는 무료 영상 편집기

캡컷 같은 컷 편집을 브라우저 안에서만 끝내는 정적 웹 앱.
파일을 서버로 올리지 않고 `objectURL` 로만 열어서 편집하고, 결과는 화면 녹화 방식으로 저장한다.

- 배포: https://richroro.github.io/video-editor/
- 소스: `index.html` 한 파일 (외부 스크립트·빌드 없음, 구글 폰트만 링크)

## 되는 것

| 영역 | 기능 |
| --- | --- |
| 불러오기 | 영상·사진·음악 드래그&드롭 / 파일 선택, 샘플 클립 생성 |
| 자르기 | 클립 양 끝 드래그 트리밍, 재생 위치 분할(<kbd>S</kbd>), 복제, 삭제, 드래그로 순서 변경 |
| 영상 | 속도 0.25~4배, 볼륨·음소거, 채우기/전체보기, 확대·이동·회전, 페이드 인/아웃 |
| 사진 | 길이 지정, 켄번즈(줌 인/아웃) |
| 필터 | 프리셋 6종 + 밝기·대비·채도·색조·흐림 슬라이더 (`ctx.filter`) |
| 자막 | 글꼴 3종·굵기·크기·색·외곽선·배경, 정렬, 등장 효과 4종, 미리보기에서 직접 드래그 |
| 음악 | 배경음악 트랙, 시작 위치·구간·볼륨·페이드 |
| 프로젝트 | 9:16 / 16:9 / 1:1 / 4:5, 720p·1080p, 되돌리기·다시 실행(80단계) |
| 내보내기 | 해상도·프레임(24/30/60)·화질 선택 후 파일 저장 |

## 구조

상태는 `P`(프로젝트: 미디어 풀 + 세 트랙)와 `UI`(재생 위치·선택·줌)로 나뉜다.

- **영상 트랙**은 자석 트랙이다. 클립을 이어 붙이고 `layout()` 이 매번 시작 시각(`_s`)과
  타임라인 길이(`_d = (out-in)/speed`)를 다시 계산한다.
- **음악·자막 트랙**은 시작 시각을 자유롭게 갖는다.
- 클립마다 `<video>`/`<audio>` 요소를 따로 만든다(`els` 맵). 같은 파일을 여러 번 써도
  탐색 위치가 서로 안 엉키고, 겹치는 구간을 각자 재생할 수 있다.
- 소리는 `클립 GainNode → mix → [미리보기 볼륨 → 스피커]` 와 `mix → MediaStreamDestination`
  두 갈래다. 미리보기 볼륨을 줄여도 내보낸 파일 음량은 그대로다.
- 그리기는 `requestAnimationFrame` 한 루프에서 처리한다. 재생 중이 아니면 `needsDraw`
  플래그가 설 때만 다시 그려서 idle 비용을 줄였다.

## 내보내기 방식

`canvas.captureStream()` + 오디오 그래프를 `MediaRecorder` 로 **실시간 녹화**한다.
5분짜리 영상은 5분이 걸리고, 그동안 탭이 살아 있어야 한다(백그라운드로 가면 rAF 가
멈춰서 화면이 얼어붙는다 — 그래서 탭 이탈 시 경고를 띄운다).

컨테이너는 지원되는 첫 번째를 고른다.

```
video/mp4;codecs=avc1…  →  video/webm;codecs=vp9,opus  →  video/mp4(기본)  →  video/webm
```

최신 크롬·엣지는 H.264 MP4 로 바로 저장되고, 파이어폭스는 WebM 으로 떨어진다.
WebCodecs + mp4 먹서를 쓰면 실시간보다 빠르게 뽑을 수 있지만 외부 라이브러리가 필요해서
"한 파일, 의존성 0" 원칙을 지키려고 택하지 않았다.

## 만들면서 걸린 것

| 증상 | 원인 | 대응 |
| --- | --- | --- |
| 불러온 webm 길이가 `Infinity` | MediaRecorder 로 만든 파일은 duration 메타가 비어 있다 | `currentTime = 1e6` 으로 끝까지 보낸 뒤 `timeupdate` 에서 확정된 길이를 읽고 되감기(`settleDuration`) |
| `hidden` 을 걸어도 안 사라짐 | `.btn{display:inline-flex}` 같은 클래스 규칙이 UA 의 `[hidden]{display:none}` 을 이김 | `[hidden]{display:none !important}` 전역 선언 |
| 모바일에서 화면이 가로로 터짐 | flex 자식 기본값 `min-width:auto` 때문에 타임라인 스크롤 영역이 콘텐츠 폭만큼 늘어남 | `.tl / .tl-main / .tl-scroll` 에 `min-width:0` |
| 모바일 헤더·패널이 어긋남 | 탭 바를 추가하면서 `.app` 그리드 행(3개)보다 자식이 많아져 행이 밀림 | 행을 4개로 늘리고 `grid-row` 를 명시 |
| 트랙 이름표가 첫 클립을 가림 | 스크롤 영역 안에 `position:sticky` 로 붙여둠 | 타임라인 왼쪽에 고정 머리글 열을 따로 두고 세로 스크롤만 `transform` 으로 동기화 |
| 합성 포인터 이벤트에서 예외 | `setPointerCapture` 는 활성 포인터가 아니면 던진다 | 전부 `try/catch` |

## 검증

헤드리스 크로미움(Playwright)에서 실제 파일을 넣어 확인했다.

- 영상(webm·MediaRecorder 산출물)·사진·음악 불러오기, 길이 인식
- 클립 배치 → 오른쪽 핸들 드래그로 트리밍 → 드래그로 순서 교체
- 속도 2배 적용 시 타임라인 길이 절반, 되돌리기/다시 실행 복원
- 자막 추가 후 미리보기에서 드래그로 위치 이동
- 필터 프리셋, 9:16 ↔ 16:9 전환 시 캔버스 1080×1920 / 1920×1080
- 내보내기: 1080×1920 파일 생성 → 다시 디코딩해 길이(±0.2초)·프레임 픽셀·자막 확인
- 내보낸 파일의 오디오를 `decodeAudioData` 로 풀어 무음이 아님을 확인(peak 0.28)

## 한계

- 실시간 녹화라 영상 길이만큼 시간이 걸린다. 내보내는 동안 탭을 벗어나면 안 된다.
- 클립 사이 크로스 디졸브는 없다. 페이드 인/아웃으로 대신한다(동시에 두 영상을 디코딩해야 해서).
- 탭을 닫으면 편집 내용이 사라진다. 파일 핸들을 저장할 수 없어서 프로젝트 저장은 넣지 않았다.
- 긴 영상은 클립 수만큼 디코더가 뜬다. 모바일보다 PC 크롬·엣지 계열이 안정적이다.
