# 테슬라 주주 계산기

서학개미용 TSLA 계산기. 수익이 **주가에서 났는지 환율에서 났는지** 갈라서 보여주고,
해외주식 양도소득세를 시뮬레이션하고, 테슬라가 분기마다 발표하는 실물 지표를 함께 본다.

- 배포: https://richroro.github.io/tesla/
- 소스: `index.html` 한 파일 (외부 스크립트·빌드 없음, 구글 폰트만 링크)

## 되는 것

| 영역 | 기능 |
| --- | --- |
| 시세 | TSLA 주가·원달러 환율 자동 조회, 실패 시 기준일 스냅샷, 직접 입력 |
| 보유 분석 | 매수 여러 건 입력 → 평단·가중평균 매수환율·원금·평가액·손익(원/달러) |
| 손익 분해 | 원화 손익을 **주가 효과 / 환율 효과 / 교차 효과**로 분리 |
| 평단 계산 | 목표 평단 → 필요한 추가 매수 주수, 추가 매수 주수 → 바뀌는 평단 (양방향) |
| 양도세 | 250만원 기본공제·22% 세액, 손익통산, **세금 0원으로 팔 수 있는 주수** |
| 전기차 지표 | 분기별 인도량·에너지 저장장치 배포량(2024 Q1~2026 Q2), 2025년 BYD 비교 |
| 접근성 | 모든 차트에 표 보기 전환, 다크 모드, 모바일 레이아웃 |

## 손익 분해가 이 페이지의 핵심

미국 주식은 주가와 환율 두 군데에 동시에 베팅한 상태다. 원화 손익만 보면 둘이 섞여 있어서
"테슬라가 올라서 번 건지 달러가 올라서 번 건지" 알 수 없다. 그래서 항등식으로 쪼갰다.

```
P₀ = 평단(USD)          F₀ = 금액 가중 평균 매수환율
P₁ = 현재가(USD)        F₁ = 현재 환율        Q = 보유 주수

원화 손익 = Q(P₁F₁ − P₀F₀)
          = Q(P₁−P₀)F₀     ← 주가 효과
          + Q·P₀(F₁−F₀)    ← 환율 효과
          + Q(P₁−P₀)(F₁−F₀) ← 교차 효과
```

`F₀`는 단순 평균이 아니라 **USD 금액 가중 평균**이다. 그래야 `원금(원) = Q·P₀·F₀`가 정확히 성립하고,
세 항의 합이 원화 손익과 소수점까지 일치한다(테스트로 검증).

## 데이터

지표는 전부 회사 발표치나 공개 집계만 쓴다. 값은 `index.html` 맨 위 `DATA` 블록 한 곳에 모아뒀고,
분기 합계가 회사가 발표한 연간 합계와 맞는지 확인한 뒤 기입했다.

| 항목 | 기간 | 출처 |
| --- | --- | --- |
| 차량 인도량·생산량 | 2024 Q1 ~ 2026 Q2 | Tesla IR 분기 발표 (Form 8-K) |
| 에너지 저장장치 배포량 | 2024 Q1 ~ 2026 Q2 | Tesla IR 분기 발표 |
| BYD 판매량 | 2025 연간 | BYD 월간 공시 (CnEVPost 집계) |
| 글로벌 EV 판매 | 2025 연간 | Rho Motion |
| BEV 점유율 | 2024 · 2025 | Autovista24 |

검증된 항등식(테스트에 포함):

```
2024 인도  386,810 + 443,956 + 462,890 + 495,570 = 1,789,226  (발표치 일치)
2025 인도  336,681 + 384,122 + 497,099 + 418,227 = 1,636,129  (발표치 일치)
2024 에너지 4.1 + 9.4 + 6.9 + 11.0 = 31.4 GWh               (발표치 일치)
2025 에너지 10.4 + 9.6 + 12.5 + 14.2 = 46.7 GWh             (발표치 일치)
BYD 2025   2,256,714 + 2,288,709 + 57,013 = 4,602,436        (발표치 일치)
```

새 분기가 발표되면 `DATA.quarters`에 한 줄 추가하고 `DATA.asOf`만 고치면 된다.
차트·표·통계는 전부 이 배열에서 파생된다.

## 시세 조회

정적 페이지라 API 키를 쓸 수 없어서, 키 없이 CORS가 열려 있는 공개 엔드포인트를 순서대로 시도한다.

```
주가  stooq CSV  →  allorigins 프록시 경유 stooq
환율  frankfurter.app  →  open.er-api.com
```

전부 실패하면 `DATA.snapshot`의 **기준일 종가**로 계산하고, 배지에 "기준일 스냅샷"이라고 표시한다.
주가·환율 칸에 직접 입력하면 그 값이 항상 우선한다. 즉 네트워크가 죽어도 계산기는 전부 동작한다.

> ⚠️ 이 엔드포인트들은 **빌드 환경의 이그레스 정책에 막혀 실제 응답을 확인하지 못했다.**
> 배포 후 브라우저에서 한 번 열어보고, "실시간 시세" 배지가 뜨지 않으면 소스를 교체해야 한다.
> 실패 경로(스냅샷 폴백·직접 입력)는 헤드리스 브라우저에서 확인했다.

## 검증

헤드리스 크로미움(Playwright)에서 33개 항목을 확인했다.

- 시세 API가 전부 막힌 상태에서 스냅샷 폴백으로 정상 렌더 (JS 런타임 에러 0건)
- 평단·가중평균 환율·원금·평가액·손익을 독립 계산값과 대조
- **손익 분해 세 항의 합 == 원화 손익** (항등식, 오차 1e-9 이내)
- 목표 평단 → 추가 주수를 구한 뒤, 그 주수로 평단을 되돌려 계산해 목표와 일치하는지 역검산
- 양도세: 과세표준 = 차익−250만, 세액 = 과세표준×22%, 세후 = 차익−세액
- 손익통산: 기타 손실 −100만 입력 시 남은 공제 한도가 350만으로 늘어나는지
- 분기 합계 == 회사 발표 연간 합계 (위 항등식 5종)
- 차트 막대 개수·범례·툴팁·표 전환, 데스크톱/모바일(375px) 가로 스크롤 0px, 다크 모드

## 색

차트 색은 눈으로 고르지 않고 색각 이상 판별 검사를 돌려서 통과한 조합만 썼다
(adjacent/all-pairs CVD ΔE, 명도 대역, 채도 하한, 배경 대비). 밝은 배경에서 초록 계열이
대비 3:1을 못 넘겨서, 규칙대로 **직접 라벨 + 표 보기**를 같이 제공한다.

손익 색은 한국 증시 관례를 따라 **상승 빨강 / 하락 파랑**이고, 색만으로 구분하지 않도록
▲▼ 기호와 +/− 부호를 항상 함께 표시한다.

## 한계

- 양도세 계산은 기본 규정만 반영한다. 국세청은 **결제일(보통 T+1) 기준환율**을 쓰지만 여기서는
  입력한 환율 하나로 계산하고, 증권사 수수료·제비용도 빼지 않는다. 실제 신고는 증권사 자료 기준.
- 취득가액을 이동평균으로만 계산한다. 증권사가 선입선출을 쓰면 실현 손익이 달라진다.
- 배당소득세(미국 15% 원천징수)는 다루지 않는다. 양도소득세와 별개 영역이다.
- 입력값은 브라우저 `localStorage`에만 남는다. 서버로 가지 않지만, 기기를 바꾸면 사라진다.
- 투자 권유나 세무 자문이 아니다.
