# 전 종목 탐색기

미국(나스닥·뉴욕·아메리칸)과 한국(코스피·코스닥·코넥스)에 상장된 주식 **전 종목**을 한 곳에서
찾고 분석하는 페이지.

- 배포: https://richroro.github.io/finder/
- 종목 페이지: `/finder/s/AAPL/` · `/finder/s/005930/` (시총 상위 미국 500 · 한국 300, 검색엔진 색인용)
- 그 밖의 종목: `/finder/#s=티커` 로 바로 열린다
- 스크리너 조건은 주소에 담긴다: `/finder/?m=US&r=pe:0:15,dy:3:&v=value`
- 심층 노트가 있는 37곳(`/stocks/`, `/m7/`)은 상세 화면에서 그 페이지로 이어진다

### 재무 지표

출처가 여럿이라 행마다 `fs` 열(`K` 한국거래소 · `N` 네이버 · `S` SEC · `Y` Yahoo)에 어디서 왔는지 적고, 상세 화면에도 표시한다.

**SEC 는 요청마다 연락처 이메일이 든 User-Agent 를 요구한다**(없으면 403). 워크플로는 저장소 변수 `SEC_CONTACT` 를 쓰고,
없으면 실행한 GitHub 계정의 no-reply 주소(`<id>+<아이디>@users.noreply.github.com`)를 쓴다.
실제로 연락받을 주소를 쓰려면 Settings → Secrets and variables → Actions → Variables 에 `SEC_CONTACT` 를 만든다.
한국은 거래소 값을 우선하고 Yahoo 는 실적일·의견에만 쓴다. 미국은 Yahoo 가 되면 최근 4분기 값을, 안 되면 SEC 값을 쓴다.

Yahoo 일괄 시세는 인증 토큰(crumb)이 필요한데 **GitHub Actions 같은 데이터센터 IP 에는 잘 내주지 않는다**(HTTP 401).
그래서 401·403 이 오면 재시도 없이 바로 건너뛰고 SEC·KRX 로 채운다.

SEC 값은 **총액으로 계산**한다: PER = 시가총액 ÷ 순이익, PBR = 시가총액 ÷ 자기자본, ROE = 순이익 ÷ 자기자본,
배당수익률 = 보통주 배당 지급액 ÷ 시가총액. 주당 값(EPS)을 쓰면 결산 뒤 액면분할이 있을 때 PER 이 몇 배로 틀어진다.
20-F 로 공시하는 외국 기업(TSMC 등)은 SEC frames 에 없다.

PER·선행 PER·PBR 은 0 이하나 말이 안 되는 크기는 버린다(적자 PER 은 비우고 "적자"로 표시).
배당수익률은 연간 배당(예상, 없으면 최근 12개월) ÷ 주가로 직접 계산한다.
ROE 는 주당순이익 ÷ 주당순자산인데, **ADR 처럼 장부 통화가 주가 통화와 다르면** 값이 수십 배 틀어진다.
그래서 `주가 ÷ 주당순자산`이 Yahoo 의 PBR 과 20% 안에서 맞을 때만 계산한다.
다음 실적일은 오늘 이후 날짜만, 애널리스트 의견은 1(강력 매수)~5(강력 매도) 평균이다. 코넥스는 출처에 없다.

### 한국 수정 주가

marcap 의 종가는 수정 전 가격이다. 액면분할·병합이 있으면 1년 수익률이 수십 배로 튄다.
**한국은 하루 가격제한폭이 ±30%**라서, 전날 대비 +31%/−31% 를 넘는 변동은 시장이 아니라
주식 수 변경에서 온 것으로 보고 그날의 비율로 이전 가격을 모두 맞춘다(그날 상장주식수 비율과 비슷하면 그쪽을 쓴다).

그래도 **거래량이 0인 채로 호가만 움직이는 코넥스 종목**은 수익률이 수천 % 로 나올 수 있다(실제 데이터다).
그래서 스크리너는 기본으로 "거래가 거의 없는 종목"(20일 평균 거래대금 한국 1억 원·미국 50만 달러 미만)을 숨긴다.
검색에서는 숨기지 않는다.

### 점수

점수는 좋고 나쁨이 아니라 **같은 시장 안의 위치**다. 미국은 미국끼리, 한국은 한국끼리, 일봉이 60개 이상인 종목만 비교한다.

```
모멘텀  = 평균(3개월, 6개월, 1년 수익률의 백분위)
추세    = 평균(50일선 대비, 200일선 대비의 백분위)
안정성  = 평균(변동성 낮은 순 백분위, 최대낙폭 얕은 순 백분위)
유동성  = 20일 평균 거래대금 백분위
```

```bash
python finder/validate.py                  # 데이터 검사
python -m unittest discover -s finder/tests   # 단위 테스트(네트워크 없음)
python -m http.server  # → http://localhost:8000/finder/
```

`finder-tests.yml` 이 finder/ 를 바꾸는 PR 마다 단위 테스트·자바스크립트 문법·데이터 검사를 돌리고,
`pages.py` 결과가 커밋된 종목 페이지와 같은지도 확인한다.

### 종목 페이지(SEO)

`/finder/#s=AAPL` 같은 해시 주소는 검색엔진이 따로 색인하지 않는다. 그래서 `pages.py` 가 시총 상위
미국 500 · 한국 300 종목에 작은 HTML(`finder/s/<티커>/index.html`)과 `finder/sitemap.xml` 을 만든다.
본문은 `app.js` 가 같은 데이터로 그린다. 페이지에는 **매일 바뀌는 숫자를 넣지 않아서** 데이터가 갱신돼도
파일이 바뀌지 않는다(이름·업종이 바뀔 때만 다시 쓴다). 한 번 생긴 페이지는 상장폐지 전까지 유지해
순위 경계에서 들락날락하지 않는다.

`--us-dir`, `--kr-dir` 로 미리 받아 둔 원천 파일(`nasdaq_full_tickers.json` …, `marcap-2026.parquet` …)을 쓸 수 있다.
Actions 탭에서 이 워크플로를 **Run workflow** 로 바로 돌릴 수도 있다.

한글 별칭은 `ko_alias.json` 에 있다. 티커가 바뀌면(예: 배릭 `GOLD`→`B`, 파라마운트 `PARA`→`PSKY`)
엉뚱한 회사에 한글 이름이 붙으므로, 추가할 때는 원천 목록의 회사명과 대조한다.

## 알려진 한계

- **미국 재무 지표는 2026-09-24 기준 비어 있었다.** GitHub Actions 에서 Yahoo 는 401(인증 토큰 거부), SEC 는 403(데이터센터 IP 차단),
  네이버는 미국 종목 요약을 주지 않는다. 그래서 나스닥 종목 요약·실적 캘린더를 추가했고, 나스닥 요약에 PER·EPS 가 없어 TradingView 스크리너를 더했다(결과는 실행 로그의 `나스닥`·`트레이딩뷰` 줄). 코드는 세 경로를 모두 시도하고 로그에 이유를 남기므로,
  자체 서버·가정용 IP 에서 돌리거나 유료 API 키를 붙이면 채워진다. 그동안 상세 화면은 TradingView 재무제표로 안내한다.
- 한국 재무 지표는 한국거래소가 로그인을 요구하게 바뀌어(`LOGOUT`) 네이버 증권 종목 요약으로 받는다.

- **실시간이 아니다.** 전 거래일 종가 기준이다.
- 재무 지표는 Yahoo 의 요약 값이라 회사 공시와 기준(회계연도, 일회성 항목)이 다를 수 있다. 원문은 상세 화면의 SEC·DART 링크로 확인한다.
- 상세 화면 차트는 시총 상위 종목만 `data/hist.json` 의 **1년 일봉**(이동평균·거래량·지수 비교)이고, 나머지 종목은 파일 크기 때문에 **5거래일 간격 주간 종가**다.
- 매일 약 3MB 파일을 커밋하므로 저장소가 1년에 100~150MB 커진다. 커지면 Pages 를 Actions 배포로 바꾸고 이 파일을 커밋하지 않는 구조로 옮기면 된다.

## 상업적으로 쓰려면 — 데이터 이용 조건

코드는 상업 서비스 수준으로 만들었지만, **지금 쓰는 무료 데이터 출처는 대부분 재배포·상업 이용을 허락하지 않는다.**
광고를 붙이거나 유료로 운영하기 전에 출처를 라이선스가 있는 것으로 바꿔야 한다.

| 출처 | 지금 | 상업 이용 시 |
| --- | --- | --- |
| Yahoo Finance (일봉·재무·환율) | 비공식 API. 개인·비상업 용도 | Polygon.io, Financial Modeling Prep, Twelve Data, Intrinio 등 유료 API |
| SEC EDGAR (미국 재무) | 미국 정부 저작물, 퍼블릭 도메인 | **그대로 가능**(요청 속도 제한·User-Agent 규칙 준수) |
| 나스닥 스크리너 사본 | 나스닥 웹사이트 데이터 | Nasdaq Data Link 또는 위 유료 API |
| 한국거래소 시세(marcap)·KIND·네이버 증권 | KRX·네이버 이용 조건 적용 | KRX 정보데이터시스템 유료 데이터 상품, 또는 증권사 Open API(한국투자증권 KIS 등) · DART Open API(공시·재무, 무료 키) |
| TradingView 위젯 | 무료 위젯, 출처 표기 조건 | 그대로 가능(위젯 약관 준수) |
| TradingView 스크리너 (재무 지표) | 비공개 웹 API. 개인·비상업 용도 | 위 유료 API 로 교체 |

`build.py` 는 출처마다 함수 하나(`load_us_universe`, `us_history`, `load_kr`, `yahoo_fund`, `sec_fund`, `krx_fund`, `naver_fund`, `fx_rate`)로 나뉘어 있고
나머지(지표 계산·점수·파일 형식)는 출처와 무관하다. 출처를 바꿀 때는 그 함수만 같은 모양의 값을 돌려주도록 바꾸면 된다.
