아이디어 하나를 다섯 채널 콘텐츠로 — 1인 콘텐츠 공장 만드는 법

2026-09-26

#콘텐츠자동화#1인미디어#AI글쓰기#GitHubActions

혼자서 블로그, 뉴스레터, 유튜브를 같이 굴리다 보면 금방 알게 됩니다. 힘든 건 글을 쓰는 일이 아니라 같은 얘기를 채널마다 다시 쓰는 일이라는 걸요. 블로그에 한 번 쓴 내용을 뉴스레터용으로 줄이고, 유튜브 대본으로 말투를 바꾸고, 쇼츠용으로 30초에 맞춰 자르다 보면 하루가 갑니다.

『AI로 1인 콘텐츠 공장 만들기』를 읽고, 이 반복을 기계에게 넘기는 파이프라인을 이 사이트에 직접 만들어 봤습니다. 지금 읽고 계신 이 글도 그 파이프라인에서 나왔습니다.

핵심은 '원본은 하나, 형식은 여러 개'

콘텐츠 공장의 출발점은 단순합니다.

  • 원본은 아이디어 메모 한 장으로 둡니다. 말하고 싶은 요지, 사례, 주의할 점 정도만 적습니다.
  • 채널별 원고는 그 메모에서 변환합니다. 블로그 글, 뉴스레터, 유튜브 대본, 쇼츠, SNS 글이 한 번에 나옵니다.
  • 사람은 세 가지만 합니다. ① 메모 쓰기 ② 결과 검토·보정 ③ 반응을 보고 다음 아이디어 고르기.

이른바 One Source, Multi Use입니다. 달라진 점은 '변환'을 사람이 아니라 AI가 한다는 것뿐입니다.

실제로 만든 구조

이 사이트(GitHub Pages)에 붙인 흐름은 이렇습니다.

  1. 저장소의 content-factory/ideas/ 폴더에 마크다운 메모를 하나 올립니다.
  2. Claude Code에게 "콘텐츠 공장 돌려줘"라고 말하면, Claude가 메모를 읽고 정해진 규칙대로 원고를 씁니다. API 키도 서버도 필요 없습니다.
  3. 채널별 원고가 JSON 한 벌로 돌아옵니다. 블로그 글, 뉴스레터, 유튜브 대본(장면별 화면 지시 포함), 쇼츠 대본 3개, SNS 글 3개.
  4. 스크립트가 원고 형식을 검증한 뒤 블로그 글을 /blog/ 아래 페이지로 만들고, RSS(/blog/feed.xml)를 갱신합니다.
  5. 뉴스레터·유튜브·쇼츠·SNS 원고는 콘텐츠 공장 대시보드에서 채널별로 보고 복사할 수 있습니다.

서버는 없습니다. GitHub Pages 무료 호스팅에 올라가고, 원고는 이미 쓰고 있는 Claude 구독 안에서 만들어지니 추가 비용이 없습니다. 나중에 완전 무인으로 돌리고 싶으면 API 키를 넣어 GitHub Actions가 생성까지 하도록 바꿀 수도 있게 만들어 뒀습니다.

책의 6단계 파이프라인과 이 사이트에서 맡은 부분

책은 콘텐츠 공장을 아이디어 → 리서치 → 생성 → 디자인 → 발행 → 분석 6단계로 나눕니다. 이 사이트에서는 이렇게 나눠 맡았습니다.

  • 아이디어: 사람. 메모 한 장.
  • 리서치: Claude. 핵심·보조 키워드, 검색 의도, 이 글만의 각도, 제목 후보 3개. 단, 검색량 수치는 지어내지 않게 하고 네이버 데이터랩 같은 도구에서 직접 확인합니다.
  • 생성: Claude. 다섯 채널 원고.
  • 디자인: 공유 썸네일 이미지는 코드가 자동으로 그리고, 유튜브 썸네일·본문 이미지는 이미지 생성 도구용 프롬프트로 받습니다.
  • 발행: 블로그 자동 게시와 RSS. 뉴스레터는 스티비·메일리 같은 도구의 RSS 발송 기능에 연결하면 됩니다.
  • 분석: 채널마다 다른 UTM 꼬리표를 붙인 링크를 넣어, 어느 채널에서 사람이 들어왔는지 GA4에서 나눠 볼 수 있게 했습니다.

채널마다 '다르게' 쓰게 하는 규칙

AI에게 그냥 "여러 채널용으로 바꿔 줘"라고 하면 같은 문장을 길이만 바꿔서 돌려줍니다. 그러면 어느 채널에서도 읽히지 않습니다. 그래서 채널마다 역할을 정해 줬습니다.

  • 블로그: 검색으로 들어온 사람이 끝까지 읽는 글. 소제목으로 나누고, 바로 따라 할 수 있는 방법과 체크리스트를 넣는다.
  • 뉴스레터: 구독자에게 보내는 편지. 첫 문장에서 '왜 지금 읽어야 하는지'를 말하고, 자세한 내용은 블로그로 넘긴다.
  • 유튜브: 8~10분 대본. 처음 15초 훅, 그리고 장면마다 화면에 무엇을 띄울지까지 적는다.
  • 쇼츠: 30~50초 대본 3개. 첫 2초 안에 손가락을 멈추게 하는 한 줄로 시작한다.
  • SNS: 스레드·인스타그램·링크드인에 맞춘 짧은 글.

자동화해도 사람이 잡아야 하는 것

만들어 보니 병목은 초안이 아니라 검증이었습니다.

  • 사실 확인: AI는 그럴듯한 숫자를 잘 지어냅니다. 그래서 "메모에 없는 통계·고유명사·인용은 쓰지 말고, 숫자가 필요하면 '예를 들어'로 가정 예시를 들라"는 규칙을 넣었습니다.
  • AI 활용 표시: 인공지능기본법 시행에 맞춰, 생성형 AI로 만든 글에는 그 사실을 밝혀 둡니다. 이 블로그는 글마다 하단에 표시합니다.
  • 과장 금지: "한 달 만에 월 천" 같은 제목은 클릭은 받아도 신뢰를 잃습니다. 낚시성 제목을 금지했습니다.
  • 처음엔 반자동으로: 첫 몇 주는 결과를 직접 읽고, 마음에 안 드는 패턴이 보이면 규칙(프롬프트)을 고치는 편이 낫습니다. 규칙이 쌓일수록 검토 시간이 줄어듭니다.

이번 주에 해 볼 것

  • 쓰고 싶은 주제 3개를 골라 메모 한 장씩 적어 보세요. 요지 3줄, 사례 1개, 주의할 점 1개면 충분합니다.
  • 각 메모를 채널별로 변환해 보고, 어느 채널 원고가 가장 손이 덜 가는지 확인하세요.
  • 손이 가장 많이 간 채널의 규칙부터 고치세요. 그게 공장의 첫 번째 개선입니다.

콘텐츠를 매일 새로 '쓰는' 대신, 아이디어를 모으고 공장을 손보는 쪽으로 일의 무게중심을 옮겨 보세요. 혼자서도 여러 채널을 꾸준히 운영할 수 있게 됩니다.
