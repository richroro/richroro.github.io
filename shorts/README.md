# 쇼츠 메이커 — 가로 영상의 명장면을 세로 쇼츠로

해외·국내 영상에서 볼 만한 구간만 골라 **제목 + 영상 + 자막 + 출처**를 얹은
세로 쇼츠(1080×1920)로 저장하는 정적 웹 앱.
파일은 서버로 올리지 않고 `objectURL` 로만 열어서 브라우저 안에서 처리한다.

- 배포: https://richroro.github.io/shorts/
- 소스: `index.html` 한 파일 (외부 스크립트·빌드 없음, 구글 폰트만 링크)

## 쓰는 순서

1. **영상 불러오기** — 파일을 끌어다 놓거나, `화면 녹화로 가져오기`로 다른 탭에서 재생 중인 영상을 녹화해 바로 소스로 쓴다.
   1분 이하 영상은 통째로 첫 구간이 된다.
2. **구간 고르기** — 소스 보기에서 <kbd>I</kbd>/<kbd>O</kbd> 로 시작·끝을 찍고 `구간 추가`.
   `소리 큰 구간 자동으로 찾기`를 누르면 환호·웃음처럼 소리가 커지는 곳을 후보로 골라 준다.
3. **꾸미기** — 템플릿 5종(블랙·블러·화이트·레드·풀화면), 영상 크기·위치·여백·모서리, 구간 전환 효과, 진행 막대.
4. **제목·자막** — `*별표*` 로 감싼 말은 강조색. 자막은 지금 위치에 추가 / 여러 줄 고르게 나누기 /
   재생하며 <kbd>Enter</kbd> 로 탭해서 맞추기 / SRT·VTT 불러오기.
5. **소리·출처** — 원본 음량, 배경음악(반복 재생), 영상 귀퉁이 출처 표기.
6. **저장** — MP4(크롬·엣지) 또는 WebM, 30/60fps. 지금 화면은 `썸네일` 로 PNG 저장.

## 구조

| 부분 | 방식 |
| --- | --- |
| 구간 재생 | 구간마다 `<video>` 를 따로 만들고 다음 구간을 시작점에 미리 맞춰 둔다. 한 rAF 루프가 지금 구간 영상의 `currentTime` 으로 전체 타임라인 위치를 계산하고, 끝점에 닿으면 다음 영상을 재생한다. 같은 파일에서 여러 구간을 뽑아도 넘어갈 때 탐색 지연이 없다. |
| 소리 | `구간 영상 → GainNode → mix ┬→ 미리보기 볼륨 → 스피커` / `└→ MediaStreamDestination(녹화)`. 미리보기 볼륨은 저장 파일 음량에 영향이 없다. |
| 블러 배경 | 매 프레임 1080×1920 에 블러 필터를 거는 대신, 영상을 135×240 캔버스에 `blur(5px)` 로 그린 뒤 키워서 붙인다. `ctx.filter` 가 없는 브라우저(사파리)는 27×48 로 줄였다 키우는 것만으로 흐리게 만든다. |
| 글자 | `*강조*` 를 토큰으로 나눠 띄어쓰기 단위로 줄바꿈하고, 한 단어가 너무 길면 글자 단위로 자른다. 외곽선을 전부 먼저 그리고 채우기를 나중에 해서 강조 경계에서 외곽선이 글자를 덮지 않게 했다. 구글 폰트 한글은 글자 범위별 조각이라 `document.fonts.load(font, text)` 로 실제 쓸 글자 조각을 미리 받는다. |
| 소리 큰 구간 | 파일을 `OfflineAudioContext(8kHz)` 로 디코딩 → 0.25초마다 RMS → 정한 길이의 창 평균이 큰 순서로 겹치지 않게 고른다. 큰 소리가 창보다 짧아 점수가 같은 창이 이어지면 그 가운데를 고르고, 중앙값의 1.25배에 못 미치는 곳은 후보에서 뺀다. 700MB 초과 파일은 메모리 때문에 분석하지 않는다. |
| 화면 녹화 | `getDisplayMedia` + `MediaRecorder` → `File` 로 만들어 일반 불러오기와 같은 길을 탄다. 녹화 webm 은 길이가 `Infinity` 로 와서 끝까지 탐색해 확정한다(`settleDuration`). |
| 가려지는 영역 | 쇼츠 화면의 채널명·설명·버튼 자리를 별도 캔버스에 겹쳐 보여 준다. 녹화 캔버스와 분리돼 있어 저장 파일에는 들어가지 않는다. 위치는 대략값. |
| 설정 저장 | 템플릿·제목·글자 모양·출처는 `localStorage` 에 남긴다. 영상·구간·자막은 남기지 않는다. |

## 내보내기

`canvas.captureStream(fps)` + 녹화용 오디오 트랙을 `MediaRecorder` 로 **실시간 녹화**한다(웹컷과 같은 방식).
영상 길이만큼 걸리고 그동안 탭이 앞에 있어야 한다. 컨테이너는 H.264 MP4 → VP9 WebM 순으로 지원되는 첫 번째.

## 저작권

페이지 안에 `올리기 전 저작권 체크`를 넣었다. 요지는 출처 표기 ≠ 허락, Content ID,
안전한 소재(직접 촬영·허락·CC BY·공공누리), 인용 요건(저작권법 제28조·제35조의5).
영상 다운로드 기능은 넣지 않았다.

## 검증

헤드리스 크로미움(Playwright)에서 실제 파일로 확인했다.

- 20초 VP9/Opus 테스트 영상(12~15초만 소리 큼) 불러오기 → 길이·해상도 인식, 1분 이하라 자동 첫 구간
- 소리 큰 구간 찾기: 5초 창 → `0:11~0:16`, 8초 창 → `0:09~0:17` (조용한 곳은 후보에서 빠짐)
- 구간 2개(2~4초, 10~15초) → 타임라인 7초, 템플릿 5종·출처·가려지는 영역 화면 확인
- 탭으로 맞추기: 3줄을 1.5초 간격으로 탭 → `1.53–3.04 / 3.04–4.58 / 4.58–6.11`
- 저장: 1080×1920 VP9 + Opus 파일, 디코딩 길이 7.3초, 제목 글꼴·외곽선·자막이 프레임에 그대로, 두 번째 구간 소리가 더 큼
- 390px 폭 모바일에서 가로 스크롤 없음

GPU 없는 컨테이너에서는 1080×1920 그리기가 프레임당 40ms 가까이 걸려 저장 프레임 수가 적게 나왔다.
GPU 가속 캔버스가 있는 일반 PC 브라우저에서는 이 제약이 없다.

## 한계

- 실시간 녹화라 길이만큼 시간이 걸린다. 저장 중 탭을 벗어나면 안 된다.
- 화면 녹화로 가져오기는 PC 크롬·엣지에서만 된다(모바일 브라우저는 `getDisplayMedia` 미지원).
- 구간 사이 크로스 디졸브 대신 검게 페이드·흰색 번쩍 전환만 있다.
- 탭을 닫으면 구간·자막이 사라진다.
