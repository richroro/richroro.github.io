# 쇼츠 리믹스 기획 — 유튜브 리믹스 버튼으로 실행할 컷 시트

남의 유튜브 영상을 소재로 쇼츠를 만들 때, **무엇을 어디서 몇 초 가져올지**를 정하고
그대로 실행할 수 있는 지시서를 뽑는 정적 웹 앱.

- 배포: https://richroro.github.io/shorts-remix/
- 소스: `index.html` 한 파일 (외부 스크립트는 유튜브 공식 IFrame Player API 하나, 그 밖에 구글 폰트 링크)

## 왜 편집기가 아니라 기획 도구인가

남의 영상 파일을 받아서 잘라 붙이는 방식은 택할 수 없었다.

- 임베드된 유튜브 플레이어는 다른 출처라 `canvas` 로 프레임을 읽을 수 없다. 브라우저가 막는다.
- 서버에서 받아오는 방식은 유튜브 약관 위반이고, 그렇게 만든 쇼츠는 Content ID 클레임과
  재사용 콘텐츠 정책에 걸린다.

대신 유튜브가 공식으로 열어둔 **리믹스** 기능이 그 일을 한다(사운드 사용 · 그린 스크린 ·
잘라내기 · 콜라보). 원본 링크가 자동으로 붙어 출처도 남는다. 그래서 이 도구는 화면과 소리를
가져오는 일에는 손대지 않고, **리믹스로 무엇을 할지 정하는 단계**만 맡는다.

## 되는 것

| 영역 | 기능 |
| --- | --- |
| 소재 | `watch` · `shorts` · `youtu.be` · `embed` 링크와 11자리 ID, `t=1m30s` 시작점 인식. 공식 플레이어로 재생하고 제목·채널·길이를 플레이어에서 받아 적는다 |
| 구간 찍기 | <kbd>I</kbd> 시작 · <kbd>O</kbd> 끝 · <kbd>Space</kbd> 재생 · <kbd>←</kbd><kbd>→</kbd> 1초(<kbd>Shift</kbd> 0.1초), 구간 반복 재생, 0.25~2배속, 시간 직접 입력 |
| 컷 | 리믹스 방식 5종(잘라내기 · 사운드 사용 · 그린 스크린 · 콜라보 · 내 촬영·해설), 순서 이동, 컷별 자막·메모, 그 장면으로 되돌아가기 |
| 검사 | 목표 길이(15·30·60초·3분) 게이지, 소재별 비중, 잘라내기 5초 초과 경고, 한 영상 비중 50% 초과 경고, 내 촬영 0% 경고 |
| 내보내기 | 컷 시트 복사 · `.txt` · `.csv`(엑셀용 BOM), 설명란 출처 표기 블록, 유튜브 앱 실행 순서 |
| 보관 | `localStorage`. 서버로 가는 것은 없다 |

## 구조

상태는 `S`(소재 · 컷 · 대본)와 `MARK`(지금 찍어둔 시작·끝) 둘뿐이고, 화면은
`renderSrcs` / `renderCuts` / `renderOutputs` 세 갈래로 다시 그린다.

- 컷은 `{vid, way, in, out, cap}`. `way` 가 `mine`(내 촬영)이면 원본이 없으므로 길이만 쓴다.
- 컷 시트·CSV·실행 순서는 저장해 두지 않고 매번 같은 상태에서 만들어 낸다. 어긋날 일이 없다.
- 플레이어 시계는 90ms 폴링으로 갱신하지만, **구간을 찍는 순간에는** `getCurrentTime()` 을
  직접 불러 쓴다(`nowT()`). 폴링 값만 믿으면 최대 0.09초 어긋난다.
- 소재마다 색을 배정해 게이지·비중표·컷 카드 왼쪽 선에 같은 색을 쓴다.

## 만들면서 걸린 것

| 증상 | 원인 | 대응 |
| --- | --- | --- |
| I·O 로 찍은 시각이 조금씩 어긋남 | 90ms 폴링으로 받아둔 값을 그대로 썼다 | 찍는 순간 `player.getCurrentTime()` 을 다시 읽는 `nowT()` |
| 오른쪽 패널 카드가 눌려 내용이 잘림 | `.rail` 이 세로 플렉스라 기본값 `flex-shrink:1` 이 카드를 줄였고 `.card{overflow:hidden}` 이 잘라냈다 | `.rail>*{flex:none}` 으로 스크롤에 맡김 |
| 모바일에서 시작·끝·길이가 따로 흩어짐 | 라벨과 값이 각각 줄바꿈 대상 | 세 쌍을 `.grp`(`white-space:nowrap`)로 묶어 통째로 줄바꿈 |
| 플레이어 위에서는 단축키가 안 먹음 | 포커스가 유튜브 iframe 으로 넘어간다 | 같은 동작의 버튼을 전부 제공. 플레이어 밖을 한 번 누르면 키가 돌아온다 |
| 스크립트가 막힌 환경에서 빈 화면 | 사내망 등에서 `iframe_api` 차단 | `onerror` 에서 "시간 직접 입력" 안내로 내려가고, 컷 시트 기능은 그대로 쓸 수 있다 |

## 검증

헤드리스 크로미움(Playwright)에서 가짜 `YT.Player` 를 심어 재생 시간을 통제하며 34가지를 확인했다.

- 링크 파싱과 `t=` 시작점, 제목·채널 자동 기입
- I·O 찍기와 길이 계산, 담은 뒤 초기화, 시간 직접 입력
- 잘라내기 5초 초과 경고, 한 영상 비중 경고, 내 촬영 없음 경고가 붙고 사라지는 것
- 컷 순서 이동, 자막 저장, 목표 길이 변경
- 컷 시트·CSV 생성(행 수와 출처 표기, 실행 순서 문구)
- 새로고침 후 소재·컷·대본·플레이어 복원
- 데스크톱·모바일에서 카드 잘림 없음, 가로 넘침 없음
- 플레이어 API 실패 시 대체 안내, 콘솔 오류 0건

## 한계

- 영상을 내려받거나 화면을 캡처하지 않는다. 실제 편집은 유튜브 앱의 리믹스나 편집기에서 한다.
- 원작자가 리믹스를 꺼둔 영상, 음원 라이선스로 막힌 영상은 소재로 쓸 수 없다.
- 리믹스 메뉴 이름과 잘라내기 5초 제한은 유튜브 앱 업데이트에 따라 달라질 수 있다.
- 저장은 그 브라우저 한 곳에만 남는다. 기기끼리 동기화되지 않는다.
