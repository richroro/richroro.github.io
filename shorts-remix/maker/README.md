# 쇼츠 렌더러 — 대본을 세로 영상으로

컷 시트의 "내 촬영·해설" 자리에 넣을 화면을 만드는 도구.
`render.html` 의 대본만 고치면 1080×1920 영상이 나온다. 촬영도 편집기도 없이,
화면을 전부 코드로 그린다.

- 미리보기: `shorts-remix/maker/render.html` 을 브라우저로 열면 재생·구간 이동이 된다
- 렌더링: `node render.cjs` → `out/short.mp4`

## 왜 필요한가

리믹스로 가져온 컷만 이어 붙인 쇼츠는 재사용·비진정 콘텐츠로 분류돼 수익 창출에서 빠진다.
내 해설·자막이 들어간 오리지널 구간이 있어야 하는데, 매번 얼굴을 찍기는 번거롭다.
이 렌더러가 그 구간을 만들어 준다. 결과물에는 남의 저작물이 한 조각도 들어가지 않는다.

## 쓰는 법

```bash
cd shorts-remix/maker

node render.cjs                    # out/short.mp4 한 편
node render.cjs --clips            # 장면별로 잘라 out/clips/ 에도 저장
node render.cjs --fps 24 --crf 22  # 프레임·화질 조정
FFMPEG=/usr/bin/ffmpeg node render.cjs
```

`--clips` 로 나온 장면별 파일이 실제로는 더 쓸모 있다. 폰 갤러리에 넣어두고 유튜브 앱에서
리믹스 컷을 딴 다음 그 사이사이에 끼우면 된다. 통짜 파일은 폰에서 자르기가 번거롭다.

필요한 것: Node 18+, `playwright`(전역 설치도 인식), `ffmpeg`.
ffmpeg 은 `FFMPEG` 환경변수 → `PATH` → `imageio-ffmpeg` 순으로 찾는다.
`libx264` 가 없는 ffmpeg 이면 자동으로 VP8/WebM 으로 떨어진다(경고를 찍는다).

## 대본 고치기

`render.html` 위쪽 `SCRIPT` 만 보면 된다. 장면 길이(`dur`)를 바꾸면 뒤 장면 시작 시각이
알아서 밀리고, 진행 막대와 장면별 클립 경계도 따라온다.

| type | 쓰는 칸 | 생김새 |
| --- | --- | --- |
| `hook` | `lines[]`, `sub` | 큰 글씨 여러 줄, 마지막 줄만 보라색 + 작은 한 줄 |
| `mark` | `mark`(`x`\|`check`), `title[]`, `items[]` | 동그라미 표시 + 제목 + 카드 안 항목들 |
| `list` | `title`, `items[[제목, 설명]]` | 번호 붙은 카드 목록 |
| `verdict` | `top`, `verdict`, `note`, `items[]` | 윗줄 + X + 결론 + 카드 |
| `two` | `title[]`, `bad[]`, `good[]` | 빨간 카드와 민트 카드를 위아래로 |
| `wrap` | `title`, `items[]`, `cta` | 정리 목록 + 마지막 안내 카드 |

카드 높이는 항목 수에 맞춰 계산한다. 항목을 늘리거나 줄여도 겹치지 않는다.
새 장면 종류가 필요하면 `SCENE` 객체에 함수를 하나 더하면 된다 — `(scene, local, fo)` 를 받아
캔버스에 그리기만 하면 나머지(페이드·타임라인·클립 분할)는 공통 코드가 처리한다.

## 소리는 넣지 않는다

영상은 무음으로 나온다(MP4 안에 빈 오디오 트랙만 넣어 둔다. 없으면 일부 폰 편집기가 싫어한다).

- 나레이션은 쇼츠 편집기의 음성 녹음으로 얹는 편이 낫다. 목소리가 들어가야 오리지널 요소로 쳐준다.
- 음악은 유튜브 오디오 보관함이나 쇼츠 내 음원만 쓴다. 외부 음원을 넣으면 클레임 대상이 된다.

## 왜 이렇게 만들었나

| 선택 | 이유 |
| --- | --- |
| 실시간 녹화(`MediaRecorder`) 대신 프레임 단위 렌더링 | 실시간 녹화는 탭이 밀리면 프레임을 흘린다. `__draw(t)` 를 한 칸씩 호출해 찍으면 몇 초가 걸리든 결과가 같다 |
| 프레임을 파일로 쌓지 않고 ffmpeg 표준입력으로 직접 보냄 | 1050장이면 150MB가 넘는다. 디스크를 거치지 않으면 그만큼을 안 쓴다 |
| 본편과 장면별 클립을 한 번에 인코딩 | 같은 프레임을 여러 인코더에 나눠 보내면 두 번 그릴 일이 없다 |
| 폰트를 파일로 두지 않고 구글 폰트 링크 | 저장소에 폰트 바이너리를 넣지 않으려고. 폰트가 안 잡히면 시스템 고딕으로 떨어진다 |

## 만들면서 걸린 것

| 증상 | 원인 | 대응 |
| --- | --- | --- |
| MP4로 안 묶이고 WebM만 나옴 | 플레이라이트가 들고 다니는 ffmpeg 은 VP8·WebM 전용 빌드다 | `libx264` 유무를 먼저 확인하고, 없으면 WebM으로 떨어지되 그렇다고 알린다 |
| 첫 프레임에서 글꼴이 다르게 찍힘 | `document.fonts.ready` 가 끝나도 첫 그리기에는 아직 반영이 안 될 때가 있다 | 준비 후 0.7초를 더 기다리고 첫 프레임을 그린다 |
| 카드 안 글자가 카드 밖으로 넘침 | 카드 높이를 숫자로 박아 뒀더니 항목을 늘리면 터졌다 | 항목 수로 높이를 계산 |

## 한계

- 자막·도형만 그린다. 사람도 실사 화면도 없다. 그 구간은 직접 찍어야 한다.
- 35초 기준 렌더링에 1분 남짓 걸린다(1080×1920, 30fps).
- 글자가 길면 줄바꿈을 자동으로 해주지 않는다. 대본에서 줄을 나눠 적는다.
