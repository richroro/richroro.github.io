# 신고가 장부 — 아파트 실거래 정보

안양시와 서울 주요 구의 아파트 실거래 6년치를 단지·전용면적별로 묶어 **시세, 신고가, 고점 대비, 전세가율,
층을 보정한 저가 거래**까지 정리해 보여 주는 정적 사이트. 핵심은 **가성비 추천** — 같은 동네·연식·면적·단지 규모의
단지끼리 견줘서 실제로 덜 비싸게 거래되는 곳을 골라 준다. 맨 위 **물어보기** 상자에 "강남 30평대 20억 이하"처럼
한국어로 물으면 12개 지역 1만여 개 단지·면적에서 바로 찾아 문장·차트·목록으로 답하고, 옆에 **오늘의 브리핑**을
자동으로 쓴다. 그 아래 **예산으로 보는 가성비 지도**에서 예산·평형을 고르면 구마다 살 수 있는 가성비 후보 수를
한눈에 보고, 12개 지역을 차트로 비교하고, 지역을 고르면 그 지역을 자세히 본다.
자료는 전부 국토교통부 API 에서 받은 것이다.

## 자료는 어디에 저장되나

**이 저장소 안, `real-estate/data/` 폴더다.** 서버도 데이터베이스도 없다.
깃허브 액션이 매일 아침 국토교통부 API 로 자료를 받아 그 폴더에 커밋하고, GitHub Pages 가 그대로 정적 파일로
내보내고, 페이지가 열릴 때 브라우저가 읽는다. 바뀐 내용이 있을 때만 커밋하므로 빈 커밋은 생기지 않는다.

```
real-estate/data/index.json   지역 목록 (이름·건수·기간·파일명)
real-estate/data/summary.json 지역별 요약 (지수·고점·바닥·전세가율·거래량, 첫 화면 차트용 23KB)
real-estate/data/catalog.json 12개 지역 단지·면적 목록 + 층 보정 저가 거래 (가성비·물어보기·브리핑용, gzip 370KB)
real-estate/data/41171.json   경기도 안양시 만안구
real-estate/data/11680.json   서울특별시 강남구
…                             시군구마다 파일 하나
```

- 배포: https://richroro.github.io/real-estate/
- 소스: `index.html` 한 파일 (외부 스크립트 없음, 구글 폰트만 링크) · 공유 그림과 아이콘: `og.png`, `icon*.png`, `icon.svg`, `manifest.webmanifest`

## 화면에 뜨는 자료

페이지는 위 `data/` 파일만 읽는다. **파일을 직접 넣는 기능은 없다.** 첫 화면의 12개 지역 비교는 `summary.json` 하나로 그리고,
차트에서 지역을 누르거나 "지역별로 자세히" 선택에서 고르면 그 지역 파일 하나를 읽어 뿌린다. 지역을 더 보고 싶으면 `regions.json` 에 시군구 코드를 추가하면
다음 수집부터 목록에 생긴다.

국토교통부 API 를 브라우저에서 바로 부르지 않는 이유: 공공데이터포털이 CORS 를 허용하지 않아 브라우저 호출이
막히고, 정적 페이지에 인증키를 넣으면 누구나 볼 수 있다. 그래서 키는 깃허브 시크릿에 두고 액션에서만 부른다.

## 자동 수집 설정

한 번만 해 두면 된다.

1. [공공데이터포털](https://www.data.go.kr) 에서 **국토교통부_아파트 매매 실거래가 상세 자료** 활용신청 → 인증키 발급
   전세가율까지 보려면 **국토교통부_아파트 전월세 자료** 도 활용신청한다 (매매와 별개 신청이다).
2. 저장소 **Settings → Secrets and variables → Actions → New repository secret** 에
   이름 `DATA_GO_KR_KEY`, 값은 발급받은 인증키(일반 인증키, Decoding 쪽을 넣으면 된다)
3. 전월세 자료의 인증키가 매매와 **다르게 발급됐다면** 같은 자리에 `DATA_GO_KR_RENT_KEY` 로 하나 더 등록한다.
   같은 키를 쓰는 계정이면 이 시크릿은 없어도 되고, 없으면 매매 키를 그대로 쓴다.
4. **Actions → 실거래가 자동 수집 → Run workflow** 로 첫 실행. 이후 매일 06:10 KST 에 자동 실행된다.
   **기간 칸은 비워 둔다** — 숫자를 넣으면 그 개월만 받아서 `regions.json` 의 72개월이 무시된다.

키를 넣기 전까지는 예약 실행이 **아무것도 받지 않고 초록색으로 건너뛴다.** 매일 실패 알림이
오면 곧 안 보게 되기 때문이다. 대신 실행 요약에 왜 건너뛰었는지와 등록 방법이 남고,
`Run workflow` 로 직접 돌린 실행은 키가 없으면 그대로 실패한다 — 사람이 결과를 보고 있으니
빨갛게 알려 주는 게 맞다.

샘플 데이터는 없다. 키가 없어 아직 한 번도 수집하지 못했으면 페이지는 "아직 받아 둔 자료가 없다"고만 알린다.

수집 지역과 기간은 `regions.json` 에서 바꾼다. 기본값은 **안양시 만안구·동안구와 서울 10개 구(강남·서초·송파·강동·용산·성동·마포·양천·영등포·노원), 최근 72개월(6년)** 이다.
6년을 받는 이유는 2021년 고점이 자료 안에 들어와야 신고가와 고점 대비 등락이 뜻을 갖기 때문이다.
최근 1년만 받으면 그 안의 최고가가 전부 신고가로 잡혀서 쓸모가 없다.

```json
{ "months": 72, "regions": [ { "code": "41171", "name": "경기도 안양시 만안구" } ] }
```

`code` 는 법정동코드 앞 5자리(시군구)다. 구가 있는 시는 구 단위 코드를 쓴다(안양시 만안구 41171, 동안구 41173).
`regions.json` 의 `_다른지역_예시` 에 광명·군포·의왕·화성·강남 코드를 넣어 두었으니 붙여 쓰면 된다.
지역 12곳 × 72개월이면 매매 호출 864회, 전월세 144회(최근 12개월)로 하루 1,008회이고,
지역 파일은 하나에 0.3~1.1MB(gzip 65~260KB) 안팎이다. `--rent-months 0` 으로 전월세 수집을 끌 수 있다.

대상은 **아파트 매매와 아파트 전월세(최근 12개월)** 다. 오피스텔·연립다세대는 별도 API 라서 들어 있지 않다.

> 브라우저에서 이 API 를 직접 부르지 않는 이유: 공공데이터포털이 CORS 를 허용하지 않고,
> 정적 페이지에 인증키를 넣으면 그대로 공개된다. 그래서 키는 깃허브 시크릿에 두고
> 액션에서만 호출한다.

## 직접 실행

```
python fetch_molit.py --rebuild-summary data          # API 없이 summary.json·catalog.json 만 다시 만들기
python fetch_molit.py --key "$KEY" --config regions.json --split-dir data
python fetch_molit.py --key "$KEY" --lawd 11680 --months 6 -o data/latest.json
python fetch_molit.py --key "$KEY" --lawd 11680 --months 6 --format csv -o data/latest.csv
```

표준 라이브러리만 쓴다. 한 달치 호출이 실패해도 나머지는 계속 받고, **매매** 실패가 `--max-fail` 을 넘으면
종료코드 1 로 끝난다. **전월세 실패는 여기에 포함되지 않는다** — 전세가율은 덤이라, 전월세를 한 건도 못 받아도
매매 자료만으로 파일을 만들고 로그에 이유(전월세 활용신청 여부)를 남긴다.
받은 내용이 기존 파일과 같으면 파일을 다시 쓰지 않아서 빈 커밋이 생기지 않는다.

## 정리 기준

| 항목 | 정의 |
| --- | --- |
| 묶음 단위 | 시군구 + 읍면동 + 단지명 + 전용면적(㎡ 반올림) |
| 신고가 | 묶음 안에서 시간순으로 볼 때 이전 모든 거래보다 높은 가격에 체결된 거래 |
| 경신 | 최근 N개월(기본 3) 안에 신고가가 나온 묶음. 경신폭은 직전 신고가 대비 |
| 시세 | 최근 N개월(기본 3) 거래의 중위값, 없으면 마지막 거래가 |
| 고점 대비 | 시세 ÷ 신고가 − 1 |
| 해제 거래 | 해제사유발생일이 있는 거래. 기본으로 제외(토글 가능) |

## 시장 개요 (첫 화면)

"지금이 고점인가"에 바로 답하는 탭. 큰 숫자 하나가 **고점 대비 현재 시세**이고, 바닥 대비 회복폭(기간 중 가장 깊이 빠진 달 기준),
최근 3개월 방향, 완결된 12개월 거래량이 옆에 붙는다. 아래에 월별 시세 지수 선과 거래량 막대가 같은 가로축으로 놓인다.

지수는 그냥 월별 중위값이 아니다. 달마다 거래되는 단지가 달라서 중위값은 단지 구성 때문에 튄다.
그래서 **단지·면적별로 그 달 평단가가 자기 자신의 기간 중앙값 대비 몇 배인지**를 먼저 구하고,
그 배수들의 중앙값을 지수로 쓴다. 한 달에 최소 몇 개 단지가 거래된 달만 점을 찍는다.
위쪽 필터(시군구·읍면동·면적)를 바꾸면 그 범위로 다시 계산한다.

## 가성비 추천 (맨 위)

"싼 아파트"가 아니라 **비슷한 단지보다 덜 비싸게 거래되는 아파트**를 고른다. 두 단계로 계산한다.

1. **구마다 회귀 모델을 맞춘다.** 평당가(로그)를 동, 연식 구간(5년 단위), 전용면적, 단지 규모(6년 동안의 거래 수로 대신),
   브랜드(래미안·자이·힐스테이트·푸르지오 등)로 설명한다. 거래가 적은 동은 구 평균 쪽으로 당기고, 값이 동떨어진 묶음은 덜 보게
   (Tukey 가중) 했다. 설명력(R²)은 10개 구에서 0.82~0.93, 동이 넓게 잡힌 노원·안양 동안은 0.54~0.59 다.
2. **비교 사례로 값을 매긴다** (감정평가의 거래사례비교와 같은 생각). 후보와 같은 동(모자라면 같은 구)에서 연식 ±6년·면적 ±25%·
   단지 규모 1/3~3배인 다른 단지를 고르고, 그 단지들 가격을 회귀 계수로 후보 조건에 맞게 옮긴 뒤 가중 중앙값을 **비교 가격**으로 쓴다.

가격은 한 건짜리 이상 거래에 흔들리지 않게 **실거래 기준가**를 쓴다: 최근 12개월 중개거래(직거래는 가족 간 거래가 많아 뺌)를
구 지수로 지금 수준에 맞춘 중위값이다 (`catalog.json` 의 `pa`). 후보는 실거래 기준가가 3건 이상, 최근 1년 거래 3건 이상,
단지 6년 거래 40건 이상(나홀로·초소형 단지 제외), 전용 40~200㎡ 인 곳이다. 임대·토지임대부는 뺀다.

**가성비 점수(0~100)** = 비슷한 단지 대비 할인 45 + 전세가율(구 중위 대비) 20 + 거래량 15 + 최근 6개월 흐름 10 + 연식 10.
할인은 ±25% 에서 자르고 비교 사례가 적으면 덜 믿는다. 비교 가격보다 30% 넘게 싼 곳은 임대·지분·특수 거래일 수 있어 순위에서 뺀다.
카드의 "왜 이 점수인가"를 펼치면 항목별 점수와 비교한 단지들(원래 평당가·이 단지 조건으로 옮긴 평당가)이 나온다.

화면: 히어로의 **예산·평형·지역·연식** 선택(전세 끼고 사면 예산을 갭으로) → "가성비 찾기"는 그 조건을 문장으로 바꿔 물어보기에 넣는다
("서울 30평대 15억 이하 20년 이내 가성비"). 오른쪽 **오늘의 가성비**에 12개 지역 1~5위가 뜬다. 답에는 비교 가격×실거래 기준가
산점도(대각선 아래 = 덜 비쌈)와 순위 카드가 나온다. 단지 상세의 '한눈에 읽기', 단지 카드, 지역 탭의 "내게 맞는 단지"(가성비 항목)도
같은 점수를 쓴다.

**모르는 것**: 역세권·학군·향·층·수리 상태·주상복합 여부·재건축 진행 단계. 싼 데는 이유가 있을 수 있으니 후보를 좁히는 데까지만 쓰고
직접 확인해야 한다. 투자 권유가 아니다.

## 물어보기

검색창이 아니라 **질문을 알아듣는 상자**다. 문장을 조건으로 바꾸고, 그 조건으로 `catalog.json` 을 걸러,
결과를 문장·차트·목록으로 쓴다. 답 위에는 "이렇게 이해했어요" 칩이 붙고, 칩의 × 를 누르면 그 조건만 빼고 다시 묻는다.
결과가 없으면 조건을 하나씩 풀었을 때 몇 개가 나오는지, 가격을 얼마까지 올리면 잡히는지까지 알려 준다.

**외부 AI 서비스를 쓰지 않는다.** 질문 해석·답 문장·브리핑은 모두 브라우저 안에서 규칙과 통계로 만들고,
질문은 어디로도 보내지 않는다 (정적 페이지에 AI 키를 넣으면 공개되고, 서버도 없다).
그래서 처음 보는 표현은 못 알아들을 수 있는데, 그럴 땐 못 알아들은 낱말을 칩으로 보여 준다.

| 신고가 · 급매 | 신고가·최근 한 달·올해·경신폭 큰 순 / 급매·싸게 팔린·10% 이상 싸게 |
| 정렬 | 싼·비싼·거래 많은·전세가율 높은·갭 작은·많이 빠진·오르는·가성비(동네 평단가보다 싼)·top 10 |
| 가성비 | 가성비·저평가·추천·살 만한·적정가 ("마포 30평대 15억 이하 가성비", "헬리오시티 적정가") |
| 판단 · 비교 | "송파 지금 고점이야?"·"강남 vs 서초"·"마용성 비교"·"송파 30평대 vs 강동"·"은마 비슷한 단지" |

답의 종류는 조건 목록, 신고가 목록, 급매 목록, 지역 진단(지수 꺾은선·타일·거래 많은 단지), 지역 비교(겹친 꺾은선과 표),
조건을 건 지역 비교, 단지 카드, 비슷한 단지다. 목록의 단지를 누르면 그 지역 자료를 열고 상세 패널을 띄운다.
입력하는 동안 단지·동·지역 이름을 추천하고 (↑↓ 로 고르고 Enter), `/` 키로 바로 입력칸에 간다.
답은 주소(`#ask=...`)에 남아서 **링크 복사**로 그대로 공유된다.

숫자 기준은 페이지 기본 설정과 같다: 해제 거래 제외, 시세 = 최근 3개월 중위(없으면 마지막 거래가), 신고가 경신은 최근 3개월.
목록은 기본으로 **최근 1년 안에 거래된 곳만** 센다 (칩에서 풀 수 있다). 파생 지표로 줄 세울 때는 표본이 적은 묶음을 뺀다 —
6개월 흐름은 1년 거래 6건 이상, 동네 대비·고점 대비는 3건 이상, 전세가율·갭은 전세 거래 3건 이상.
직전보다 50% 넘게 뛴 신고가와 25% 넘게 싼 거래는 특수 거래·신고 오류일 수 있어 ⚠ 로 따로 표시한다.

**못 하는 것**: 앞으로의 가격 예측, 단지별 몇 년 전 값과의 비교, 세대수·학군·역세권·향·조망. "살 때야?" 같은 질문에는
예측 대신 지금 위치(고점 대비·바닥 대비·최근 흐름·거래량)를 정리하고 투자 권유가 아니라고 적는다.

`catalog.json` 은 수집 때 `fetch_molit.py` 가 페이지의 `analyze()`·`computePeers()`·`cheapDeals()` 를 그대로 옮겨 만든다.
12개 지역 전부에서 페이지가 직접 계산한 값과 모든 단지·면적(1만 1천여 개), 모든 저가 거래가 일치하는 것을 확인했다.

## 예산으로 보는 가성비 지도 (브리핑 아래, 01)

서울 10개 구와 안양 2개 구를 칸 하나씩으로 놓은 타일 지도다. 칸 자리는 실제 위치를 대강 따른다 — 한강 북쪽
(노원·마포·용산·성동), 남쪽(양천·영등포·서초·강남·송파·강동), 점선 아래 경기 안양(만안·동안).

- **예산 막대**(3억 ~ 30억, 전체)와 **평형**(20평대·30평대·40평 이상)을 고르면 칸마다 그 조건으로 고를 수 있는
  가성비 후보 수가 바뀐다. 색이 진할수록 많다(파랑 다섯 단계, 0곳은 빗금). 칸 아래 작은 글씨는 그 구 1위의 점수.
- 칸을 누르면 오른쪽(모바일은 아래)에 그 구의 후보 수 · 10% 넘게 싼 곳 · 평당 중위와 상위 4곳이 뜨고, 단지를 누르면 상세가 열린다.
- **"○○구 후보 N곳 모두 보기"는 같은 조건을 물어보기로 묻는다.** 지도 숫자와 답의 후보 수는 같은 거르기(`valFilter`)를
  쓰므로 항상 같다 (5개 조합 × 12개 구 모두 확인).
- 금액은 가성비 답과 같이 실거래 기준가(`pa`)로 보고, 비슷한 단지보다 30% 넘게 싼 곳(특수 거래 의심)은 뺀다.

## 화면 구성과 디자인

장부(원장)와 신문 지면을 본떴다. 머리에는 신문처럼 날짜줄(몇 년 몇 월 며칠 무슨 요일 · 지역 · 갱신 시각)을 두고,
장(01 가성비 지도 · 02 12개 지역 한눈에 · 03 지역별로 자세히)마다 겹줄 아래 번호와 명조 제목을 단다.
큰 숫자는 명조, 표의 숫자는 고정폭. 그림자는 여러 겹을 옅게 쌓고, 지역별 탭은 고른 탭이 아래 판과 이어지는 색인 탭이다.

- **차례 막대** — 히어로를 지나 내려가면 위에 붙는다. 지금 읽는 장을 표시하고, 누르면 그 장으로 간다
  (주소의 상태 해시는 건드리지 않는다). "물어보기"는 맨 위 입력칸으로 데려간다.
- **공유 미리보기** — `og.png`(1200×630), `icon.svg`·`icon-192/512.png`·`icon-maskable-512.png`, `manifest.webmanifest`.
  카카오톡·슬랙에 링크를 붙이면 큰 그림 카드로 뜨고, 휴대폰 홈 화면에 추가하면 앱 아이콘으로 뜬다.
- 동작 줄이기를 켜면 부드러운 스크롤·숫자 굴리기·카드 등장 효과를 모두 끈다. 다크 모드는 시스템 설정을 따르고 직접 바꿀 수도 있다.

## 싸게 나온 거래 (층 보정)

같은 단지·같은 면적이라도 1층과 20층은 값이 다르다. 그래서 "시세보다 쌌다"를 그냥 중위값과 비교해 판단하면
저층 거래만 잔뜩 걸린다. 이 탭은 두 단계로 판단한다.

1. **그때 수준** — 거래월 앞뒤 3개월 중위값으로 그 시점 시세를 잡는다.
2. **그 층의 값** — 각 거래가를 1번 값으로 나눠 시세 흐름을 걷어내고, 남은 비율의 중앙값을
   저층(1~3층) / 중층 / 고층(최고층의 75% 이상, 최소 10층)으로 나눠 구한다. 중층을 1로 놓는다.

그 층이라면 얼마였어야 하는지와 실제 거래가를 비교해 많이 싼 순으로 세운다.
거래 10건 미만이거나 한 층대에 3건이 안 되는 묶음은 층 효과를 못 재므로 목록에서 뺀다.
**직거래는 기본으로 제외한다** — 가족 간 거래가 섞여 시세보다 싼 경우가 많다.
상세 패널에는 그 단지의 층별 값 차이(예: 저층 −6.1%, 고층 +4.1%)와 거래마다 기대 대비 편차가 표시된다.

이미 체결된 거래이지 지금 살 수 있는 매물이 아니고, 향·조망·수리 상태·소음은 실거래가에 없다.

## 면적대·읍면동별로 갈라 보기

시장 개요 아래에 같은 방식의 지수를 면적대별 또는 읍면동별로 따로 내서 나란히 놓는다.
세로 눈금을 모두 같게 맞춰서 어디가 더 빠졌고 어디가 먼저 돌았는지 비교된다.
단지가 3개 미만인 구간은 표본 부족으로 표시만 하고 선을 그리지 않는다.

## 전세가율과 갭 (전월세 자료)

매매와 함께 **아파트 전월세 실거래가**도 받아서 묶음별 전세 중위 보증금을 낸다(월세·반전세는 뺀다).
여기서 전세가율(전세 ÷ 매매 시세)과 갭(매매 − 전세)이 나오고, 정리표·상세 패널·비교표·추천에 모두 붙는다.

추천 탭에는 **전세 끼고 사기** 토글이 있다. 켜면 예산을 매매가가 아니라 **갭 + 취득세·중개보수** 로 따진다.
성향에 "갭 작은 곳 · 전세 끼고"가 추가되고, 전세가율이 점수 항목으로 들어간다.
전세 자료가 없으면 이 토글과 성향은 숨고, 전세가율 가중치는 나머지 항목에 나눠 준다.

## 비슷한 단지와 비교 (상세 패널)

정리표나 추천 목록에서 한 줄을 누르면 열리는 상세 패널 맨 아래에, 견줄 만한 단지를 찾아 나란히 놓는다.

같은 면적대(60~85㎡ 같은 구간) 안에서 전용면적이 25% 이내로 가깝고, 연식이 비슷하고, 같은 읍면동에 있는 순으로
여섯 곳을 고른다. 같은 시군구에서 세 곳도 못 찾으면 범위를 전체로 넓힌다. 같은 단지의 다른 평형은 뺀다.

표에는 시세, 평단가, **이 단지 대비 평단가 차이**, 고점 대비, 최근 1년 거래 건수가 들어가고, 기준 단지는 파란 줄로 표시된다.
위쪽 한 줄이 결론이다 — "동안구 60~85㎡ 가운데 면적·연식이 가까운 6곳과 견주면, 평단가가 7곳 중 4번째로 비싼 편입니다."
비교 단지를 누르면 그 단지 상세로 넘어가므로 계속 타고 다닐 수 있다.

## 내게 맞는 단지 (추천 탭)

예산·면적·연식·성향을 넣으면 후보를 점수순으로 세워 준다. 예산은 **취득세와 중개보수를 빼고** 따진다
(1주택 기준: 6억 이하 1.1%, 6~9억 누진, 9억 초과 3.3%, 85㎡ 초과 농특세 0.2%, 중개보수는 구간별 상한요율).

점수는 아래 여섯 가지를 후보 안에서 백분위로 매긴 뒤 성향별 가중치로 합한 값이다.

| 항목 | 무엇을 보는가 |
| --- | --- |
| 거래 활발 | 최근 12개월 거래 건수. 팔고 사기 쉬운지 |
| 고점 낙폭 | 시세가 신고가에서 얼마나 내려왔는지 |
| 6개월 흐름 | 최근 6개월 중위값 ÷ 그 이전 6개월 중위값 |
| 가격 안정 | 최근 12개월 거래가의 변동계수. 낮을수록 시세가 또렷하다 |
| 동네 대비 | 같은 읍면동·같은 면적대의 평단가 중위값보다 싼지 |
| 전세가율 | 전세 중위 보증금 ÷ 매매 시세. 높을수록 갭이 작고 실수요 지지가 두껍다 |
| 연식 | 준공연도 |

보유 현금과 대출 금리·기간을 넣으면 카드마다 대출액과 **원리금균등 월 상환액**이 함께 나온다.
금리를 0으로 두면 꺼진다. 총부채원리금상환비율(DSR)이나 주택담보대출비율(LTV) 한도는 보지 않으므로,
실제로 그만큼 빌릴 수 있는지는 따로 확인해야 한다.

성향은 여섯 가지 가중치 묶음이다 — 균형 있게 / 실거주·안정 우선 / 저평가·낙폭 큰 곳 / 반등·상승 흐름 /
환금성 우선 / 갭 작은 곳·전세 끼고.

전세가율, 재건축·리모델링, 향·조망·층·수리 상태, 지금 매물이 있는지. 집값을 좌우하는 것들이 여기 다 빠져 있으므로
후보를 좁히는 용도로만 쓸 것. 투자 권유가 아니다.
